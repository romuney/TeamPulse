# 12. Тур «Как работать» (TR)

**Зачем глава.** Файлы в чарт не положить: ни видео, ни GIF, ни внешней справки. Proteus не помнит, заходил ли
пользователь раньше. Поэтому объяснение отчёта — живой тур по самому отчёту: экран затемнён, подсвечена одна цель,
карточка со стрелкой говорит «это — вот что, нажми — будет вот что». Эталон — тур Proteus Adoption через три чарта
единого листа: он идёт в бою с 07.10, и владелец считает его лучшим. Движок HRBP HUB (один чарт, вкладки, окно
фильтров, «нажми — будет») и detail_list (два чарта, шаги панели через сообщения; с 30-й поставки — тур на весь экран
CSS-ом борда, по просьбе владельца «как в Proteus Adoption») — совместимые варианты того же устройства. Обмен сообщениями между iframe в целом — MC-12 (09-multi-chart.md); слои в `body` и видимая часть — SB-09 и SB-05
(08-sandbox.md).

**Главное в 5 пунктах.**
1. **TR-01.** Тур запускается только кнопкой «Как работать». Показа «при первом входе» и памяти в браузере нет.
2. **TR-02 / TR-20.** Шаги описаны декларативно в `tourSteps()`. Цели нет — шаг пропускается. Новый элемент интерфейса или вкладка — новый шаг.
3. **TR-11 / TR-12.** Через несколько чартов тур ведёт один ведущий, соседи подсвечивают свои цели по сообщениям. Состав шагов соседа решается один раз, на вступлении.
4. **TR-13 / TR-14 / TR-16 / TR-22.** Плавность и бесшовность: карточка ждёт ответа соседа (≤ 400 мс) и переезжает за 0,2 с; «дырка» без цели схлопывается в точку; первый кадр — без анимации; страницу вокруг чартов затемняет CSS борда по маркеру тура, углы карточек под шторкой — прямые.
5. **TR-21.** Тур прогоняется скриптом на стенде целиком: все шаги, клавиши в каждом чарте, 0 ошибок.

**Метки уверенности.** [бой] — видно в бою (скриншот, видео, жалоба владельца); [владелец дд.мм] — решение
владельца; [вывод] — следует из фактов, напрямую не проверено; [не проверено в бою] — добавка к любой метке. Прогон
в браузере на стенде проекта (HRBP `tour.cjs`, DL `click.cjs`, Chromium 141) своей метки не имеет: он пишется словом
«стенд» рядом с меткой источника, а без неё — «[вывод] — стенд».

### Протокол сообщений

Рассылка — `postMessage` всем фреймам борда (обход от `window.top.frames`, MC-12 в 09-multi-chart.md). Ключ цели — строка
`'<чарт>:<цель>'`.

| Сообщение | Кто → кому | Поля | Что делает получатель |
|---|---|---|---|
| `PA_TOUR_GO` | шапка → все | — | ведущий запускает тур (`tourStart`) |
| `PA_TOUR {op:'dim', ask:true}` | ведущий → соседи | на вступлении `ask` | сосед затемняется целиком и отвечает списком своих целей |
| `PA_TOUR {op:'dim'}` | ведущий → соседи | — | шаг ведущего: сосед затемнён целиком |
| `PA_TOUR {op:'show', key:'head:period', pad}` | ведущий → соседи | `key`, поле рамки `pad` | сосед с этим `from` затемняется вокруг своей цели, закрывает её крышкой и отвечает, где она |
| `PA_TOUR {op:'off'}` | ведущий → соседи | — | снять слой, остановить повтор маркера, отправить чистый PNG |
| `PA_TOUR_AT {from, key:'', keys:[…]}` | сосед → ведущий | цели, которые у соседа есть сейчас | ведущий включает только шаги с этими целями (TR-12) |
| `PA_TOUR_AT {from, key, ok, l, t, r, b}` | сосед → ведущий | прямоугольник цели в координатах соседа | ведущий показывает карточку и ставит стрелку (TR-13, TR-17) |
| `PA_TOUR_KEY {k:'next'\|'back'\|'close'}` | сосед → ведущий | — | клавиша, нажатая, пока фокус в соседе (TR-10) |

### Шаги эталона

Вступление «Proteus Adoption за минуту» → период (шапка) → «Что считать» (шапка) → «Целевая аудитория» (шапка) →
разрезы каталога → «Мои отчёты» (`need`: есть пользователь) → поиск → выбор строки → колонки → выбранные фильтры →
показатели (панель) → «Что видно в данных» (панель) → вкладки панели → «Тур всегда под рукой» (кнопка в шапке).
Цели нет — шаг пропускается.

### Ход одного шага у ведущего

```js
function tourShow() {
  var t = state.tour, list = tourSteps(), step = list[t.i];
  if (!step) { tourEnd(); return; }
  var els = tourEls(step);
  if (step.sel && !els.length) { tourGo(t.i + (t.dir || 1), t.dir || 1); return; }   // цели нет — пропуск в ту же сторону
  t.shown = t.i; t.at = null;
  paBcast({ type: 'PA_TOUR', op: step.remote ? 'show' : 'dim', key: step.remote || '', pad: step.pad, ask: !!step.intro });
  var L = tourLayer(), fresh = L.style.display !== 'block', card = tourQ('tcard');
  if (fresh) L.classList.add(CFG.ns + '-tnoa');                       // первый кадр — без transition
  L.style.display = 'block';
  tourScroll(els);
  card.innerHTML = tourCardHTML(list, t.i, step);
  clearTimeout(t.wait);
  card.style.opacity = step.remote ? '0' : '1';                        // шаг соседа: ждём его ответа
  if (step.remote) t.wait = setTimeout(function () { if (state.tour === t) card.style.opacity = '1'; }, 400);
  tourPos();
  if (fresh) { void L.offsetWidth; L.classList.remove(CFG.ns + '-tnoa'); }
}
```

## Совместимый движок: HRBP HUB и detail_list

Тур Adoption вырос из движка detail_list, а тот — из HRBP HUB. Поля шага у всех одинаковые, поэтому шаг из одного
отчёта переносится в другой без переделки.

| Поле шага | Что значит | Где есть |
|---|---|---|
| `title`, `html` | заголовок и текст карточки | все |
| `intro: true` | вводная карточка, вся страница затемнена (TR-03) | все |
| `sel` | селектор внутри overlay или функция `(overlay) → элемент \| список` | все |
| `all` | подсветить все совпадения одной рамкой | все |
| `rings` | рамка у каждого совпадения отдельно | HRBP |
| `pad` | поле рамки вокруг цели (может быть отрицательным) | все |
| `lock` | только смотреть: пятая шторка ложится на цель, клик не проходит (там запрос или переход) | все |
| `demo` + `done(key)` + `hint` | «нажми — будет»: кнопка «Показать» кликает цель сама (TR-07) | HRBP, DL |
| `at: 'left'` | точка «нажатия» — у левого края цели (строка таблицы) | HRBP |
| `drawer: true` | шаг внутри окна «Фильтры и настройки»: тур сам открывает и закрывает окно (TR-09) | HRBP |
| `need` | показывать ли шаг (TR-08) | все |
| `remote` | цель у соседнего чарта: `'panel'` у DL, `'head:period'` у Adoption (TR-11) | DL, Adoption |
| `last` | последний шаг — «Готово» или «Дальше — тур по вкладке …» | все |

| Приём | HRBP_HUB | detail_list | adoption |
|---|---|---|---|

## Правила

### TR-01. Запускай тур только кнопкой «Как работать»
- **Почему:** Владелец 29.09 (HRBP): «Proteus не запоминает, первый раз зашёл или не первый». Приглашение «Впервые в
  HRBP HUB?» висело бы при каждом входе — его добавили и в тот же день убрали. Хранилища у песочницы нет: без
  `allow-same-origin` `localStorage` бросает исключение (SB-02, 08-sandbox.md).
- **Как:**
  - Кнопка «Как работать» — в шапке, справа, на виду. На листе из нескольких чартов — в шапке листа. Если шапка — не
    ведущий чарт, кнопка шлёт `*_TOUR_GO`, а тур стартует у ведущего.
  - Никакого показа при первом входе, никаких флагов в `localStorage`, cookies и параметрах адреса.
  - Последний шаг показывает, где кнопка: «Тур всегда под рукой».
- **Проверка:** На стенде после загрузки слоя тура нет и приглашения нет (`tour.cjs`: `INVITE false`); тур появляется
  только после клика по кнопке.
- **Уверенность:** [владелец 29.09].
- **Образец:** adoption:Виджеты/pa-head.chart.js (кнопка `data-tourstart` → `PA_TOUR_GO`); HRBP_HUB:proteus/hrbp-hub.chart.js
  (кнопка `data-tact="tour"`). TeamPulse в пробнике держит онбординг на `localStorage` (в Proteus выключен) — не
  переносить.

### TR-02. Описывай шаги декларативно в `tourSteps()` и пропускай шаг без цели в ту же сторону
- **Почему:** Тур — по живому отчёту: цели (строки, кнопки, вкладки) есть не всегда — нет строк, одна страница, узкая
  ячейка, нет пользователя. Владелец 29.09: «затемняется экран, стрелочками: нажми сюда — будет то-то».
- **Как:**
  - Шаги — функция `tourSteps(view)` в БЛОКЕ 5 шаблона скилла: массив объектов с полями из таблицы выше. Логики показа в
    шагах нет.
  - Цель ищется при показе шага: видимый элемент с ненулевым прямоугольником. Не нашлась — шаг пропускается в ту же
    сторону (`t.dir`): «Назад» тоже не застревает.
  - Текст шага: заголовок в 1–3 слова и 1–3 фразы — что это и что будет при клике. Названия кнопок — как на экране,
    жирным.
  - Объём: HRBP «Сводка» 16–17 шагов, «Команды» 10–11, «Трансформеры» 5–6, «Цели» 4, «Каталог» 2; DL — 16; Adoption — 14.
  ```js
  function tourSteps(view) {
    var P = '.' + CFG.ns, out = [];
    function add(o) { if (o.need === undefined || o.need) out.push(o); }
    add({ intro: true, title: 'Отчёт за минуту', html: tourIntroHTML() });
    add({ sel: P + '-tabbar', lock: true, title: 'Вкладки', html: '…' });
    add({ sel: '[data-action="drawer"]', demo: true, done: function () { return !!state.drawer; },
      title: 'Фильтры и настройки', html: '…', hint: 'Нажмите на подсвеченную кнопку или «Показать».' });
    add({ sel: '[data-tour="help"]', pad: 4, last: true, title: 'Тур всегда под рукой', html: '…' });
    return out;
  }
  ```
- **Проверка:** На стенде — прогон всех шагов (TR-21) на нескольких логинах и ширинах: шаги без цели пропущены, номер «N
  из M» не врёт.
- **Уверенность:** [владелец 29.09] + стенд HRBP и DL.
- **Образец:** HRBP_HUB:proteus/hrbp-hub.chart.js (`tourSteps(view)`, `tourShow`, `tourGo`).

### TR-03. Открывай тур вводной карточкой «<Отчёт> за минуту», закрывай шагом «Тур всегда под рукой»
- **Почему:** Решение владельца 29.09 (HRBP): сначала — как читать отчёт, потом — где что. Повторено в DL и Adoption.
- **Как:**
  - Первый шаг — `intro: true`: вся страница затемнена, в карточке 4–5 правил чтения отчёта с живыми числами из ответа
    (месяц данных, сколько строк загружено), а не общими словами.
  - Последний шаг — кнопка «Как работать»: где запустить тур снова.
  - В отчёте с вкладками тур идёт по текущей вкладке. Последний шаг вкладки предлагает «Дальше — тур по вкладке
    „…“» (`TOUR_NEXT`), последний шаг всей цепочки — «Готово».
  ```js
  var TOUR_NEXT = { onepager: 'teams', teams: 'transform', transform: 'goals', goals: 'catalog' };
  ```
- **Проверка:** На стенде первый шаг — вводная с числами из ответа стенда, последний — кнопка тура; переход «Дальше» ведёт
  в тур следующей вкладки.
- **Уверенность:** [владелец 29.09].
- **Образец:** HRBP_HUB:proteus/hrbp-hub.chart.js (`tourIntroHTML`, `TOUR_NEXT`, действие `nexttab`);
  detail_list:proteus/detail-list.chart.js (`tourIntroHTML` с живым лимитом загрузки).

### TR-04. Держи слой тура в `body` iframe: четыре шторки, крышка, рамки и карточка
- **Почему:** Скрипт чарта перезапускается на каждый ответ датасета, overlay пересобирается. Слой внутри overlay
  исчезал бы при каждой перерисовке, а копии слоя в `body` при перезапуске копились бы.
- **Как:**
  - Слой создавай один раз в `body`, вне overlay. При монтаже удаляй прежний `body > .<ns>-tour` (SB-09).
  - Состав:
    - четыре шторки `position:fixed` вокруг цели, `rgba(17,24,39,.55)`, без скругления (TR-22): клики мимо цели не
      проходят;
    - пятая — крышка на цель при `lock`;
    - рамка `box-shadow: 0 0 0 2px <акцент>, 0 0 0 6px <акцент, .22>`, радиус 10, из пула — столько рамок, сколько целей
      (`rings`);
    - карточка `role="dialog"`, `aria-modal`, 340 px, радиус 12, стрелка — квадрат 10 px под 45°; фокус — на главной
      кнопке;
    - нарисованный курсор и круг «нажатия» для «нажми — будет».
  - z-index 99990–99993 — выше выпадашек чарта. Тултип на время тура спрятан (`hideTip()` в `tourShow`): у HRBP и DL
    его z-index 99999, выше слоя тура.
  - Ореол рамки — тем же акцентом, что рамка (UI-05, 11-ui.md).
  - Шрифт и цвета задавай явно: слой вне корня с переменными (UI-04, UI-05 в 11-ui.md).
  ```css
  .xx-tb    { position:fixed; z-index:99990; background:rgba(17,24,39,.55); transition:left .2s,top .2s,width .2s,height .2s; }
  .xx-tring { position:fixed; z-index:99991; border-radius:10px; pointer-events:none;
              box-shadow:0 0 0 2px #245FD4, 0 0 0 6px rgba(36,95,212,.22); transition:left .2s,top .2s,width .2s,height .2s,opacity .2s; }
  .xx-tcard { position:fixed; z-index:99992; width:340px; max-width:calc(100vw - 24px); border-radius:12px; background:#fff; }
  ```
- **Проверка:** На стенде — тур, затем 3 перерисовки (смена фильтра, ресайз): в `body` ровно один слой, подсветка на
  месте.
- **Уверенность:** [бой] — слой работает в туре Adoption (жалобы 07.10 были на движение, не на слой), владелец считает
  этот тур лучшим; [вывод] — стенд HRBP и DL.
- **Образец:** HRBP_HUB:proteus/hrbp-hub.chart.js (`tourLayer`, CSS `-tb`, `-tring`, `-tcard`, `-tcur`);
  adoption:Виджеты/pa-reports-body.chart.js (`tourLayer`).

### TR-05. Синхронизируй тур после каждой перерисовки
- **Почему:** Перерисовка двигает цели: пришёл ответ, раскрылась строка, сменилась ширина. Шаг «нажми — будет» может
  сделать сам пользователь — тур должен это заметить.
- **Как:** В конце `render()` вызывай `tourSync()`:
  - тура нет — спрятать слой (или удалить остаток прежнего);
  - сменилась вкладка или пропал доступ к данным — конец тура;
  - слой пропал или шаг ещё не показан — показать шаг заново;

### TR-10. Лови Esc и стрелки на `document` в фазе перехвата, а в соседе — пересылай ведущему
- **Почему:** Фокус клавиатуры остаётся в том iframe, где кликнули, а у каждой песочницы свой `document`. Без пересылки
  Esc, нажатый после клика по шапке, до ведущего (каталога) не дойдёт, и тур не закроется.
- **Как:**
  - Слушатель `keydown` на `document` с `capture = true`, снимается при перезапуске скрипта (ссылка в `state`, CJ-06).
  - Esc закрывает тур всегда. Стрелки ← → листают шаги, кроме случая, когда фокус в поле ввода (`INPUT`, `SELECT`,
    `TEXTAREA`).
  - В мультичартовом туре такой слушатель стоит в каждом чарте. Сосед делает `preventDefault` и шлёт ведущему
    `*_TOUR_KEY {k:'close'|'next'|'back'}`.
  ```js
  state.onTourKey = function (ev) {
    if (!state.tour) return;
    var k = ev.keyCode || ev.which, tag = ev.target && ev.target.tagName;
    if (k === 27) { ev.preventDefault(); ev.stopPropagation(); tourEnd(); return; }
    if (tag === 'INPUT' || tag === 'SELECT' || tag === 'TEXTAREA') return;
    if (k === 39) { ev.preventDefault(); tourAct('next'); } else if (k === 37) { ev.preventDefault(); tourAct('back'); }
  };
  document.addEventListener('keydown', state.onTourKey, true);
  ```
- **Проверка:** На стенде DL `click.cjs`: клик в панель (под затемнением), → листает шаг списка, Esc закрывает тур в обоих
  чартах.
- **Уверенность:** [вывод] — по устройству песочниц; стенд DL (`click.cjs`: стрелки и Esc из панели).
- **Образец:** HRBP_HUB:proteus/hrbp-hub.chart.js (`state.onTourKey` с исключением полей ввода);
  adoption:Виджеты/pa-head.chart.js (пересылка `PA_TOUR_KEY`).

### TR-17. Считай стрелку на цель соседа по общей сетке борда и записывай раскладку
- **Почему:** iframe не знает своего положения на странице. Координаты из `*_TOUR_AT` — в системе соседа. Сопоставимы
  они только по общей оси: общая колонка даёт x, общий ряд — y.
- **Как:**
  - Шапка во всю ширину над ведущим (одна левая граница, одна ширина) — карточка у верхнего края ведущего, стрелка вверх
    на x цели.
  - Сосед в одном ряду справа (Adoption) или слева (DL) — карточка у бокового края ведущего, стрелка на y цели.
  - Другая раскладка — другая привязка. Раскладку, под которую посчитана стрелка, записывай в комментарии
    `tourPlace` и в инструкции поставки.
  ```js
  if (rem && rem.from === 'head') { side = 'bottom'; cx = at ? (at.l + at.r) / 2 : W / 2; top = m; left = cx - cw / 2; }
  else if (rem && rem.from === 'one') { side = 'left'; cy = at ? (at.t + at.b) / 2 : H / 3; left = W - cw - m; top = cy - ch / 2; }
  ```
- **Проверка:** На стенде с раскладкой борда — стрелка указывает на цель соседа (скриншот шага, DL `click.cjs`: карточка
  `left ≤ 20`, стрелка `-ta-right`).
- **Уверенность:** [вывод] — по коду; стенд DL.
- **Образец:** adoption:Виджеты/pa-reports-body.chart.js (`tourPlace` с ветками `head` и `one`);
  detail_list:proteus/detail-list.chart.js (`tourPlace` с `rem`).

### TR-18. Отсекай сообщения тура чужой вкладки и чужого отчёта
- **Почему:** Сообщения рассылаются всем фреймам борда, их видят iframe всех вкладок (MC-12, 09-multi-chart.md). На борде DL
  две вкладки с одинаковыми парами чартов: без ключа вкладки панель КП затемнялась бы по туру списка УС.
- **Как:** В каждом сообщении тура — ключ вкладки или листа (`cf` у DL) и префикс отчёта в `type` (`DL_TOUR`, `PA_TOUR`).
  Получатель отбрасывает чужой ключ первой строкой обработчика. У Adoption лист один и ключа нет — на борде с двумя
  листами Adoption его надо добавить ([вывод]).
  ```js
  if (d.type !== 'DL_TOUR' || d.cf !== MODEL.cf || !overlay.parentNode) return;
  ```
- **Проверка:** На стенде с двумя вкладками на одной странице — тур на вкладке УС не затемняет панель КП. Стенд DL
  гоняет вкладки по одной (`?mode=us|kp`), такого прогона пока нет.
- **Уверенность:** [вывод] — по коду DL и устройству рассылки; [не проверено в бою].

### TR-22. Делай углы карточки под шторкой тура прямыми, а шторки — без скругления
- **Почему:** DL, 30-я поставка (стенд, 08.10): когда страница вокруг затемнена (TR-16), скруглённый угол карточки под
  шторкой даёт на углу чарта светлую дугу. Документ iframe прозрачный (BC-11, 10-board-css.md), и за углом карточки —
  белая подложка ячейки радиуса 12 (BC-06). Первая попытка — резать шторки по скруглению карточки рамкой (`-tclip`): на
  углу легли друг на друга сглаженный край шторки, сглаженный край белой карточки и подложки — 160–166 по каналу вместо
  124. Шторки, скруглённые по карточке (так DL делал до 30-й поставки), дают то же самое.
- **Как:**
  - Шторки — без `border-radius`: четыре прямоугольника вокруг цели (TR-04).
  - Карточке на время тура — прямые углы там, где угол окна под шторкой: overlay получает `data-tsq` со списком углов
    окна вне выреза цели (`tl tr bl br`), CSS чарта по нему снимает скругление у корня карточки. Угол внутри выреза
    (цель — вся карточка) остаётся скруглённым, как без тура.
  - Конец тура — атрибут снят, углы снова 12.
  - Белая карточка во всё окно iframe (UI-08) под шторкой — ровный прямоугольник `#7c8088`, того же цвета, что страница
    вокруг: шва между чартами не видно.
  ```js
  // r — вырез цели в координатах окна или null (вступление: затемнено всё окно)
  function tourCorners(r) {
    var W = window.innerWidth, H = window.innerHeight, sq = [], cs = [['tl', 0, 0], ['tr', W, 0], ['bl', 0, H], ['br', W, H]];
    for (var i = 0; i < cs.length; i++) {
      var c = cs[i];
      if (!r || c[1] < r.l || c[1] > r.r || c[2] < r.t || c[2] > r.b) sq.push(c[0]);
    }
    overlay.setAttribute('data-tsq', sq.join(' '));
  }
  // в buildCSS(): P + '-overlay[data-tsq~="tl"] ' + P + '-root{border-top-left-radius:0;}' — и так же для tr, bl, br
  ```
- **Проверка:** На стенде — пиксели углов обоих чартов (квадраты 12 × 12 px у каждого угла; только точки, светлые до тура,
  — фон страницы и белая карточка, без содержимого чарта): во время тура — `#7c8088` ± 3, после — как до тура ± 2 (DL
  `click.cjs DL_ONLY=board`, «углы обоих чартов без шва», больше 300 точек).
- **Уверенность:** [вывод] — стенд (Chromium 141) [не проверено в бою]; [владелец 08.10] — «бесшовно».
- **Образец:** detail_list:proteus/detail-list.chart.js и detail_list:proteus/detail-list-filters.chart.js (`tourCorners`,
  `data-tsq` в `tourPos`, снятие в `tourEnd`).
