# Proteus Playbook — гайд по бордам Proteus

**Что это.** Единая база практик для тех, кто делает борды (дашборды) в Proteus — корпоративном BI на форке
Apache Superset 2.1.0 (владелец зовёт его «2.0»). В Proteus чарты — кастомный JS (`react_sanbbox`) в iframe-песочнице, данные — ClickHouse 24.8,
витрины считаются в Greenplum ноутом Helicopter. Читатели гайда:
- **агенты** — сессии Claude Code, которые пишут датасеты, чарты, CSS и поставки;
- **владелец бордов** — он вставляет файлы в боевой Proteus руками и присылает ответы SQL Lab и DevTools.

В гайде 364 правила с кодами и метками уверенности, 83 антипаттерна с датами инцидентов, 43 открытых вопроса с проверками
для боя и kit — инструменты стенда.

**Состояние.** Факты — на 08.10.2026, инструменты kit проверены на всех четырёх проектах 09.10.2026.

Как собирали гайд:
1. Читатели разобрали каждый проект: практики, факты, инциденты, открытые вопросы.
2. Сводки по темам свели правила и решили противоречия между проектами.
3. Скептик проверил каждое правило по первоисточникам (исходник Superset 2.0.1, sqlparse, ClickHouse 24.8) и опытами на
   стенде (chdb 2.1.1, Chromium 141). Где правило поправили, в гайде — поправленная версия.
4. Инструменты kit прогнали на SQL и JS всех четырёх проектов. Находки — в kit/RESULTS.md и kit/RESULTS.js.md.

## Как подключить агенту

**Как скилл Claude Code** — локально, где есть `~/.claude/skills`. Гайд лежит в ветке `claude/proteus-playbook`, пока
она не влита в `main`. Папку скилла назови так же, как `name` в SKILL.md:

```bash
git clone --branch claude/proteus-playbook https://github.com/romuney/TeamPulse.git ~/src/TeamPulse
mkdir -p ~/.claude/skills
cp -r ~/src/TeamPulse/proteus-playbook ~/.claude/skills/proteus-board-playbook
```

Агент подхватит скилл по описанию, когда работа касается борда Proteus. Обновление — `git pull` и копирование заново.

**Ссылкой в CLAUDE.md проекта** — так удобнее в облачных сессиях. Агенту нужен доступ к репозиторию `romuney/TeamPulse`
в сессии. Строка для CLAUDE.md:

```markdown
## Гайд по Proteus
Перед любой работой с бордом, датасетом, чартом, CSS борда или поставкой читай romuney/TeamPulse:proteus-playbook/SKILL.md
(ветка claude/proteus-playbook), дальше — главы по таблице «Задача → главы». Инструменты стенда — proteus-playbook/kit/.
```

**Инструменты kit:**

```bash
bash proteus-playbook/kit/setup.sh            # два venv на Python 3.12 (sqlparse 0.4.3 — бой, 0.4.4 — запас), chdb 2.1.1, node-пакеты
BROWSER=1 bash proteus-playbook/kit/setup.sh  # ещё и Chromium для модели песочницы kit/sbx
```

Скрипты kit запускают по полному пути, рабочая папка — проект. Подробности — `kit/README.md`.

## Метки уверенности

У каждого правила есть строка «Уверенность»:

| Метка | Что значит |
|---|---|
| [бой] | видно в бою: SQL Lab, DevTools, слова, фото или видео владельца |
| [стенд 24.8] | воспроизведено на стенде chdb 2.1.1 = ClickHouse 24.8.4.1 |
| [исходник 2.0.1] | следует из исходника Superset 2.0.1, sqlparse или ClickHouse нужной версии |
| [владелец дд.мм] | решение владельца с датой |
| [вывод] | следует из фактов, напрямую не проверено. Опыты в Chromium 141 и модель песочницы kit — тоже [вывод], со словом «стенд» рядом |
| [не проверено в бою] | добавка к любой метке; вопрос и способ проверки — в 17-open-questions.md |

«Спорно:» в правиле — решение, которое можно оспорить, и почему.

## Как устроено правило

```
### SP-06. Экранируй кавычку удвоением '', а слэш — раньше кавычки
- Почему:      инцидент или замер с датой и числами
- Как:         приём — фрагмент SQL, JS, CSS или команда из кода проектов
- Проверка:    чем проверить на стенде и что посмотреть владельцу в бою
- Уверенность: метки из таблицы выше
- Образец:     где сделано лучше всего: проект и файл, функция или макрос
```

В начале каждой главы — «Зачем глава» и «Главное в 5 пунктах», в конце — «Связанные главы». Ссылка на чужую главу —
кодом и файлом: «SP-06 (02-superset-path.md)».

## Как обновлять

1. **Пришёл ответ из боя** (SQL Lab, DevTools, слова владельца). Агент вносит факт в таблицу фактов 01-platform.md с
   меткой [бой] и источником. Правила, которые на нём стоят, он правит: снимает [не проверено в бою], обновляет числа.
   Вопрос в 17-open-questions.md переносит в раздел «Уже известно».
2. **Что-то сломалось.** Новая строка в 16-antipatterns.md и правило в главе, если его ещё нет.
3. **Коды не перенумеровывают.** Новое правило — следующим номером в главе, устаревшее переписывают на месте.
4. **В тот же день** проверяют поставки остальных проектов на старую формулировку (PR-25 в 15-process.md).
5. Меняют дату в строке «Состояние» этого файла и в начале SKILL.md.

Подробный порядок — SKILL.md, раздел 6.

## Безопасность

Репозиторий TeamPulse может быть публичным. В гайде и в kit нет внутренних адресов и хостов, токенов, настоящих ФИО и
логинов сотрудников, данных боя. Есть только агрегатные замеры (секунды, КБ, число строк), номера бордов и чартов
Proteus и логины синтетических миров стендов (`a.user`, `hr.super`, `b.kotov`, `nobody` и т. п.). Так же пишите и
дополнения. HAR, тела ответов `chart/data` и выгрузки SQL Lab с людьми не коммитьте (AC-16, PR-06).
