# 17. Открытые вопросы: что подтвердить в бою (OQ)

**Зачем глава.** Боя агент не видит. Часть правил гайда держится на исходнике Superset 2.0.1, на стенде chdb 24.8 или
на опытах в Chromium 141 — у них метка [не проверено в бою]. Здесь эти допущения собраны вопросами. У каждого — зачем
знать ответ, как владельцу проверить его за минуты (DevTools, SQL Lab без слова `system`, Explore), что поменяется от
ответа и как действовать, пока ответа нет. В конце — пакет проверок на один заход и бланк ответа.

**Главное в 5 пунктах** — эти ответы меняют больше всего правил:
1. **OQ-01.** Есть ли `GROUP BY` во внешней обёртке чарта. От ответа зависят порядок строк, склейка дублей и признак
   обрезки (SP-13, DS-25).
2. **OQ-02.** Какой sqlparse и стоит ли патч лексера Superset. От ответа зависят модель пути, экранирование и бюджет
   разбора (SP-02, SP-06).
3. **OQ-12.** Совпадает ли ключ кэша форка с 2.0.1. От ответа зависят и безопасность личного ключа, и общий кэш
   (AC-06…AC-09).
4. **OQ-16.** Чем песочница ловит ошибки окна — `window.onerror` или слушателем. От ответа зависит, спасает ли обёртка
   SB-03.
5. **OQ-09.** Профиль ClickHouse в бою: `prefer_column_name_to_alias`, `join_use_nulls`, `group_by_use_nulls`,
   `max_query_size`. От ответа зависят основной режим регресса и бюджет текста (CH-03, SP-16).

**Как пользоваться.**
- Опираешься на правило с меткой [не проверено в бою] — найди его вопрос здесь. Пока ответа нет, действуй по строке
  «Пока ответа нет».
- Владельцу отдавай вопросы пакетом и с бланком ответа (раздел «Пакет на один заход»). HAR и тела ответов не проси —
  только поля и скриншоты колонок (AC-16, PR-20).
- Пришёл ответ — обрабатывай по PR-24 (15-process.md):
  1. факт — строкой в таблицу фактов 01-platform.md с меткой [бой] и датой;
  2. в правилах, которые на нём стоят, сними [не проверено в бою] или перепиши правило на месте;
  3. вопрос перенеси в раздел «Уже известно» с датой и источником. Номер вопроса не переиспользуй.
- Слова `system` и `SHOW` в запросах SQL Lab нельзя даже в комментариях (PL-04). Все запросы SQL Lab в главе — один
  SELECT. Они проверены на chdb 2.1.1 (запросы с заглушками `<…>` — с подставленными именами) и гейтом
  `kit/sqlgate.py --sqllab` в обеих моделях лексера. Исключения — пробы OQ-02 и OQ-04: они нарочно ломают лексер или
  SQL Lab.

## A. Superset и путь SQL

### OQ-01. Есть ли `GROUP BY` во внешней обёртке чарта `react_sanbbox` — закрыт 09.10
- **Ответ (09.10, «Показать SQL запрос» каталога adoption):** `) AS virtual_table GROUP BY section, g, k, parent, n LIMIT 50000`. `GROUP BY` по всем
  «Измерениям» есть: строки уникальны, порядок не держится, обрезка — по числу строк (SP-13, DS-25). Ниже — как было спрошено.
- **Зачем:** у кастомного чарта `metrics: []`, и в 2.0.1 это даёт обёртку `SELECT <Измерения> FROM (…) AS virtual_table
  GROUP BY <Измерения> LIMIT N`. Тогда порядок строк под лимитом не держится, одинаковые строки склеиваются, а строка
  `end` не доказывает целостность. Правила: SP-13 (02-superset-path.md), DS-25 (05-dataset.md), ST-13 (13-stand.md),
  CJ-15 (07-chart.md).
- **Как проверить:**
  1. Борд → F12 → Network, фильтр `chart/data` → меню борда «Обновить дашборд».
  2. Ответ чарта: при холодном запросе — GET `chart/data/qc-…`, из кэша — POST с кодом 200.
  3. Response → `result[0].query`. Прислать конец текста: от `) AS virtual_table` до `LIMIT` (середину с SQL датасета
     не нужно).
  4. Другой путь: меню «⋯» чарта или Explore → пункт «View query». В русской локали 2.0.1 он переведён «Скопировать
     запрос», у форка может называться «Показать запрос».
- **Что меняется:**
  - Есть `GROUP BY` — правила остаются: строки уникальны, порядок восстанавливает JS, целостность — по `meta.rows`.
  - Нет — порядок под `LIMIT` держится, ORDER BY по роли и строка `end` становятся гарантией обрезки «с хвоста». Число
    строк в `meta` всё равно оставить: оно дешёвое.
  - В обёртке есть `WHERE` по носителю — носитель стоит в SELECT датасета, это нарушение SP-14.
- **Пока ответа нет:** считай, что `GROUP BY` есть ([исходник 2.0.1] + [стенд 24.8]).

### OQ-02. Какая версия sqlparse у Proteus и стоит ли патч лексера Superset — почти закрыт 09.10
- **Ответ (09.10):** Proteus сообщает `version_string` 2.1.0 (сниппет консоли). Superset 2.1.0 закрепляет `sqlparse==0.4.3`
  с патчем лексера `insert(0)`; модель «0.4.3 + патч» сходится с боем adoption (kit/RESULTS.md, «Модель боя»). Точный пин
  форка — `kit/server-probe.sh` на сервере; пробы SQL Lab п. 2.1–2.2 checklists/backend-probe.md ждут `2`, `a -- b` и
  ошибку. Ниже — как было спрошено.
- **Зачем:** по исходнику 2.0.1 — sqlparse 0.3.0 с патчем, а бой adoption ведёт себя как 0.4.x. От модели зависит, какие
  строки ломает лексер (`\'`, «]»), сколько стоит разбор и какой бюджет текста держать. Правила: SP-02, SP-06, SP-07,
  SP-15 (02-superset-path.md), ST-12 (13-stand.md).
- **Как проверить:** SQL Lab, два запроса по одному на выполнение. Прислать ответ или текст ошибки целиком.
  ```sql
  SELECT length(['x', '[y]']) AS n, 'a -- b' AS s
  ```
  ```sql
  SELECT 'O\'K; c' AS t
  ```
- **Что меняется:**

  | Запрос | Ответ | Значит |
  |---|---|---|
  | первый | `n = 2`, `s = a -- b` | sqlparse ≥ 0.4.3: основная модель — М2 (0.4.4 + патч), бюджет разбора — по ней; М1 — запас |
  | первый | ошибка | sqlparse 0.3.0: основная модель — М1 |
  | второй | ошибка | патч Superset стоит: `\'` в литералах опасен — только `''` |
  | второй | `t = O'K; c` | патча нет: `\'` лексер не сбивает, но `''` оставить — так верно в обоих случаях |

  Верхняя граница уже известна: в бою sqlparse < 0.5.5 (файл 10 DL исполнился в SQL Lab, а 0.5.5 на нём падает).
- **Пока ответа нет:** датасет проходит обе модели, экран — только `''`, «]» — только в `array(…)` ([исходник 2.0.1];
  бой ≈ 0.4.x — [вывод]).

### OQ-03. Чем форк проверяет SQL при сохранении и какое у него окружение Jinja
- **Зачем:** «Некорректный SQL запрос: →…←» — проверка самого форка, её нет в Superset. Гейт sqlglot 23–30 — только её
  модель: отказ на алиасе в `GROUP BY` он повторяет, а отказ на кортежном типе в строке CAST — нет. Jinja форка может
  отличаться от `SandboxedEnvironment(undefined=DebugUndefined)` без расширений. Правила: SP-03, SP-04 (02-superset-path.md),
  ST-15 (13-stand.md).
- **Как проверить:** только на копии, в новом пробном виртуальном датасете. Сохранить по очереди тексты ниже и записать,
  какой дал ошибку (текст целиком). После пробы датасет удалить.
  1. `SELECT ch, count() AS n FROM (SELECT intDiv(number, 10) AS ch FROM numbers(100)) GROUP BY ch` — ждём: сохраняется.
  2. `SELECT ch, count() AS n FROM (SELECT number AS x FROM numbers(100)) GROUP BY intDiv(x, 10) AS ch` — ждём: «Некорректный SQL запрос».
  3. `SELECT CAST([], 'Array(Tuple(UInt8, String))') AS a` — ждём: «Некорректный SQL запрос» (так было 18.09).
  4. `{% set x = [] %}{% do x.append(1) %}SELECT 1 AS a` — ждём ошибку шаблона: в 2.0.1 расширения `do` нет.
- **Что меняется:** (2) прошло — проверка форка мягче гейта; (3) прошло — запрет кортежного CAST снять; (4) прошло — у форка
  есть `do`, но писать его всё равно не надо: стенд и гейт его не моделируют.
- **Пока ответа нет:** гейт sqlglot 23–30, grep кортежного типа в строке CAST, без `{% do %}`.

### OQ-04. Что ещё запрещает и меняет SQL Lab форка: `WITH` первым словом, `LIMIT N BY`, кэш по тексту
- **Зачем:** запрет `WITH` первым словом и `* REPLACE` — осторожность, отказа не было. `LIMIT N BY` на верхнем уровне
  SQL Lab 2.0.1 принимает за лимит строк. Кэша результата по тексту в 2.0.1 нет, но adoption 22.09 видел 16,42 → 1,57 с
  на одном тексте. Правила: PL-04, PL-05 (01-platform.md), DV-27, DV-28 (14-delivery.md), ST-32 (13-stand.md).
- **Как проверить:** SQL Lab, по одному:
  1. `WITH 2 AS x SELECT x AS y` — прислать ответ или текст отказа.
  2. `SELECT number AS n FROM numbers(10) LIMIT 2 BY number % 2` — сколько строк показал SQL Lab.
  3. Файл «где время» проекта — три прогона подряд: (а) как есть после простоя; (б) тот же текст сразу; (в) с другой
     меткой внутри запроса (`2 AS run` → `3 AS run`). Прислать три времени, которые показал SQL Lab.
- **Что меняется:**
  - (1) отказ — «`WITH` первым словом нельзя» становится фактом; ответ `2` — осторожность снять.
  - (2) 4 строки — `LIMIT N BY` безвреден; 2 строки — подтверждено, держать его только внутри подзапроса.
  - (3) (б) намного быстрее (в) — у форка есть кэш SQL Lab по тексту, метка внутри запроса обязательна (так и делаем);
    (б) ≈ (в) — кэша нет, ускоряют кэши ClickHouse и ОС.
- **Пока ответа нет:** `WITH` первым словом не писать, `LIMIT N BY` — только внутри подзапроса, метку прогона ставить в сам
  запрос.

### OQ-05. Рендерит ли SQL Lab форка Jinja и какой логин видит Proteus
- **Зачем:** запрос «кто я для Proteus» (AC-17) и проверки, рассчитанные на шаблоны в SQL Lab. В ванильном 2.0.1 SQL Lab
  рендерит Jinja под тем же флагом, что датасеты. Adoption 18.09 записал «не рендерит», но не проверял. Правила: AC-17
  (03-access-cache.md), факты F7 и F17 (01-platform.md).
- **Как проверить:** SQL Lab: `SELECT '{{ current_username() }}' AS who`. Сам логин не присылать — только «мой логин»,
  «буквально скобки» или текст ошибки.
- **Что меняется:** рендерит — запрос «кто я» работает как есть. Не рендерит — логин сессии смотреть в профиле Proteus, а
  запрос «кто я» давать с заглушкой логина. SQL Lab-файлы поставки остаются отрендеренными скриптом в любом случае (DV-27).
- **Пока ответа нет:** в SQL Lab-файлах Jinja нет, логин — заглушкой `ваш_логин`.

### OQ-06. Доходят ли параметры адреса до запроса кастомного чарта; работают ли якорь вкладки и короткая ссылка

  3. Значок ссылки у названия вкладки → короткая ссылка → открыть в новом окне. В адресе снова `probe=1` и якорь `#TAB-…`?
     Открылась ли та же вкладка?

### OQ-07. Какой предел длины адреса у Proteus
- **Зачем:** у nginx по умолчанию строка запроса ≤ 8 КБ, у gunicorn ≤ 4 094 байт; что стоит у Proteus — неизвестно.
  Permalink при открытии раскрывается в тот же длинный адрес. Правила: SB-18 (08-sandbox.md), SP-23, факт F24.
- **Как проверить:** на копии борда открыть адрес с параметром длиной ≈6 000 знаков (кнопка «Ссылка» с длинным списком
  или `?probe=` и 6 000 букв `x`). Ответ 414 или 400 — предел меньше. Борд открылся и в Payload весь `probe` — предел
  больше.
- **Что меняется:** проходит 6 000 — предел ссылки (`CFG.board.maxLen`) можно поднять до 6 000; нет — держать 4 000 или
  меньше по пробе.
- **Пока ответа нет:** ссылка ≤ 4 000 знаков в закодированном виде.

### OQ-08. Какой бэкенд кэша у Proteus и какое время жизни по умолчанию
- **Зачем:** −1 в «Время жизни кэша» уходит в бэкенд сроком жизни, в Redis это запись без срока. Объяснение владельцу
  зависит от бэкенда. Правила: SP-24 (02-superset-path.md), факт F19.
- **Как проверить:** спросить администратора Proteus: `CACHE_CONFIG` и `DATA_CACHE_CONFIG` (Redis, Metastore, Simple),
  `CACHE_DEFAULT_TIMEOUT`.
- **Что меняется:** только объяснение. Правило «пусто или 0, −1 не ставить» остаётся при любом ответе.
- **Пока ответа нет:** пусто или 0 — это 12 ч (`cache_timeout` 43 200 с виден в ответах).

## B. ClickHouse

### OQ-09. Какой профиль ClickHouse в бою: режимы и пределы — закрыт 09.10
- **Ответ (SQL Lab владельца, 09.10):** `24.8.15.1`, анализатор `true`, `max_execution_time` 30, `max_threads` 12,
  `prefer_column_name_to_alias` **1**, `join_use_nulls` 0, `group_by_use_nulls` 0, `max_query_size` 262 144,
  `max_ast_elements` 50 000, `max_expanded_ast_elements` 500 000, `max_parser_depth` 1 000, `use_query_cache` 0. Профиль
  боя — основной режим стенда (F14, CH-03). Ниже — как было спрошено.
- **Зачем:** Code 215 в бою (adoption 23.09) воспроизводится только при «новый анализатор + `prefer_column_name_to_alias
  = 1`», поэтому в бою, вероятно, `prefer = 1`. Пределы текста запроса сняты только на стенде. Правила: CH-03, CH-28
  (04-clickhouse.md), SP-16 (02-superset-path.md), факты F14 и F15.
- **Как проверить:** SQL Lab, один запрос. Прислать строку ответа целиком.
  ```sql
  SELECT version() AS v,
         getSetting('allow_experimental_analyzer') AS analyzer,
         getSetting('max_execution_time') AS max_exec_s,
         getSetting('prefer_column_name_to_alias') AS prefer_alias,
         getSetting('join_use_nulls') AS join_nulls,
         getSetting('group_by_use_nulls') AS group_nulls,
         getSetting('max_query_size') AS max_query_size,
         getSetting('max_ast_elements') AS max_ast,
         getSetting('max_expanded_ast_elements') AS max_ast_exp,
         getSetting('max_parser_depth') AS max_depth,
         2 AS run
  ```
  На стенде (chdb 2.1.1) ответ такой: `24.8.4.1, true, 0, false, false, false, 262144, 50000, 500000, 1000, 2`.
- **Что меняется:**
  - `prefer_alias = 1` — Code 215 объяснён, режим «новый анализатор + prefer» становится основным в регрессе.
  - `join_nulls` или `group_nulls = 1` — эти режимы тоже основные (ключи ROLLUP и признаки пар через `ifNull`).
  - `max_query_size` больше 262 144 — бюджет текста можно поднять, меньше — снизить.
  - `max_ast` меньше 50 000 — `array(…)` короче.
  - Ответ — строками в таблицу фактов F 01-platform.md.
- **Пока ответа нет:** вся матрица режимов CH-03, бюджет — 256 КиБ после `reindent` с запасом 10 %.

### OQ-10. Где время Proteus в бою: почему холодный бой ≈ 2× стенда
- **Зачем:** панель DL — 7,0 с холодно в бою против 3,3 с на стенде, adoption — 5,7 против 2,6 с. Неизвестно, что это:
  нагрузка кластера, разбор Superset (`reindent`, ключ кэша) или упаковка JSON. От ответа зависит, что ускорять.
  Правила: PL-03 (01-platform.md), ST-19 (13-stand.md), PR-08 (15-process.md).
- **Как проверить:** один сценарий, одна вкладка.
  1. Файл «где время» — холодно и тепло (OQ-04, п. 3).
  2. Протокол DevTools того же сценария (DV-29): Timing у POST и у GET `qc-…`, сколько раз забирается один `qc-…`.
  3. Время Proteus = время в браузере − время SQL Lab. Пустой запрос SQL Lab стоит ≈ 0,5 с.
- **Что меняется:** большое «время Proteus» — сокращать текст датасета и не держать логин в ключе без нужды (SP-15,
  SP-22). Большое время ClickHouse — SQL (04-clickhouse.md). Большой приём — вес ответа (DS-16).
- **Пока ответа нет:** множитель бой / стенд 24.8 — ≈ 2× холодно, ≈ 1× тепло (факт F22).

### OQ-11. Что дают настройки базы (`allow_query_settings`, `enable_data_access_control`, `is_internal_db`) и есть ли RLS
- **Зачем:** RLS вошёл бы в ключ кэша и мог бы резать строки. `allow_query_settings` может оказаться штатным путём
  передать настройки ClickHouse, раз SETTINGS в датасете падает. Правила: AC-01 (03-access-cache.md), CH-04
  (04-clickhouse.md), факт F12.
- **Как проверить:** спросить администратора Proteus. RLS виден в меню «Security → Row Level Security» у тех, у кого есть
  права администратора.
- **Что меняется:** RLS есть — учитывать его в ключе кэша (SP-21) и в пробе на коллеге. Настройки передаются штатно —
  проба на копии борда (DV-08), иначе — только профилем ClickHouse.
- **Пока ответа нет:** доступ — только внутри датасета, настроек ClickHouse в тексте датасета нет.

## C. Доступ и кэш

### OQ-12. Совпадает ли ключ кэша форка с Superset 2.0.1
- **Зачем:** форк мог поменять `ExtraCache.regex` или состав ключа. Ошибка в одну сторону — утечка ответа с чужими
  данными, в другую — холодное открытие у каждого. Правила: AC-06…AC-09 (03-access-cache.md), SP-20, SP-21
  (02-superset-path.md).
- **Как проверить:** вы и коллега, один борд, одни и те же фильтры → F12 → Network → ответ `chart/data` каждого чарта →
  Response → `result[0].cache_key` и `is_cached`. Прислать по каждому чарту первые 8 знаков ключа: «у меня …, у коллеги …».
- **Что меняется:**
  - Личный датасет (логин в ключе) с одинаковым ключом — утечка, срочная поставка (AC-12).

### OQ-13. Видит ли коллега черновик борда и что нужно для пробы на коллеге

## D. Песочница и код чарта

### OQ-16. Чем песочница ловит ошибки окна: `window.onerror` или слушателем `error`
- **Зачем:** обёртка `window.onerror` (SB-03) пропускает мимо песочницы «ResizeObserver loop». Если песочница слушает
  `addEventListener('error')`, обёртка её не опередит, и держит только `overflow:hidden`. Правила: SB-03
  (08-sandbox.md), факт S8; `kit/sbx/run.cjs --catch`.
- **Как проверить:** F12 → Console → в списке контекстов (слева вверху, «top») выбрать фрейм чарта, у которого нет нашей
  обёртки (HRBP, adoption, TeamPulse или любой чужой кастомный чарт), и ввести:
  ```js
  ({ onerror: typeof window.onerror, listeners: (getEventListeners(window).error || []).length })
  ```
  Во фрейме чарта DL (с обёрткой): `String(window.onerror).indexOf('ResizeObserver') >= 0` — `true` значит, что обёртка
  встала. `getEventListeners` работает только в консоли DevTools [вывод].
- **Что меняется:** `onerror: 'function'` и 0 слушателей — песочница ставит `onerror`, обёртка работает: держать обе
  защиты. `onerror: 'object'` (null) и слушатель есть — обёртка бесполезна, защищает только `overflow:hidden`: проверять
  его строже, модель kit гонять с `--catch listener`.
- **Пока ответа нет:** обе защиты обязательны в каждом чарте.

### OQ-17. Как форк создаёт iframe чарта и что чарт видит в `document.referrer`
- **Зачем:** iframe по `src` с того же хоста видит в `document.referrer` путь борда, а iframe по `srcdoc` — только хост.
  От этого зависит адрес для кнопки «Ссылка». Как форк запускает код (`new Function` или `<script>`), тоже неизвестно.
  Правила: SB-17 (08-sandbox.md), CJ-04 (07-chart.md); `kit/sbx/run.cjs --frame`, `--exec`.
- **Как проверить:**
  1. F12 → Console, контекст top:
     ```js
     Array.prototype.map.call(document.querySelectorAll('iframe'), function (f) {
       return f.hasAttribute('srcdoc') ? 'srcdoc' : (f.hasAttribute('src') ? 'src' : '—');
     }).join(' ')
     ```
  2. Контекст — фрейм чарта:
     ```js
     document.referrer.replace(/^[a-z]+:\/\/[^\/]+/i, '') || '(пусто)'
     ```
     Строка прошла без хоста. `/superset/dashboard/<id>/…` — путь есть; `/` или «(пусто)» — только хост.
- **Что меняется:** путь есть — адрес борда из referrer, запасной из `meta` нужен только копиям. Пути нет — ссылка всегда
  из `meta.board`; на копии борда она ведёт на боевой борд, об этом — строка в инструкции.
- **Пока ответа нет:** referrer, затем запасной адрес из `meta` датасета.

### OQ-18. Почему загрузчик кода 22-й поставки DL сломал все чарты

### OQ-20. Держится ли маркер канала скриншотов после перезапуска чарта и доходит ли маркер тура

  TR-22).

### OQ-21. Есть ли у страницы борда свой прокручиваемый контейнер и какой высоты липкая шапка

### OQ-22. Какие шрифты рисуются у коллег и схлопываются ли веса
- **Зачем:** в iframe виден только установленный шрифт: Inter страницы Superset туда не доходит. У Arial 500 рисуется как
  400, а 600 — как 700. TeamPulse перешёл на 400 / 700, ссылаясь на «в Proteus только Arial», но без замера. Правила:
  UI-03, UI-04 (11-ui.md).
- **Как проверить:** у себя и у коллеги на Windows: Console → контекст — фрейм чарта → вставить и прислать строку:
  ```js
  (function () {
    var c = document.createElement('canvas').getContext('2d'), s = 'Отчёт HRBP 1234567890 мм', o = {};
    function w(f) { c.font = f; return c.measureText(s).width; }
    function has(f) { return w('12px "' + f + '", monospace') !== w('12px monospace') && w('12px "' + f + '", serif') !== w('12px serif'); }
    ['Inter', 'Segoe UI', 'Roboto', 'Arial'].forEach(function (f) { o[f] = has(f) ? 'есть' : 'нет'; });
    o['Arial 500 = 400'] = w('500 12px Arial') === w('400 12px Arial');
    o['Arial 600 = 700'] = w('600 12px Arial') === w('700 12px Arial');
    o[':has'] = !!(window.CSS && CSS.supports && CSS.supports('selector(:has(a))'));
    o.ua = navigator.userAgent;
    return JSON.stringify(o);
  })()
  ```
  Проверено в Chromium 141 в iframe `sandbox="allow-scripts"`: несуществующий шрифт даёт «нет».
- **Что меняется:** Inter у коллег есть — профиль как есть. Только Arial или Segoe UI — иерархия цветом остаётся главной;
  проверить экран с 500 = 400. Спор TeamPulse (400 / 700 против 400 / 500 / 600) решается этим ответом.
- **Пока ответа нет:** веса 400 / 500 / 600, иерархия — цветом, кеглем и капителью.

### OQ-23. Поддерживают ли браузеры коллег `:has()`

- **Пока ответа нет:** `:has()` работает у владельца (DL — с 10-й поставки), базу держать и по классу холдера.

### OQ-26. Перезапрашивает ли Proteus ту же маску и входит ли порядок значений в ключ
- **Зачем:** если порядок значений входит в ключ, тот же выбор в другом порядке кликов — холодный запрос. Если повтор

- **Как проверить:** выбрать значения A, B → «Применить» → Response `cache_key`. Сбросить, выбрать B, A → `cache_key`.
  Затем «Применить» без изменений — ушёл ли POST.
- **Что меняется:** ключи разные — сортировка значений в маске обязательна (у HRBP добавить). POST на повтор уходит —
  MC-03 экономит запрос. POST не уходит — без MC-03 чарт ждал бы ответа вечно.
- **Пока ответа нет:** значения сортировать, повтор и умолчание не эмитить.

### OQ-27. Грузит ли Proteus чарты неоткрытых вкладок и пересоздаёт ли iframe при переключении
- **Зачем:** чарт на скрытой вкладке не должен ждать ответов; после пересоздания iframe `window.__pvtState` пропадает, и
  применённое берётся только из эха ответа. Правила: MC-12, MC-14 (09-multi-chart.md), CJ-05 (07-chart.md).
- **Как проверить:** открыть борд с двумя вкладками → Network: есть ли POST `chart/data` чартов второй вкладки до перехода
  на неё. В чарте первой вкладки поменять вид (колонку, сортировку) → уйти на другую вкладку и вернуться: вид остался
  (iframe жив) или сбросился (пересоздан).
- **Что меняется:** неоткрытые вкладки не грузятся — первое открытие вкладки — свой холодный запрос, писать это в «Что
  нового». iframe пересоздаётся — всё, что должно пережить переход, держать в эхе ответа или в ссылке.
- **Пока ответа нет:** состояние — в `window.__pvtState`, применённое — из эха ответа.

### OQ-37. Есть ли в MDM-источнике ноутов повторы юнита ниже по пути и заглушки уровней
- **Зачем:** в источнике списков DL уровни ниже юнита заполнены им же — узлов в 4,25 раза больше листов. В
  `mdm_employee_structure_d` (HRBP, adoption) это не проверено. У HRBP повтор ломает справочник юнитов: путь из md5
  уровней получает один id дважды, и юнит может оказаться родителем самому себе (`pid = id`). Результаты «Диагностики
  источников» HRBP (значения разрезов, покрытие разметки) тоже не присланы. Правила: DS-21 (05-dataset.md), GP-09, GP-18
  (06-helicopter-gp.md).
- **Как проверить:** у HRBP — SQL Lab по справочнику юнитов, который ноут уже выгрузил в ClickHouse (дополняет проверку 6
  файла 5 поставки HRBP):
  ```sql
  SELECT count() AS units,
         countIf(ifNull(id = pid, 0)) AS self_parent,
         countIf(arrayUniq(path) < length(path)) AS repeated_in_path,
         countIf(match(ifNull(nm, ''), '^[[:space:][:punct:]—–…]*$')) AS stub_names,
         max(length(path)) AS max_depth
  FROM prod_proteus.hrbp_hub_unit
  ```
  Ждали: `self_parent` и `repeated_in_path` — 0; `max_depth` — глубина пути, до 11 id (lvl1 и lvl3…lvl12).
  `stub_names` — юниты с пустым именем или именем из одних знаков («-», «—», «…»). Ноут сам пишет «—» вместо пустого
  имени, поэтому не 0 — не ошибка, а число для GP-18. На стенде HRBP ответ `82, 0, 0, 0, 11`; на синтетике с повтором и
  заглушками запрос находит все случаи (тире собраны из байтов: chdb меняет тире в тексте запроса на `--`). У adoption
  уровни — имена `lvl3…lvl7` в витринах ноута: то же условие «уровень равен предыдущему» ставь в параграф ноута
  ([вывод], не проверено).
- **Что меняется:** повторы есть — правило `nodup` в ноуте (у HRBP — до md5 пути) или в датасете; заглушки — пустым
  уровнем по GP-18.
- **Пока ответа нет:** `nodup` — только у DL.

### OQ-38. Есть ли в боевых значениях фильтров апостроф, «]», `--`, `;` и слэш в конце
- **Зачем:** показывает, насколько реальна угроза сбоя лексера для конкретного отчёта. Экран `''` и `array(…)` при «]»
  нужны в любом случае. Правила: SP-06, SP-07, SP-08 (02-superset-path.md), AC-14 (03-access-cache.md).
- **Как проверить:** SQL Lab, по запросу на каждую колонку-фильтр (подставить схему, таблицу и колонку). Прислать числа.
  ```sql
  SELECT count() AS total,
         countIf(position(v, '''') > 0) AS apostrophe,
         countIf(position(v, ']') > 0) AS bracket,
         countIf(position(v, '--') > 0) AS dashes,
         countIf(position(v, ';') > 0) AS semicolon,
         countIf(endsWith(v, char(92))) AS backslash_end
  FROM (SELECT DISTINCT ifNull(toString(<колонка>), '') AS v FROM <схема>.<таблица>)
  ```
- **Что меняется:** числа больше 0 — поставка с `''` и `array(…)` срочная; все 0 — плановая.
- **Пока ответа нет:** экран `''`, «]» — только в `array(…)`.

### OQ-39. Какой ключ сортировки у чужих таблиц-источников
- **Зачем:** фильтр датасета читает гранулы, только если идёт по префиксу ключа сортировки. Из SQL Lab ключ не узнать:
