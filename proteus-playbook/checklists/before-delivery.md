# Чек-лист: перед сдачей поставки

**Зачем.** Маршрут проверок — десяток команд, и легко отдать файл без одной из них: апострофная дыра в датасете, чарт,
гаснущий на Windows, CSS с заглушками, SQL Lab-файл со словом `system`. Здесь — всё, что прогнать до того, как папка
поставки уйдёт владельцу, по порядку гейта ST-33, командами `kit/` и стенда проекта. Любой провал — стоп: коммит
«WIP — не для установки», папка поставки прежняя (PR-22).

**Главное в 5 пунктах.**
1. **SP-02, ST-12.** Датасет — путём Superset 2.0.1 в обеих моделях лексера (М1 и М2), с враждебным вводом и
   исполнением на ClickHouse 24.8; ответ после пути равен прямому запуску.
2. **AC-08, ST-16.** Ключ кэша — по сырому тексту файлов поставки: личный датасет — ЛИЧНЫЙ, общий — ОБЩИЙ, «ОПАСНО» нет.
3. **CJ-20, ST-24.** Чарт: `node --check` → ESLint no-undef → `check.py` скилла → модель песочницы; сборка —
   `min.cjs --verify`.
4. **ST-30.** Живой прогон, тур и регресс — на файлах поставки (сжатая сборка, подставленные id), validate скилла — на
   исходнике.
5. **DV-11, DV-15.** «Что нового» — по формату, «Заменить:» = вывод сборщика; «проверено» и «не проверено» — числами
   этого прогона.

## 1. Датасет — каждый вариант, на исходнике и на файлах поставки

```sh
$PY stand/check.py                         # регресс: 24.8 Nullable и plain, режимы, оракул, независимый расчёт
for P in $PY $PY44; do                     # обе модели лексера; в расчёт бюджета — большее
  $P $KIT/superset201.py $X.data.sql --user <логин> --cols auto --filters @stand/<типичный>.json \
     --run --db stand/.db --hostile --hostile-set full --matrix
  $P $KIT/superset201.py $X.data.sql --user <логин> --cols auto --filters @stand/<худший>.json \
     --run --db stand/.db --max-reindent-s 1 --max-key-s 0.5
  $P $KIT/sqlgate.py $X.data.sql --user <логин> --cols auto --filters @stand/<худший>.json \
     --sqlglot-dirs "$SG" --sqlparse-dirs "$SP"
done
git show <проект>-<N-1>:$X.data.sql > /tmp/old.sql && $PY stand/same.py /tmp/old.sql   # если датасет переписан
```

Нет `base64Encode` в chdb 2.1.1 — `--ch-sub 'base64Encode\(=>('` (ST-21). Варианты датасета (вкладки, общий вид) —
файлами поставки после `pack.py`, тем же списком команд.

- [ ] Код выхода 0 в обоих venv: одна инструкция, лексер в фазе, «ответ после пути тот же» во всех режимах ClickHouse;
      на каждом логине мира, в том числе `nobody` (только meta с `ok = 0`, AC-02).
- [ ] Сохранение (AlwaysTrue + `LIMIT 1000`) исполняется (SP-05); враждебные хвосты: «ответ тот же», отброшенное —
      «до SQL не дошло» по пределам (AC-14).
- [ ] Ключ кэша: личный датасет — «ЛИЧНЫЙ», общий — «ОБЩИЙ» (вызовов нет даже в комментариях), «ОПАСНО» нет (AC-07…AC-09).
      Текст SQL и ответ общего датасета одинаковы до байта у всех логинов мира (AC-09).
- [ ] Бюджет худшего набора носителей: после обёртки и reindent < 256 КиБ с запасом 10 %, токенов < 10 000, reindent
      ≤ 1 с, разбор ради ключа ≤ 0,5 с у личного; не дороже прошлой поставки (SP-15…SP-17, ST-17).
- [ ] Холодный худший запрос на стенде боевого масштаба ≤ 15 с (×2 в бою — предел 30 с), клик ≈ 1 с (PL-02, ST-19);
      строк ответа ≪ 50 000 (DS-24); вес JSON и на проводе — в «Что нового» (DS-16).
- [ ] grep (совпадения в комментариях и строках разобрать глазами, в коде их быть не должно):
      `rg -n '^\s*(SETTINGS|FORMAT)\b|AS\s+MATERIALIZED' proteus/*.data.sql` (CH-04);
      `rg -n "'[^']*Tuple\(" proteus/*.data.sql` — кортежный тип в строке CAST гейт не ловит (CH-17).
- [ ] `same.py`: «случаев N, расхождений 0 · ClickHouse 24.8.4.1»; время на 24.8 не хуже (ST-11, PR-11).
- [ ] Шапка датасета, `proteus/FIELDS.md` и ответ совпадают: роли, колонки, носители (DS-26); колонки не менялись —
      инструкция говорит «Измерения не трогать» (DV-20).


      S11a, C4, K3b, S20.

      открытие и закрытие выпадашек — чарт на месте (SB-03, SB-20). Три перезапуска подряд — один overlay, клик
      срабатывает один раз (CJ-03, CJ-06).
