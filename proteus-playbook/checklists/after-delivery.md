# Чек-лист: после вставки — что владелец проверяет и присылает, как это разобрать

**Зачем.** Боя агент не видит: всё, что известно о бое, приходит от владельца — текстом ошибки, скриншотом, выводом
DevTools и SQL Lab. Без точной просьбы владелец присылает не то (HAR с данными сотрудников) или не присылает ничего, а
агент правит вслепую. Здесь — что владелец делает сразу после вставки, что и когда просить, по каким бланкам, и как
агент обрабатывает ответ. Пути кликов для владельца — в инструкции поставки (`<playbook>/templates/instruction.template.md`,
п. 8); здесь — когда это просить и что значит ответ.

**Главное в 5 пунктах.**
1. **DV-13, DV-18.** После каждой вставки — Save, Update chart, жёсткая перезагрузка; штамп в подсказке «Как работать»
   = номер поставки. Красное — стоп и текст ошибки целиком.
2. **PR-10.** На «сломалось» — сначала факты: текст на месте чарта, скриншот целиком, консоль F12 целиком, номер
   стоящей поставки. Откат на прошлую рабочую поставку — можно и без фактов, новая правка — только с ними.
3. **PR-20, AC-16.** Просить конкретные поля под конкретный вопрос (`cache_key`, `result[0].query`, Size и Timing), а
   не HAR и не тела ответов.
4. **DV-27, DV-28, DV-30.** Факты боя — файлами поставки: один запрос SQL Lab, «где время» тремя прогонами, сниппет
   разметки.
5. **PR-24.** Ответ из боя — по порядку: сохранить агрегаты, сверить с пределами, записать в CLAUDE.md, факт платформы —
   в гайд, откалибровать стенд, воспроизвести, почистить сырое.

## 1. Сразу после вставки — владелец, 5 минут

| Что | Как | Норма | Если нет |
|---|---|---|---|
| Датасет | SQL целиком → Save; колонки поменялись — «Синхронизировать столбцы» (DV-18) | сохранился без красного, колонки = FIELDS.md | текст ошибки целиком; «→…←» — фрагмент между стрелками (SP-04) |
| Настройки датасета | «Время жизни кэша» пусто или 0, «Описание» = номер поставки (DV-21) | в ответе `cache_timeout` 43 200 | −1 не ставить: кэш не выключает (SP-24) |
| Чарт | JS целиком → Update chart → Save → Cmd/Ctrl+Shift+R | в подсказке «Как работать» — «поставка N» | старый штамп — у соседа старый JS из кэша: снова жёсткая перезагрузка (DV-18) |
| CSS борда | прежний блок отчёта удалить, файл вставить целиком в конец → Сохранить → Cmd/Ctrl+Shift+R | нет белых рамок; при загрузке — «Загружаю…» | сниппет разметки (п. 5) |
| JSON-метаданные | вставить → сохранить свойства → «Сохранить» → опубликовать → обновить → сверить JSON (MC-09) | на «Применить» перезапросились ровно получатели из таблицы инструкции (MC-10) | прислать, какие `chart/data` ушли (Payload → `form_data.slice_id`) |
| Холодный кэш | общий датасет — сразу открыть его вкладку (DV-22) | второй человек получает ответ сразу (POST 200) | — |
| «Проверить» из «Что нового» | один признак за минуту (DV-11) | как написано | что видно вместо — скриншот целиком |

## 2. Если «красное» или чарт пропал — что прислать

- [ ] Текст на месте чарта или текст ошибки — целиком, текстом.
- [ ] Скриншот всего экрана (не вырезку).
- [ ] F12 → Console — целиком (что в ней кроме «ResizeObserver loop…»): по тексту — таблица «Симптом → правило»
      08-sandbox.md.
- [ ] Номер стоящей поставки — штамп в подсказке «Как работать» (DV-09); какие файлы ставили и в каком порядке (DV-10).
- [ ] Для данных — Network → `chart/data`: Status, Size, Time; Payload `queries[0]`; Response — `result[0].query`
      (без HAR, AC-16).
- [ ] Развилка «сигнал или CSS» — однострочник маркера при открытой выпадашке (или туре) из п. 6 инструкции (DV-13).
- [ ] Правило агента: правка — только после воспроизведения на стенде на файлах этой поставки (PR-09); пока фактов нет —
      откат на прошлую рабочую поставку (PR-10). В «Что нового» следующей поставки заранее пиши «если не легло — пришлите …».

## 3. Протокол DevTools — когда просить

| Когда | Что взять из протокола | Зачем |
|---|---|---|
| первая установка | Timing одного POST, Size ответа, `cache_timeout` | «бой: что известно»: сеть, вес, кэш |
| «долго грузится» | всё по бланку п. 8.5 инструкции | раскладка по слагаемым — checklists/perf-triage.md |
| после правки кэша (логин в ключе, общий кэш) | `cache_key` у двух логинов при тех же фильтрах | личный — разные, общий — одинаковые (AC-07, AC-09) |
| после поставки с ускорением | те же поля, что сняты «до» | подтверждение «было → стало» в бою (PR-11) |
| ссылка на вид не работает | Payload → `queries[0].url_params` | пусто — параметры адреса до чарта не доходят (SP-23) |
| пропали строки, порядок «скачет» | Response → `result[0].query`: есть ли GROUP BY | вид обёртки (SP-13, DS-25) |

Путь кликов и бланк — DV-29 (14-delivery.md) и п. 8.2, 8.5 инструкции. Голый `force` в адресе `chart/data` — норма;
`force=true` со значением — запрос мимо кэша (SP-25).

## 4. SQL Lab — когда просить

| Файл | Когда | Что прислать | Правило |
|---|---|---|---|
| «Проверка на бою — один запрос» | первая установка; изменился источник; вопрос про объёмы, словари, деревья | ответ (CSV или скриншот) и время | DV-27 |
| «Где время» | «долго»; после поставки с ускорением | ответ и три времени: (а) после простоя, (б) тот же текст сразу, (в) с меткой `2 AS run` | DV-28, PL-05, OQ-04, OQ-10 |
| «Какой лексер у Proteus» (два запроса) | один раз на весь Proteus и после его обновления | оба ответа, ошибки — текстом целиком | SP-02, OQ-02 |
| «Кто я для Proteus» | «Мои» пустые, чужая зона, «нет доступа» у того, у кого доступ есть | ответ под собой и под коллегой (сам логин не присылать) | AC-17, OQ-05 |
| «Проверки после выгрузки» | после прогона ноута Helicopter | ответы с «Ждали:» | GP-22 |

- [ ] Логин в файле подставлен (Ctrl+H `ваш_логин`, число мест — в шапке); не подставлен — личная часть отдала только
      `meta` (так и читать ответ).
- [ ] Время SQL Lab ≈ время ClickHouse; пустой запрос ≈ 0,5 с; время Proteus = браузер − SQL Lab (PL-05).
- [ ] Первая установка — заодно «Пакет на один заход» из 17-open-questions.md: открытые вопросы платформы одним
      сеансом владельца, с бланком ответа.

## 5. Сниппет разметки борда — когда просить

- [ ] Первая установка CSS; поставка с правкой блоков 5–7; «рамки остались», «вкладки — пилюли», «поле сверху больше,
      чем сбоку», «внизу полоса» (BC-22, DV-30).
- [ ] Владелец: борд на нужной вкладке, не в режиме правки → F12 → Console, контекст «top» → вставить → Enter (Chrome
      может попросить `allow pasting`) → прислать вывод целиком.
- [ ] Агент: строка `ИТОГ:` — число расхождений; «замените 201 на N» — число в блок 7 исходника CSS (следующей поставкой
      или Ctrl+H владельцем сейчас); «браузер отбросил K блоков» — синтаксис или незнакомый селектор; «правило ни с чем не
      совпадает» — у форка другие классы: цепочку ячейки — в каркас стенда и в CSS (BC-23).
- [ ] Владелец сам поправил CSS на борде (поля, число высоты) — его числа в исходник до следующей поставки, цели сниппета
      и проверки стенда — те же числа (DL 08.10: 12 и 201; DV-35).

## 6. Проба на коллеге (AC-18)

- [ ] Черновик опубликован; права на дашборд и на **все** новые датасеты выданы.
- [ ] Минимум два логина разных видов доступа (полный и частичный), по возможности — без строки доступа; у каждого —
      ожидаемое из таблицы п. 4 инструкции (AC-04).
- [ ] `cache_key` у двух логинов при тех же фильтрах: у личного датасета разный, у общего одинаковый (AC-06).
- [ ] «Нет доступа к датасету» — права Proteus; «Нет доступа к отчёту» в чарте — таблица доступа (AC-18).

## 7. Как агент разбирает присланное (PR-24)

1. [ ] **Сохранить:** файл владельца — в `inbox/` (только агрегаты: секунды, КБ, число строк), коммит «Бой: <что>, дд.мм».
2. [ ] **Сверить** с пределами окна и соседними числами (PR-12): узлов ≈ листов, итог ≥ строки, доли — 100 %, время
       холодно ≤ 30 с с запасом (PL-02); со стендом — во сколько раз (ST-19).
3. [ ] **Записать** в CLAUDE.md «Бой: что известно» — факт, число с единицей, дата, источник; закрытое — убрать из «Что не
       проверено» в том же коммите (PR-05).
4. [ ] **Факт платформы** (версия sqlparse, текст обёртки, ключ кэша, классы форка, настройки ClickHouse) — в таблицу
       фактов 01-platform.md (PL-09) и 17-open-questions.md; тем же днём — grep по поставкам остальных проектов (PR-25).
5. [ ] **Откалибровать стенд:** кардинальности мира (ST-05), испорченная копия под патологию (ST-06), множитель бой /
       стенд (ST-19), режимы ClickHouse по `getSetting` (ST-03).
6. [ ] **Воспроизвести** симптом или патологию на стенде — только потом править (PR-09).
7. [ ] **Почистить:** сырой ответ — до схемы и главного; ПДн попали в репозиторий — удалить из истории и сказать
       владельцу (PR-06, AC-16).
8. [ ] **Спросить следующее** одной просьбой с бланком, если ответ открыл вопрос (PR-19).

| Прислано | Что значит | Что делать |
|---|---|---|
| лексер: `2` и `a -- b` | у Proteus sqlparse ≥ 0.4.3 — модель М2 | М1 — запасом; записать в 01-platform.md (F5) |
| лексер: синтаксическая ошибка | sqlparse 0.3.0 — модель М1 | обе модели остаются; записать |
| `cache_key` одинаковый у двух логинов на личном датасете | логин не в ключе: ответ одного уходит другому | срочная поставка безопасности (AC-12, DV-23) |
| `cache_key` разный на общем датасете | в тексте есть вызов логина или параметра адреса (или предикат автозаполнения) | убрать вызов (AC-09), проверить вкладку «Настройки» |
| `result[0].query` с `GROUP BY` по «Измерениям» | модель обёртки стенда верна | строки уникальны, порядок — в JS (SP-13) |
| `queries[0].url_params` пустой | параметры адреса до `react_sanbbox` не доходят | ссылку на вид — убрать или переделать (SP-23) |
| `cache_timeout` не 43 200 | у чарта или датасета задано своё время | вкладка «Настройки» (DV-21) |
| узлов дерева в разы больше листов | повтор юнита ниже по пути | правило DS-21, копия источника на стенде (ST-06) |
| «где время»: холодно ≫ 2 × стенд | кардинальность мира ниже боевой или нагрузка кластера | мир по разведке (ST-05); разложить по слагаемым (perf-triage) |
| сниппет: «замените 201 на N» | TOP высоты ряда у этого борда или раскладки другой (ряд над вкладками, вкладки верхнего уровня) | число — в блок 7 CSS (BC-18) |
| фото владельца: «по бокам шире», «снизу пусто», «на краях тень» | вкус владельца или тени цепочки ячейки и карточки | поля — числами владельца в одном месте (BC-12), тени — со всей цепочки и карточек одной поставкой (BC-25); числа — по сниппету, не по фото (DV-35) |
