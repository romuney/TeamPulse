# 09. Несколько чартов: кросс-фильтры, области, канал между чартами (MC)

**Зачем глава.** У кастомного чарта Proteus два способа повлиять на других: кросс-фильтр (`applyCrossFilter` → Proteus
перезапрашивает чарты своей области) и канал `postMessage` между iframe борда. Первый меняет данные, но медленный и
настраивается JSON-метаданными дашборда; второй мгновенный, но данных не меняет. Глава — о том, как эмитить маску, как понять,
что пришёл ответ именно на твой выбор, как задать области, как связать чарты каналом и как разделить работу между чартами,
чтобы борд не рассинхронизировался. Код чарта — 07-chart.md, песочница — 08-sandbox.md, носители в датасете и ключ кэша —
02-superset-path.md и 03-access-cache.md.

**Главное в 5 пунктах.**
1. **MC-02, MC-04.** Маска — по контракту: `operator: 'IN'`, значения строками и отсортированы, все носители чарта одним
   вызовом, `value: []` — никогда; серия кликов — один эмит.
2. **MC-06…MC-08.** Ожидание снимает только ответ, эхо которого равно подписи отправленного выбора. Пока ждёшь — секундомер
   текущего запроса; жёлтая плашка — не раньше 45 с; повтора по таймеру нет.
3. **MC-09, MC-10.** Области кросс-фильтров и самовлияние — только JSON-метаданными дашборда, `scope` и `chartsInScope`
   согласованно; проверка — по Network, какие чарты перезапросились.
4. **MC-12, MC-15.** Канал между чартами — `postMessage` по всем фреймам от `window.top`. Числа от собственного выбора чарта
   считает датасет соседа и передаёт каналом («один запрос — два чарта»): ASK, переспрос, ответ всегда, таймаут с причиной.
5. **MC-17, MC-21.** Тяжёлое и общее — отдельным чартом с общим кэшем и параллельным запросом; смена вида — в браузере без
   запроса.

Метки уверенности — как во всём гайде (01-platform.md). Опыты в браузере (Chromium 141) и стенды чартов подтверждают
поведение браузера и кода, но не фронтенда форка: такие правила помечены [вывод] с пометкой, на чём проверено.

## A. Сколько чартов

### MC-01. Решай число чартов по рабочему месту: один чарт с самовлиянием или несколько с каналом
- **Почему:** один чарт на одном датасете получает всё одним запросом на смену выбора — рассинхрона нет (HRBP, TeamPulse).
  Разделение даёт параллельные запросы и общий кэш тяжёлой части (DL: панель фильтров 7,0 с холодно в бою, список ≈0,3 с на
  стенде; владелец 30.09: «вынести в отдельный чарт») и разные роли (adoption: шапка-эмиттер, каталог, панель). Цена каждого
  лишнего чарта — канал, протокол, поставка JS пачкой, тур через несколько iframe.
- **Как:**

  | Признак | Решение | Пример |
  |---|---|---|
  | Отчёт — одно рабочее место с общим выбором, ответ ≤ 1–2 МБ | один чарт, вкладки, фильтры и деревья — внутри виджета, самовлияние через JSON | HRBP_HUB, TeamPulse |
  | Часть ответа тяжёлая и не зависит от пользователя или от фильтров | отдельный чарт с общим кэшем, запросы параллельно (MC-17) | DL: панель + список |
  | Настройка меняет и сам чарт, и соседей | отдельный чарт-эмиттер (MC-18) | adoption: шапка |
  | Чарту нужны числа от собственного выбора | секция в ответе соседа + канал (MC-15) | adoption: каталог ← панель |

  Нативные фильтры Proteus для таких бордов не используются: выбор, каскад и счётчики — в чартах (MC-19, MC-20).
- **Проверка:** перед проектированием запиши для каждого чарта: что он эмитит, кому, что зависит от пользователя, какой вес
  ответа и время ClickHouse на масштабе боя (01-platform.md, PL-03).
- **Уверенность:** [вывод] — по четырём проектам; [владелец 30.09] — разделение DL и «один запрос, два чарта» adoption.
- **Образец:** HRBP_HUB:docs/architecture.md (один чарт); detail_list:CLAUDE.md (пара на вкладку); adoption:Единый лист —
  актуальные файлы/0. Что куда и как проверить.md (три чарта).

## B. Эмит кросс-фильтра

### MC-02. Эмить маску по контракту: `operator: 'IN'`, значения строками, все носители одним вызовом, `value: []` — никогда
- **Почему:**
  - Борд 59922, 14.09: без `operator` data API отвечает 400 «Missing data for required field» — и падают ВСЕ чарты-получатели.
    По исходнику 2.0.1 поле `op` у `ChartDataFilterSchema` обязательно.
  - 59922: `value: []` ронял запрос получателя. По ванильному 2.0.1 пустой список даёт «Filter value list cannot be empty»,
    только если носитель — колонка датасета; падение для носителя вне SELECT ванильным кодом не объясняется (возможно, форк).
    Правило держим.
  - Маска заменяется целиком: редьюсер `dataMask` 2.0.1 делает `{...прежнее, ...новое}`, то есть `extraFormData` чарта —
    последняя маска. Второй вызов стирает фильтры первого.
  - Носитель в SELECT получает автоматический `WHERE col IN (…)` во внешнем запросе (SP-14, 02-superset-path.md).
- **Как:**
  - Вызов: `applyCrossFilter([{column, operator: 'IN', value: [строки]}])`.
  - Значения — `String(v)`, без `null`, `undefined` и пустых строк; пустой набор — колонку не шли вовсе.
  - Все носители чарта — одним вызовом. Полный сброс — `applyCrossFilter([])`.
  - В маске — те же пределы, что в датасете (AC-14, 03-access-cache.md): не проси того, что датасет отбросит (HRBP — юнитов
    ≤ 50; DL — ≤ 200 значений на атрибут).
  - Нет `applyCrossFilter` (чарт открыт вне дашборда) — плашка сразу, без ожидания.
  ```js
  function maskOf(o) {
    var out = [];
    function add(col, vals) {
      var v = [];
      for (var i = 0; i < (vals || []).length; i++)
        if (vals[i] !== null && vals[i] !== undefined && String(vals[i]) !== '') v.push(String(vals[i]));
      v.sort();                                               // MC-04
      if (v.length) out.push({ column: col + MODEL.cf, operator: 'IN', value: v });   // MC-05: суффикс
    }
    add('unit', (o.unit || []).slice(0, 50));
    add('emp', o.emp && o.emp !== CFG.emp[0].v ? [o.emp] : []);                      // MC-03: умолчание не шлём
    return out;
  }
  if (typeof applyCrossFilter !== 'function') { state.warn = CFG.text.noCf; render(); return; }
  applyCrossFilter(maskOf(next));
  ```
- **Проверка:** стенд со шпионом `applyCrossFilter` (`kit/sbx/run.cjs` печатает каждый эмит): у каждого элемента
  `operator === 'IN'`, `value` — непустой массив строк; носителей нет среди колонок SELECT (SP-14).
- **Уверенность:** [бой] (59922, 14.09) + [исходник 2.0.1] (схема фильтра, редьюсер маски).
- **Образец:** detail_list:proteus/detail-list-filters.chart.js (`maskOf`); HRBP_HUB:proteus/hrbp-hub.chart.js (`maskOf`, `emit`).

### MC-03. Не эмить умолчание и повтор той же маски
- **Почему:** ответ без фильтров у всех одинаков и лежит в кэше; маска с умолчанием — другой ключ кэша, а значит холодный
  запрос того же ответа. Повтор той же маски Proteus может не перезапросить — тогда чарт ждал бы эха вечно, а пользователь
  видел бы плашку ожидания.
- **Как:**
  - Состояние по умолчанию (юнит = корни зоны, опции по умолчанию) в маску не клади.
  - Подпись нового выбора равна эху текущего ответа — ожидание снять, запроса нет.
  - Эмиттер без кнопки «Применить» помнит последнюю отправленную маску (`state.lastEmit`) и не шлёт её повторно.
  ```js
  var sig = sigOf(next);
  if (sig === sigOf(reqEcho())) { state.pend = null; armPend(); render(); return; }   // уже показано
  ```
- **Проверка:** стенд: выбрать и снять значение — `applyCrossFilter` не вызван (или вызван `[]`), запроса нет; нажать
  «Применить» без изменений — запроса нет.
- **Уверенность:** [вывод] — по коду трёх проектов; поведение Proteus на повтор маски не проверено.
- **Образец:** HRBP_HUB:proteus/hrbp-hub.chart.js (`emit`, `reqNow`: юнит по умолчанию — пустой); adoption:Виджеты/pa-reports-body.chart.js
  (`emitSel`, `state.lastEmit`).

### MC-04. Сортируй значения маски, держи порядок носителей и отправляй серию кликов одним эмитом
- **Почему:**
  - adoption 29.09: каждый Shift-клик слал отдельный фильтр — гонка, справа оставался ответ под старый выбор.
  - Ключ кэша 2.0.1 содержит фильтры вместе с порядком значений (SP-21, 02-superset-path.md): тот же выбор в другом порядке
    кликов — другой ключ и холодный запрос. HRBP значения не сортирует (сортирует только подпись для сравнения).
- **Как:**
  - Значения в `value` сортируй, порядок носителей в маске держи постоянным.
  - Эмит прямым кликом (без «Применить») — с дебаунсом 300 мс после ПОСЛЕДНЕГО клика (`CFG.selDelay`). Соседям ключ выбора
    уходит каналом сразу (MC-13), чтобы они приглушились до ответа.
  - С кнопкой «Применить» дебаунс не нужен: набранное копится в `state.stage` и уходит одним эмитом.
  ```js
  function emitSel() {
    var fl = areaMask(), key = JSON.stringify(fl);
    if (state.lastEmit === key) return;                         // MC-03
    state.lastEmit = key;
    paOut('cat', sheetOf(), CFG.paCols, fl);                    // соседи узнают сразу (MC-13)
    state.pendMask = fl;
    clearTimeout(state.emitT);
    state.emitT = setTimeout(function () { applyCrossFilter(state.pendMask); }, CFG.selDelay);   // 300 мс
  }
  ```
- **Проверка:** стенд: пять Shift-кликов за 1 с — один вызов `applyCrossFilter` с полным выбором; два порядка кликов дают
  одинаковую маску (сравнение JSON). В бою — `cache_key` в ответе `chart/data` одинаков при двух порядках кликов.
- **Уверенность:** [бой] (adoption 29.09) + [исходник 2.0.1] (состав ключа); [не проверено в бою] — прирост попаданий в кэш.
- **Образец:** adoption:Виджеты/pa-reports-body.chart.js (`emitSel`, `paVals` — сортировка). Нарушение — HRBP_HUB (`maskOf`
  без сортировки).

### MC-05. Называй носитель основой с суффиксом чарта или вкладки
- **Почему:** DL 29.09: четыре чарта на двух вкладках одного дашборда с одинаковыми фильтрами. С общим именем носителя при
  слишком широкой области фильтр одной вкладки попадёт в датасет другой и поменяет его ответ. С суффиксом — в худшем случае
  лишний перезапрос, данные не испорчены.
- **Как:**
  - Имя носителя — основа + суффикс вкладки или чарта (`flt_f` / `flt_kf`); суффикс датасет отдаёт эхом в `meta.cf`, чарт берёт
    его оттуда, а не из своего кода.
  - Тот же суффикс — у параметра ссылки на вид (`dl_f` / `dl_kf`, SB-18, 08-sandbox.md) и в сообщениях канала (`cf`):
    получатель отбрасывает чужой суффикс (MC-12).
  - Датасет читает `filter_values('flt' ~ CF)`; носителей нет в SELECT (SP-14).
- **Проверка:** регресс датасета: носитель чужой вкладки не меняет ответ («чужая вкладка» в `check.py` DL).
- **Уверенность:** [вывод] — стенд DL.
- **Образец:** detail_list:proteus/detail-list.data.sql (`CF`, эхо `cf` в meta); detail_list:proteus/detail-list-filters.chart.js
  (`maskOf`: `base + cf`).

## C. Сверка и ожидание

### MC-06. Снимай ожидание только ответом, эхо которого равно подписи отправленного выбора
- **Почему:** без сверки чарт не отличает ответ на свой фильтр от перерисовки или от запоздавшего ответа на прошлый выбор и
  молча показывает старые данные (adoption 29.09: быстрые клики оставляли старый выбор). Уникальная метка на каждый клик (DL:
  `rq` / `frq` = `'q' + n + '.' + время` носителем в маске) тоже даёт точную сверку, но фильтры входят в ключ кэша 2.0.1 —
  каждое «Применить» становится новым ключом, и повтор того же выбора не берётся из кэша.
- **Как:**
  - Датасет возвращает в `meta` эхо реально применённого — после своих проверок, а не то, что прислали (DS-03,
    05-dataset.md).
  - Подпись — канонически и одинаково в SQL и JS: колонки по алфавиту, значения отсортированы, `"`, `\` и переводы строк
    выкинуты одним правилом.
  - Чарт держит `state.pend = {sig, at}` и снимает ожидание только ответом с эхом, равным `sig`. Эхо прежнего выбора не
    принимается. Ответ без эха (пустой) не сверяется.
  - Уникальная метка — только для принудительного перезапроса (MC-08).
  ```js
  function sigOf(o) {                          // каноническая подпись выбора
    var s = 'u:' + (o.unit || []).slice().sort().join(',');
    for (var i = 0; i < CFG.cuts.length; i++)
      s += '|' + CFG.cuts[i].key + ':' + ((o.cuts && o.cuts[CFG.cuts[i].key]) || []).slice().sort().join('\u0001');
    return s;
  }
  // в mount(): пришёл ответ
  var echo = sigOf(reqEcho());                 // эхо из meta этого ответа
  if (state.pend && state.pend.sig === echo) state.pend = null;
  ```
- **Проверка:** стенд гонки кросс-фильтров (13-stand.md): задержка, потеря, обратный порядок ответов — чарт не принимает
  ответ с чужим эхом и не зацикливается.
- **Уверенность:** [бой] (adoption 29.09) + [исходник 2.0.1] (метка в маске = новый ключ); [не проверено в бою] — потеря
  попаданий в кэш у DL не мерили.
- **Образец:** HRBP_HUB:proteus/hrbp-hub.chart.js (`sigOf`, `reqEcho`, `emit`, сверка в конце `mount`);
  adoption:Виджеты/pa-reports-body.chart.js (`paKey`, `paVals`). DL сверяет уникальными `rq`/`frq` — перевести на эхо выбора;
  `frq` там же ключ канала `DL_FLT` / `DL_ECHO`, поэтому менять в списке и панели одной поставкой (MC-16).

### MC-07. Пока ждёшь, считай секунды текущего запроса; жёлтую плашку показывай не раньше 45 с
- **Почему:**
  - HRBP 07.10: порог 9 с давал ложную плашку «самовлияние не настроено?» при верном JSON — она висела ≈5 с, а ответ на всю
    компанию в бою дольше стенда.
  - ClickHouse рвёт запрос на 30 с, к нему добавляются разбор Superset (HRBP до правки, 34 КБ SQL: «Применить» в бою — 20 с;
    на стенде в модели sqlparse 0.4.4 — ≈10 с `reindent` и ≈2 с на каждый разбор ради ключа, SP-15), отправка кода чарта
    (2,6–5,8 с, F11) и приём ответа (6–7 с у панели DL); порог 30 с у DL — впритык. Фронтенд 2.0.1 ждёт ответ до
    `SUPERSET_WEBSERVER_TIMEOUT` 60 с — 45 с лежит внутри 30…60.
  - Владелец 08.10: «зачем в обновлении данных писать про предыдущий запрос».
- **Как:**
  - После эмита отчёт приглушён, строка «Обновляю данные… N с» считает секунды ТЕКУЩЕГО запроса (с 2 с); время прошлого
    ответа не показывать.
  - Секундомер — `setInterval` раз в 1 с, правит только текст `[data-pendt]`, без `render()`; интервал снимается при
    перезапуске (CJ-06, 07-chart.md).
  - В многочартовой гонке плашку «Пересчитываем…» показывай, только если ждёшь дольше 0,4 с (без мигания).
  - Жёлтая плашка — не раньше `CFG.pendingWarnMs = 45000`, с причиной и пунктом инструкции: «Ответа на фильтр нет уже 45 с.
    Если так при каждом «Применить» — проверьте области кросс-фильтров в JSON-метаданных (п. N). Если отчёт просто долго
    считает — ответ ещё придёт, плашка уйдёт сама».
  - Первый ответ с нужным эхом снимает и ожидание, и жёлтую плашку.
  ```js
  function armPend() {
    if (state.pendT) clearTimeout(state.pendT);
    state.pendT = null;
    if (!state.pend) return;
    var left = Math.max(200, CFG.pendingWarnMs - (Date.now() - state.pend.at));
    state.pendT = setTimeout(function () {
      state.pendT = null;
      if (!state.pend) return;
      state.pend = null; state.warn = CFG.text.notApplied;
      if (state.rerender) state.rerender();
    }, left);
  }
  if (state.pendTick) clearInterval(state.pendTick);
  state.pendTick = setInterval(function () {
    if (!state.pend || !overlay.parentNode) return;
    var pt = overlay.querySelector('[data-pendt]');
    if (pt) pt.textContent = pendText();                       // «N с» начиная со 2-й секунды
  }, 1000);
  ```
- **Проверка:** стенд `?delay=20000`: 20 с идёт секундомер, жёлтой плашки нет; с испорченными областями (чарт вне своей
  области) — плашка ровно на 45-й секунде.
- **Уверенность:** [бой] (HRBP 07.10; владелец 08.10).
- **Образец:** HRBP_HUB:proteus/hrbp-hub.chart.js (`CFG.pendingWarnMs`, `armPend`, `pendText`, `state.pendTick`,
  `CFG.text.notApplied`). DL держит 30 с (`detail-list.chart.js`, `CFG.pendingWarnMs`) — поднять до 45 с.

### MC-08. Не повторяй фильтр по таймеру: автоповтор — только по ответу под прежний выбор
- **Почему:** adoption 29.09: автоповтор через 6 с обрывал долгие запросы, и пользователь ждал дважды. Владелец: «один клик →
  1 из 2, стало дольше». Таймерный повтор откатили.
- **Как:**
  - Долгий ответ — не ошибка: ждать (MC-07).
  - Автоповтор допустим, только если пришёл ответ под ПРЕЖНИЙ выбор, а правильный не пришёл за 10 с (`selStaleWait`), и не
    больше 2 раз (`selMaxTries`).
  - Повтор — та же маска плюс фиктивная колонка, которой нет ни в одном датасете: внешний запрос фильтр по ней пропускает, а
    ключ кэша меняется — Proteus перезапрашивает без побочек (SP-14, SP-21).
  - Ответа нет совсем 60 с (`selGiveUp`) — кнопка «Повторить запрос», сами не повторяем.
  - С кнопкой «Применить» автоповтора нет вовсе: только плашка (MC-07).
  ```js
  // источник отвечает на просьбу получателя «повтори» (PA_RESEND)
  if (state.onResend) window.removeEventListener('message', state.onResend);       // CJ-06
  state.onResend = function (e) {
    var d = e.data || {}, sh = sheetFn();
    if (d.type !== 'PA_RESEND' || d.src !== src || d.sheet !== sh || typeof applyCrossFilter !== 'function') return;
    var fl = maskFn();
    paOut(src, sh, cols, fl);
  ```

### MC-09. Задавай области кросс-фильтров и самовлияние только JSON-метаданными дашборда
- **Почему:**
  - HRBP 28.09: на новом борде «Фильтр не применился» — кросс-фильтры выключены, а чарт стоит в `excluded` своего фильтра.

  - DL 06.10: области из интерфейса — у списков `"rootPath": []`, `"chartsInScope": []`, чарт не может выбрать сам себя;
    «Загрузить всех», «Загружать» и сортировка через 30 с давали жёлтую плашку, а панели попали в свою же область.
  - adoption 25.09: выбор каталогов двух листов синхронизировали эхо-колонкой — отчёт фильтровался дважды; откат, листы
    независимы, их области не пересекаются.
  - Ключи `cross_filters_enabled` и `chartsInScope` появились в Superset 2.1.0; схема 2.0.1 отвечает на JSON владельца
    «Unknown field» для `cross_filters_enabled` и `is_css_scoped` (последнего нет ни в одной версии Superset — ключ форка).
    Форк такой JSON сохраняет: фронтенд дашборда у него с бэкпортами 2.1+ (F3, 01-platform.md).
- **Как:**
  ```json
  {
    "cross_filters_enabled": true,
    "chart_configuration": {
      "111": { "id": 111, "crossFilters": { "scope": { "rootPath": ["TAB-…"], "excluded": [222] }, "chartsInScope": [111] } },
      "222": { "id": 222, "crossFilters": { "scope": { "rootPath": ["TAB-…"], "excluded": [222] }, "chartsInScope": [111] } }
    }
  }
  ```
  Здесь 111 — список (фильтрует сам себя: сортировка, лимит), 222 — панель (фильтрует только список, себя — нет).

  | Чарт | `excluded` | `chartsInScope` |
  |---|---|---|
  | фильтрует себя (самовлияние) | себя нет | `[свой id, …]` |
  | фильтрует только соседа | свой id | `[id соседа]` |
  | `rootPath` | id вкладки `TAB-…` или `ROOT_ID` (весь борд) | — |

  - `cross_filters_enabled: true` — явно. Запись — для КАЖДОГО чарта борда: новые чарты Proteus по умолчанию включает «во
    все» области.
  - Ключ `chart_configuration` — строка id, значения `id`, `excluded`, `chartsInScope` — числа без кавычек: сравнение строгое.
  - Области разных вкладок и листов не пересекаются (`rootPath` = вкладка); выбор одного листа в другой не переносится.
  - В поставке — готовое: выгрузка JSON владельца целиком с исправленными областями (или блок `chart_configuration` с его id
    чартов и вкладок), вариант с `ROOT_ID` и таблица «источник → получатели» в инструкции. Id подставляет сборщик из таблицы
    id борда (14-delivery.md). Целый JSON затирает правки владельца после выгрузки — сверяй дату выгрузки.
  - Порядок у владельца: вставить JSON → сохранить свойства → «Сохранить» дашборд → опубликовать черновик → обновить страницу →
    снова открыть JSON и сверить. Настройку кросс-фильтров этих чартов в интерфейсе больше не открывать: она перезапишет
    области.
- **Проверка:** MC-10 (Network). На стенде области из JSON поставки превращают маски в фильтры получателей (SB-20).
- **Уверенность:** [бой] (28.09, 18.09, 25.09, 06.10) + [исходник 2.0.1] (схема JSON 2.0.1 и 2.1.0).
- **Образец:** detail_list:Поставка — Детальные списки/JSON (четыре чарта на двух вкладках); HRBP_HUB:Поставка — HRBP HUB v2/json
  (один чарт, самовлияние на `ROOT_ID`).

### MC-12. Связывай чарты `postMessage` по всем фреймам от `window.top` и фильтруй сообщения по типу, вкладке и версии
- **Почему:** чарты — в разных iframe без общего origin; других API взаимодействия, кроме кросс-фильтра, у них нет. Опыт
  Chromium 141: из песочницы `window.top.frames` доступен, `postMessage` соседям работает. В бою канал работает: сверка
  фильтров adoption (29.09), «один запрос — два чарта» (30.09), тур через три чарта (07.10).
- **Как:**
  - Рассылка — обходом от `window.top.frames` рекурсивно, глубина ≤ 5; свой `window` пропускать; каждый `postMessage` и
    вложенный обход — в `try` (чужие фреймы, стенд без родителя).
  - Сообщение — `{type, v, cf | sheet, src, …}`. Получатель отбрасывает чужой тип, чужую вкладку или суффикс: канал видят
    iframe ВСЕХ вкладок борда.
  - Слушатель `message` — по ссылке в `state`, со снятием на перезапуске (CJ-06); первым делом — `overlay.parentNode`.
  - Чарт на скрытой вкладке (iframe 0 × 0) не ждёт ответов и не просит повторов: Proteus может его не перезапрашивать.
  ```js
  function bcast(msg) {
    try {
      (function walk(w, d) {
        if (d > 5) return;
        for (var i = 0; i < w.frames.length; i++) {
          var f = w.frames[i];
          if (f !== window) { try { f.postMessage(msg, '*'); } catch (e) { /* чужой фрейм */ } }
          try { walk(f, d + 1); } catch (e2) { /* нет доступа к вложенным */ }
        }
      })(window.top, 0);
    } catch (e) { /* нет window.top — стенд без родителя */ }
  }
  ```
  Типы сообщений проектов:

  | Тип | Откуда → куда | Поля | Зачем |
  |---|---|---|---|
  | `DL_FLT` | панель → список | `cf`, `frq` | «Применить» ушло: список показывает «Обновляю…» (MC-13) |
  | `DL_ECHO` | список → панель | `cf`, `frq`, `f` | применённое из ответа списка (MC-14) |
  | `DL_ASK` | панель → список | `cf` | «пришли эхо» при монтаже панели (MC-14) |
  | `PA_SEL` | источник → получатели | `src`, `sheet`, `cols`, `key` | новый ключ выбора до ответа Proteus (MC-13) |
  | `PA_RESEND` | получатель → источник | `src`, `sheet` | переотправь фильтр с меткой (MC-08) |
  | `PA_AUD_ASK` / `PA_AUD` | каталог ↔ панель | `v`, `noflt`, `key`, `rows` | секция «один запрос — два чарта» (MC-15) |
  | `*_TOUR`, `*_TOUR_AT`, `*_TOUR_KEY`, `*_TOUR_GO` | ведущий ↔ соседи | `op`, `key`, `pad` / `l t r b` / `k` | тур через несколько чартов (12-tour.md) |
- **Проверка:** стенд с четырьмя чартами на двух вкладках: сообщения вкладки A не меняют чарты вкладки B; после трёх
  перезапусков одно сообщение обрабатывается один раз.
- **Уверенность:** [бой] (adoption 29.09, 30.09, 07.10) + [вывод] опыт Chromium 141; скрытая вкладка — [вывод].
- **Образец:** detail_list:proteus/detail-list.chart.js (`bcast`, `echoMsg`, `state.onFlt`); adoption:Виджеты/pa-reports-body.chart.js
  (`paBcast`).

### MC-14. Восстанавливай применённое из эха ответа и раздавай его по запросу ASK
- **Почему:** после перезагрузки борда Proteus может вернуть кросс-фильтры, а iframe — пересоздать: `window.__pvtState`
  пропадает, правда — только в эхе ответа. Панель DL не фильтрует сама себя (её ответ от фильтров не зависит) и знает

  самодостаточен.
- **Как:**
  - Список рассылает `DL_ECHO {cf, frq, f}` на каждом ответе и отвечает на `DL_ASK`; панель при монтаже шлёт `DL_ASK`.

  - Применённое панель держит в `state.applied`; набранное, совпавшее с применённым, сбрасывается.
  - При монтаже без активного тура чарт рассылает соседям «тур выключен», чтобы сосед не остался затемнённым (12-tour.md).

  ```js
    if (state.stage && !stageDiff()) state.stage = null;

  ```
- **Проверка:** стенд: перезагрузить борд с применёнными фильтрами — панель показывает применённое из эха; панель смонтирована

### MC-15. Считай числа от собственного выбора чарта соседним датасетом и передавай каналом — «один запрос, два чарта»
- **Почему:** решение владельца adoption 30.09 — обязательный приём: чарт A не фильтрует сам себя, а ему нужны числа от его же

  матрица «объект × группа» в браузер — 832 тыс. ячеек ≈ 20 МБ. Секция в ответе соседа B, который и так перезапрашивается на

    старый JS», «нет секции — старый SQL», «ключ другого выбора» (оба ключа — в подсказке);

  просмотры, постоянные). Стенд: B ответил до того, как A начал слушать, — A получает числа по ASK; старый SQL B — пометка

- **Уверенность:** [владелец 30.09] + [бой] (тестовый борд 61364, 30.09).

### MC-16. Меняй протокол канала во всех участниках одной поставкой и ставь версию в сообщение
- **Почему:** adoption 07.10, тур через три чарта: «нужны все три JS (4, 6, 8) одной заменой: без каталога кнопка ничего не
  запустит». 30.09 каталог не отличал «панель со старым JS» от «нет эха» — пустота вместо причины. Владелец ставит файлы не

- **Как:**

- **Уверенность:** [бой] (adoption 30.09, 07.10).

## F. Разделение работы между чартами

### MC-17. Разводи тяжёлую панель и лёгкий список по двум чартам с параллельными запросами
- **Почему:** владелец 30.09 (DL): «вынести в отдельный чарт»; «зачем фильтр ожидает, что сам на себя применяется». Стенд:
  список ≈0,3 с, панель 1,5–3,5 с; бой: панель УС — 7,0 с холодно и 3,3 с тепло, ответ 9,7 МБ. 08.10: «таблица быстро, фильтры
  долго или не грузятся, второй раз — быстро» — пока в ключе кэша панели был логин, холодное открытие платил каждый коллега
  (разбор Superset без логина в ключе 2,1–2,25 с против ≈4,2 с).
- **Как:**
  - Два чарта на одной вкладке, запросы идут параллельно, список не ждёт панель.
  - Панель эмитит фильтры только списку. Её ответ от фильтров не зависит — она вне своей области (свой id в `excluded`) и после
    «Применить» не перезапрашивается.
  - Применённое панель берёт из эха списка (MC-14).
  - Датасет панели — без логина и без проверки доступа в ключе: общий кэш на всех (AC-06, AC-09, 03-access-cache.md; решение
    владельца 08.10). Список — с логином в ключе.
- **Проверка:** DevTools → Network: «Применить» — один POST `chart/data` (список); `cache_key` ответа панели одинаков у двух
  пользователей.
- **Уверенность:** [владелец 30.09, 08.10] + [бой] (замеры SQL Lab 08.10).
- **Образец:** detail_list (пара чартов на вкладку: proteus/detail-list.chart.js и proteus/detail-list-filters.chart.js; JSON
  областей в папке поставки).

### MC-18. Выноси настройку «для себя и соседей» в отдельный чарт-эмиттер с общим кэшем
- **Почему:** adoption 25.09: настройка ЦА плашкой внутри панели требовала самовлияния — в бою ЦА к самой панели не
  применялась. 30.09: ответ шапки 7,9 МБ — составы AD-групп (1,79 млн строк) ради мгновенных счётчиков; решение владельца —
  группы только именами, счёт после «Применить»: стенд 12,8 → 0,38 МБ, бой ≈7,9 → ≈0,3 МБ.
- **Как:**
  - Настройку, которая меняет и сам чарт, и соседей (целевая аудитория, период, опции), выноси в отдельный чарт-эмиттер —
    шапку.
  - Датасет эмиттера фильтров не читает и кэшируется общим (без логина).
  - Получатели — обычные приёмники кросс-фильтра, самовлияние им не нужно.
  - Справочники боевой кардинальности ради живых счётчиков в эмиттер не вози: считай после «Применить» (DS-14, 05-dataset.md).
- **Проверка:** вес ответа эмиттера на боевой кардинальности ≤ 0,5 МБ (DS-16); клик в эмиттере перезапрашивает получателей, но
  не сам эмиттер.
- **Уверенность:** [бой] (25.09, 30.09).
- **Образец:** adoption:Виджеты/pa-head.chart.js и adoption:Виджеты/pa-head.data.sql; adoption:Виджеты/pa-ca-bar.NOTES.md
  (история решения).

### MC-19. Вези всё для взаимодействия одним ответом и не догружай части через кросс-фильтр
- **Почему:** владелец 30.09 (DL): «хочу, чтобы фильтры и значения были прогружены сразу»; 06.10 (HRBP): справочник всей зоны
  в каждом ответе, выбор и поиск — без запроса. Область — у чарта целиком: запрос «дай значения атрибута» через кросс-фильтр
  перезапросит и соседей.
- **Как:** значения фильтров, деревья, куб и справочник зоны приезжают одним ответом при открытии; каскад «фильтр на фильтр» —
  в браузере (MC-20). Предел — вес на боевой кардинальности: то, что взрывается (составы AD-групп), не вози, а считай после
  «Применить» (DS-11, DS-14, DS-16, 05-dataset.md).
- **Проверка:** стенд со счётчиком запросов: открыть выпадашку, искать, раскрывать дерево — 0 запросов.
- **Уверенность:** [владелец 30.09, 06.10]. Замеры: панель DL в бою — 9,7 МБ JSON (≈3 МБ на проводе), 7,0 / 3,3 с; HRBP
  супер-HRBP — 0,76 МБ; шапка adoption — 7,9 → 0,3 МБ после отказа от составов групп.
- **Образец:** detail_list:proteus/detail-list.data.sql (вид `filters`: роли `D`, `C`, `T`); HRBP_HUB:proteus/hrbp-hub.data.sql
  (справочник зоны `dict`).

### MC-20. Считай каскад «при остальных фильтрах» в браузере той же семантикой, что SQL, и сверяй
- **Почему:** владелец 30.09 (DL): «выбрав одно значение, ещё до применения уже отфильтровались релевантные категории»; 07.10
  (HRBP): «цифры должны пересчитываться сразу, а не после Применить». Каскад нативных фильтров перезапрашивал значения на
  каждое изменение. Если чарт считает иначе, чем условие датасета, прогноз «Будет N» расходится с итогом списка.
- **Как:** формат куба — DS-12 (05-dataset.md). Алгоритм в чарте:
  - один проход на запись: `fail` (`Uint8Array` — сколько фильтров не пройдено, считать до 2) и `fidx` (какой, если один);
  - счётчик значения X фильтра F — записи с `fail = 0` или с `fail = 1` и `fidx = F`, у которых значение X;
  - прогноз «Будет N» — число записей с `fail = 0`;
  - семантика — ровно `cond()` датасета: атрибут — значение из выбранных; дерево — лист внутри выбранного узла (несколько
    листов у записи — хоть один, в узле запись считается один раз); численность и типы — битом;
  - проход кэшируется по подписи набранного выбора, счётчики ключа — до следующей правки.
  ```js
  function cubePass() {
    var o = staged(), sig = cubeSig(o);
    if (CUBE.sig === sig && CUBE.pass) return CUBE.pass;
    var N = MODEL.N, fl = activeFilters(o), fail = new Uint8Array(N), fidx = new Uint8Array(N), total = 0;
    for (var e = 0; e < N; e++) {
      var nf = 0, last = 0;
      for (var i = 0; i < fl.length && nf < 2; i++) if (!passOne(fl[i], e)) { nf++; last = i; }
      fail[e] = nf; fidx[e] = last;
      if (!nf) total++;
    }
    var at = {};
    for (var j = 0; j < fl.length; j++) at[fl[j].key] = j;
    CUBE = { sig: sig, pass: { fail: fail, fidx: fidx, total: total, at: at }, counts: {} };
    return CUBE.pass;
  }
  // счётчики фильтра key: учитываем запись x, если
  // fail[x] === 0 || (fail[x] === 1 && fidx[x] === pass.at[key])
  ```
- **Проверка:** три сверки — с независимым SQL на стенде (тот же расчёт, что в JS, против ответа датасета); «итог списка =
  прогноз панели» после «Применить» в живом прогоне; у HRBP — `fdCalc` против фасетов ответа число в число.
- **Уверенность:** [владелец 30.09, 07.10] + [вывод] — стенды DL и HRBP. Замер стенда: 99 тыс. записей × 30 атрибутов —
  десятки мс на правку, разбор куба ≈0,5 с.
- **Образец:** detail_list:proteus/detail-list-filters.chart.js (`activeFilters`, `passOne`, `cubePass`, `cubeCounts`);
  detail_list:stand/ch.py (`cube_count`); HRBP_HUB:proteus/hrbp-hub.chart.js (`fdCalc`) и HRBP_HUB:stand/check.py.

### MC-21. Меняй вид без запроса
- **Почему:** DL 06.10: колонки списка «по запросу» у владельца не выбирались — список не получал собственный кросс-фильтр
  (области из интерфейса), через 30 с — жёлтая плашка. Вид — не данные: каждый запрос ради вида — секунды ожидания и лишний
  ключ кэша. Цена «всех колонок в ответе»: УС 5 000 × 97 колонок — 0,58 с ClickHouse и 13,1 МБ JSON; после колонкового
  формата со словарём — 3,7 МБ JSON, ≈0,7 МБ на проводе (DS-18).
- **Как:** всё, что меняет только вид, держи в чарте и делай без запроса: выбор и порядок колонок, пресеты, ширины,
  сортировку загруженного, группировку, сводную, показ метрик, вид «таблица | сводная». Для этого все нужные поля приезжают в
  каждом ответе. Набранный показ (HRBP `state.stageV`) применяется той же кнопкой «Применить», но без запроса.
- **Проверка:** стенд со счётчиком запросов: переключить колонки, пресет, группировку, сводную — 0 запросов.
- **Уверенность:** [бой] (DL 06.10).
- **Образец:** detail_list:proteus/detail-list.chart.js (`colRows`, `CFG.defaultPreset`, `pvCompute`, `viewRows`);

### MC-22. Держи общие куски чартов борда дословно одинаковыми
- **Почему:** ДС Adoption §16.6–16.7: CSS «ТАБЛИЦЫ», «ВЫБРАННЫЕ ФИЛЬТРЫ» и функция строки фильтров одинаковы во всех чартах
  листа — иначе один и тот же элемент на одном борде выглядит и ведёт себя по-разному. Функции канала (`bcast`, `paKey`,
  `paVals`) обязаны совпадать у отправителя и получателя: подпись выбора по разным правилам не совпадёт никогда (MC-06).
- **Как:**
  - Лучше всего — один исходник на пару чартов и сборка вариантов (DL: один файл на список УС и КП, отличие — строка `ns`).
  - Иначе — копировать дословно и править во всех файлах сразу.
  - Регресс извлекает тексты общих функций из всех чартов борда и сравнивает их (предложение: ни в одном проекте автоматической
    сверки нет).
- **Проверка:** скрипт сравнения: тела `bcast`, `paKey`, `paVals` и общих блоков CSS во всех чартах борда совпадают байт в байт.
- **Уверенность:** [вывод] — ДС Adoption §16.6–16.7 и практика проектов.
- **Образец:** detail_list:stand/pack.py (`CHARTS`: один исходник — два чарта по строке `ns`); adoption:DESIGN_SYSTEM.md (§16.6–16.7).

|---|---|---|

| Запрос получателя падает после снятия выбора | эмит `value: []` | MC-02 |
