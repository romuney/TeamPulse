# 02. ClickHouse SQL и Jinja-датасеты Proteus

Как писать и ускорять виртуальный Jinja-датасет борда Proteus. Платформа: форк Superset 2.1.0 (путь SQL как у 2.0.1),
ClickHouse 24.8, витрины Greenplum через Helicopter (`gp_to_click`). Коды правил ссылаются на гайд `../proteus-playbook/`
(§11). Пометка **«актуально 09–14.10»** значит, что свежие поставки уточняют гайд; действуй по ней. Jinja-датасет пиши
руками и проверяй на стенде, через MCP его не снимай (PR-18; SQL.md скилла здесь устарел).

## 1. Профиль боя

| Что | Значение |
|---|---|
| ClickHouse | 24.8.15.1, новый анализатор, `prefer_column_name_to_alias = 1`, `join_use_nulls = 0`, `group_by_use_nulls = 0` (SQL Lab 08–09.10) |
| Пределы | `max_execution_time` 30 с, `max_threads` 12, память 10 ГиБ, `max_query_size` 262 144 Б **после reindent**, `max_ast_elements` 50 000 |
| Кэши | кэш результатов CH выключен (не включай: `today()` → Code 704, CH-30); кэш Superset — Redis, 12 ч |
| Обёртка чарта | `SELECT <Измерения> FROM (<датасет>) AS virtual_table GROUP BY <все Измерения> LIMIT 50000` (бой 09.10) |
| Лимит строк чарта | по умолчанию 10 000, ставь 50 000; лишнее режется молча |
| Сеть владельца | отправка ≈ 50 КБ/с, приём ≈ 0,5 МБ/с; кириллица в JSON — `\uXXXX`, 6 байт на букву |

- **Стенд — только chdb 2.1.1 (= CH 24.8.4.1).** chdb 4.x (CH 26.x) молча сводит типы к Variant там, где бой даёт
  Code 386 (CH-01). Время мерь в профиле боя (CH-02); ответ сверяй матрицей режимов: анализаторы × `prefer` ×
  `*_use_nulls` (CH-03, `superset201.py --matrix`).
- **Тяжёлое (окна, сетка, маски, канон логинов) считай раз в сутки в GP** (GP-14). Из `gp_to_click` всё Nullable,
  массив — только при `array_type_cast=True` (GP-20, CH-16).

## 2. Путь текста через Superset

**Открытие чарта:** Jinja (песочница, `DebugUndefined`) → `strip('\t\r\n; ')` → `format(strip_comments)` sqlparse
с патчем лексера → `split` (больше одной инструкции — отказ) → обёртка с GROUP BY → `format(reindent)` → ClickHouse.

**Save и «Синхронизировать столбцы»:** проверка форка («Некорректный SQL запрос: →…←») → Jinja с `AlwaysTrueObject` и
логином сохраняющего → `<текст>\nLIMIT 1000` без обёртки и с комментариями.

chdb выполнит любой из этих текстов, поломки видит только модель пути `kit/superset201.py` (SP-01). Гоняй её в двух
venv: М1 — sqlparse 0.4.3 + патч 2.1.0 (бой), М2 — 0.4.4 (запас); в бюджет пиши большее (SP-02).

### 2.1 Литералы и лексер
- **Экранируй кавычку удвоением `''`, никогда не `\'`.** Слэш экранируй раньше кавычки; слэши в конце значения — через
  `repeat(char(92), N)`. С `\'` строки и код меняются местами, `--` вырезается из строки, `;` режет запрос, а в
  модели 0.4.4 ответ меняется молча (SP-06, SP-08).
- **Литерал `[…]` пиши, только если внутри нет «]», иначе — `array(…)`.** sqlparse читает `[` как имя до первой «]»
  (SP-07). Макрос `qa` выбирает форму сам (§7.2).
- **Актуально 09–14.10 (Adoption).** Регулярки в коде пиши без классов `[…]`: `'^(?:\\s|\\p{P})*$'`. `'[[:cntrl:]]'`
  безопасен только вне литерала `[…]`.
- **Не пиши `\x..`** (разделители — `char(9)`, `char(10)`, `char(31)`, SP-09) и без нужды — `--`, `//`, `/*`, `;` в
  литералах (адрес — `concat('https:', char(47), char(47), …)`, SP-10).
- **Минусы `{#- -#}` не ставь на стыке токенов SQL** — получится `1AND` (SP-19).

### 2.2 Шаблон, который сохраняется
- **`filter_values` читай только циклом или через `|first|default(…, true)` с белым списком.** При Save там
  `AlwaysTrueObject`: `+`, `|length` и `[0]` падают; ветка по умолчанию исполняется и должна быть лёгкой (SP-05).
- **Не пиши SETTINGS, FORMAT, `AS MATERIALIZED` и `;` в середине.** На SETTINGS Save даёт «Fatal error» или Code 62.
  Настройки задаёт профиль кластера (CH-04).
- **Алиас в GROUP BY не пиши** (`GROUP BY intDiv(rn - 1, 500) AS ch`): Save откажет. Ключ делай колонкой подзапроса
  (SP-04).
- **Кортежный тип в строке CAST не пиши** (`'Array(Tuple(…))'`). Вместо него —
  `arrayFilter(t -> t.2 != '', [(toUInt8(0), '')])`; `CAST([], 'Array(String)')` проходит (CH-17).
- **Колонки выхода — не Array и не Tuple:** в бою массив пришёл строкой `['a', 'b']` (DS-02).
- **Сменились колонки — Save → «Синхронизировать столбцы» → «Измерения»**, иначе 500 CANNOT_INSERT_NULL (PL-07).

### 2.3 Бюджет текста
Разбор в Superset стоит ≈ токены² × вложенность. Если логин в ключе, разбор идёт на каждом расчёте ключа: у HRBP 34 КБ и
1 200 скобок дали «Применить» за 20 с при 2 с работы ClickHouse (SP-15, SP-22).

| Предел (худший набор носителей) | Значение |
|---|---|
| Текст после обёртки и reindent, байты UTF-8 | < 256 КиБ, запас 10 % (SP-16) |
| Токены / глубина скобок | < 10 000 / < 100 — запас на sqlparse ≥ 0.5.4 (SP-17) |
| reindent / разбор ради ключа у личного датасета | ≤ 1 с / ≤ 0,5 с (SP-15, SP-22) |

- **Список задавай один раз константой WITH:** `['a', 'b'] AS dl_x`, затем `x IN dl_x`. После reindent `[…]` растёт ×1,0,
  кортеж ×1,7, IN-список ×2,2. Список в каждом условии давал 1,8 МБ. `array(…)` на десятки тысяч значений — Code 168
  (SP-16, CH-28).
- **Выражение по N колонкам не повторяй.** Отдавай компоненты плоским массивом и режь его один раз наверху (DS-23).
  Чистку строки делай одной лямбдой по массиву полей.
- **Отступы снимай фильтром `{% filter replace %}`, пояснения пиши в `{# #}`, а не в `--`** (SP-18).
- **Длинный литерал (эхо, JSON) не ставь перед скобками с переносами** — reindent сдвинет хвост на его длину (842 КиБ).
  Длину значений носителей ограничивай: 3 000 знаков дают > 256 КиБ.

## 3. ClickHouse 24.8

### 3.1 План: CTE и скаляры
- **Держи CTE линейной цепочкой: каждая упомянута один раз.** CTE — это подстановка текста, каждая ссылка исполняется
  заново. Бой: 1 ссылка — 2,1 с, 6 ссылок — 11,7 с; 8 плеч UNION над CTE — 17 сканов и «Превышено время ожидания»
  (CH-05).
- **Контекст (доступ → юниты → месяц → диапазоны) сворачивай в один скаляр-кортеж с одним текстом и читай его
  проекциями.** Каждый другой скаляр над той же цепочкой стоит ≈ +0,2 с. HRBP: 2,37 → 1,30 с (CH-06).
- **Ветки над общим сканом делай ролью строки:** `arrayJoin` + один GROUP BY, состояния гаси условием по роли, лимиты
  секций — `row_number() OVER (PARTITION BY role …)`. Плечи UNION — только по своим диапазонам или таблицам (CH-07).
- **Вычисляемые WITH-алиасы держи только на верхнем уровне.** В подзапрос контекст передавай через CTE и
  `CROSS JOIN ctx` (CH-08).
- **Скаляр, который может быть пустым, бери агрегатом без GROUP BY.** Пустой Tuple или Array даёт Code 125 (CH-09).
- **Историю сворачивай до размножения ключа, мету — после сжатия:** 11,4 → 3,2 с (CH-26).

### 3.2 Чтение и поиск
- **Ветку дерева читай диапазоном ключа сортировки:** `path_s >= p AND path_s < concat(p, '0')`. Путь — id
  фиксированной длины (12 hex), выгрузка `ORDER BY (path_s)`. Читает 3 гранулы из 245 (CH-18).
- **Фильтруй по префиксу `order_by`.** Флаги — `PREWHERE`, партиции — прямой границей даты, одна строка на сущность —
  `LIMIT 1 BY id` (CH-19).
- **Список — `x IN dl_x` по константе WITH, массив — `arrayExists(x -> x IN dl_x, path)`.** `has`/`hasAny` по длинному
  литералу перебирают его на каждой строке: 3,09 против 0,35 с, `hasAny` — 26,8 против 0,57 с. `has` — до ≈ 20 значений
  (CH-20).
- **Коды делай через `transform`, а не `indexOf`:** 0,59 с против 79,5 с на 20 млн строк (CH-21).
  ```sql
  toString(transform(x, tupleElement({{ DZ }}, 3), arrayEnumerate(tupleElement({{ DZ }}, 3)), toUInt32(0)))
  ```
- **`IN` по скаляру-массиву из данных не работает** (Code 1 / 53). Пиши `x IN (SELECT arrayJoin(scope) FROM ctx)`
  (CH-12).
- **Сначала отбери (`ORDER BY ключ NULLS LAST, id LIMIT N`), потом упаковывай отобранное:** 4,4 → 0,6 с (DS-15).
- **Дерево строй из уникальных путей** (×2,7, CH-25), уровни — `GROUP BY … WITH ROLLUP` (CH-24).
- **Ряд — строкой без хвостовых нулей** `replaceRegexpOne(arrayStringConcat(a, ','), '(,0)+$', '')` (CH-22); бит —
  `bitTest(msk, toUInt8(least(k, 63)))`, в JS не больше 53 бит (CH-27).

### 3.3 Nullable, типы, алиасы
- **`ifNull` ставь на каждом входе (до агрегатов, CAST, `arrayConcat`, JOIN) и на каждом выходе** — иначе Code 349,
  CANNOT_INSERT_NULL (CH-14). Элементы массивов — `arrayMap(x -> ifNull(x, ''), a)`, ключи кортежей —
  `toString(ifNull(x, ''))`, сентинел JOIN — вне домена (`-1`), NULL в массивах — после свёртки (CH-15).
- **Типы веток `if`, элементов массива и плеч UNION приводи явно.** Числа на выходе — `toInt64(ifNull(n, 0))`. Иначе в
  бою Code 386 (CH-13).
- **Алиасу не давай имя входной колонки.** В бою `groupBitOr(msk) AS msk … HAVING` дал Code 215, а `toInt64(0) AS n`
  отсеял всё в WHERE. Вход переименуй (`m0`) или пиши `z.n` (CH-11).
- **Колонкам первого плеча UNION давай уникальные `AS`, лучше во всех плечах** (CH-10).
- **Доли не дели в SQL:** `x / 0` даёт `null` в JSON, `intDiv(x, 0)` — Code 153. Если делишь — `if(d = 0, 0, x / d)`.

### 3.4 Чего нет в 24.8 и что молча врёт
- **`lag`/`lead` нет:** пиши `lagInFrame`/`leadInFrame` с явной рамкой `ROWS BETWEEN UNBOUNDED PRECEDING AND
  UNBOUNDED FOLLOWING`, а лучше бери соседа в JS. Нет и `GROUPS BETWEEN`, `generate_series`.
- **Недели — `toMonday()`.** Где сверяют руками — `uniqExact` и `argMax(x, dt)` с тай-брейком, а не `anyLast`.
  `UInt` перед вычитанием приводи к знаковому.
- **NULL в ключе JOIN не совпадает ни с чем.** Промах JOIN — это 0, поэтому ставь маркер `1 AS hit`.
- **Коррелированных подзапросов нет, `arrayJoin` в WHERE не пиши.** `ARRAY JOIN` по WITH-алиасу — Code 206 на старом
  анализаторе.
- **Дату считай от свежести данных одной строкой:** `(SELECT md FROM t WHERE isNotNull(md) LIMIT 1)`, а не через
  `today()` или `max()`. Периоды — закрытые (DS-06, DS-07); если владелец просит текущий месяц — исключение в DS-06 (пометка вызревающих).

## 4. Доступ и кэш

- **Доступ решай только в датасете по `current_username()`.** `currentUser()` CH — сервисная учётка (AC-01). Логин:
  `(current_username() or '')|string|trim|lower`, строка доступа — агрегатом без GROUP BY.
- **Нет доступа — отвечай одной `meta` с `ok = 0`, не ошибкой** (AC-02, DS-08). Совсем пустой ответ — это заглушка без
  iframe.

| Ответ зависит от | Ключ кэша | Как (AC-06) |
|---|---|---|
| пользователя (зона, маски, «Мои») | личный | вызов логина внутри `{{ … }}` **одной строкой** |
| только фильтров и данных | общий | ни одного `current_username`, `cache_key_wrapper`, `url_param` — даже в комментариях и предикате автозаполнения |
| того и другого | два датасета | личный — короткий, общий — тяжёлый |

- **Логин в ключ ставь только вызовом в `{{ … }}` на одной строке** (AC-07, SP-20): регулярка Superset ищет его по
  сырому тексту и не видит `{% set me = current_username() %}` и вызов на трёх строках (07.10 — чужой ответ из кэша в
  трёх отчётах). Канон — `login_q` (§7.2).
- **Актуально 09–14.10.** Adoption пишет `'{{ cache_key_wrapper(current_username()) }}'` прямо в SQL — это работает, но
  без экрана кавычки. Предпочитай `qs(…)`.
- **Общий ответ выноси в отдельный датасет без логина и `url_param`.** Один холодный расчёт на всех на 12 ч. Признак
  ошибки — «фильтры долго, второй раз быстро» (DS-10, AC-09). Варианты держи одним исходником: сборщик меняет строку
  `login_q` на заглушку.
- **Параметр адреса читай через `url_param('x', escape_result=False)` своим экраном, только в личном датасете** (SP-23).
- **«Время жизни кэша» — пусто или 0 (= 12 ч); −1 кэш не выключает** (запись без срока, SP-24). Прогревай только общий
  кэш (AC-13).
- **Актуально 09–14.10.** Adoption 07.10 сначала писал «выключает только −1», но в тот же день владелец ответил «−1
  Proteus не выполняет», и поставку вернули на 0. Выключить кэш нельзя; свежесть дают ключ, Save с реальной правкой
  (`changed_on`, например «Описание» = номер поставки) и «Обновить дашборд».

## 5. Кросс-фильтры: носители

- **Носители (`*_f`, `mode_param`, `rq_f`) не выводи в SELECT и не клади в «Измерения».** Иначе Superset повесит
  внешний `WHERE col IN (…)`, а на Array-колонке это падение (SP-14). Читает их только Jinja.
- **Носитель читай циклом с пределами и белым списком** (AC-14): rk — `isalnum` ≤ 64 знаков и ≤ 50 штук, значения —
  ≤ 200 на атрибут и ≤ 500 всего, метка ≤ 40, числа — `isdigit()` из списка, без `\n`/`\r`. Лишнее отбрасывается молча.
- **В `meta` отдавай эхо того, что датасет взял после проверок, и метку `rq`** (DS-03). Чарт эмитит значения
  отсортированными (их порядок входит в ключ) и никогда — `value: []` (SP-21, MC-02).

## 6. Оптимизация под задачу

| Задача | Приём | Правило |
|---|---|---|
| Тысячи записей, справочник, дерево | упаковать: пачки в `j`, колонки со словарём; строк ответа — десятки или сотни | DS-18, DS-19, DS-24 |
| Метрики × периоды | позиция в массиве сетки, ряд строкой без хвостовых нулей, плоский массив компонентов | DS-05, CH-22, DS-23 |
| Доли, проценты, ранги | только аддитивные компоненты, делит JS | DS-04 |
| Тяжёлое на каждый клик | предагрегат в GP; дорогая ветка — за рубильником `{% set WITH_X = false %}` | GP-14, DS-14 |
| Независимые тяжёлые части | два датасета — параллельные запросы: экран ждёт максимума, а не суммы | DS-09, MC-17 |
| Ответ одинаков у всех | отдельный датасет без логина | DS-10 |
| Кириллица в тяжёлом ответе | base64 от UTF-8 или `cz` (≈ 1 байт на букву вместо 6) | DS-17 |
| «Долго» при быстром SQL Lab | бюджет текста (§2.3), логин в ключе только где нужен | SP-15, SP-22 |

**Упаковка.**
- **Контракт держи узким и постоянным: `role` + 3–5 латинских колонок** (`role k v n j` или `section g k parent n`;
  String, `n` — Int64). Новое добавляй ролью или полем в конец упаковки, а не колонкой. Каталог 20 колонок × 13,7 тыс.
  строк → 5 × 27 дал 5,8 → 1,1 МБ (DS-01).
- **Порядок внутри упаковки задавай явно** — `arraySort(groupArray(…))`. Порядок `groupArray` не задан, и без сортировки
  ответ «плавает» (актуально 09.10, Adoption).
- **Дерево — узлами в порядке обхода в глубину, без rk родителя**; повтор юнита в пути — пустой уровень (DS-20, DS-21).

**Целостность под обёрткой.**
- **Каждая строка ответа уникальна:** GROUP BY склеит одинаковые; нужны дубли — добавь номер.
- **Порядок восстанавливает JS.** ORDER BY по роли и `end` — только страховка (SP-13).
- **Число строк ответа клади в `meta.rows`** окном `count() OVER ()`. Чарт сверяет его с `data.length` и при
  `data.length ≥ лимита` пишет «ответ обрезан» (DS-25).
- **Актуально 09–14.10.** В боевых Adoption и TeamPulse `rows` ещё нет (`end` + проверка лимита); в новых — ставь.

**Бюджеты.**
- **Холодный худший — ≤ 15 с на стенде масштаба боя** (бой ≈ 2×, предел 30 с), клик ≈ 1 с (PL-02, ST-19). Синтетика —
  с кардинальностью боя (100 тыс. людей, 10 тыс. юнитов, сотни групп), иначе в бою всплыли 7,9 МБ и клик 3–5 с (DS-16).
- **Вес считай тремя числами:** `sum(length(…))` по ролям, JSON, после gzip; 1 МБ на проводе ≈ 2 с.
- **Оптимизацию доказывай A/B:** новый анализатор, ответ байт в байт со старой версией (`same.py`) (CH-31).

## 7. Рецепты

### 7.1 Каркас датасета (контракт в шапке — DS-26)
Полная заготовка — `../proteus-playbook/templates/dataset.template.sql`.
```jinja
{#- ==========================================================================
    <Отчёт> — датасет <имя>. Вид main: ЛИЧНЫЙ ключ (логин) | shared: ОБЩИЙ (вызовов логина нет нигде).
    КОЛОНКИ: role k v n j — String, n — Int64; в «Измерения» — все пять; новое — новой ролью.
    РОЛИ: meta — 1 строка, j = {"ver","rows","build","ok","data_dt","rq",эхо}; ok = 0 — только meta и end
          r    — пачки: k — номер с 0, n — записей, j — строки через char(10), поля через char(9)
          end  — маркер
    НОСИТЕЛИ (в SELECT нет): rq_f ≤ 40 · unit_f isalnum ≤ 64, ≤ 50 · flt_f 'атр=знач' ≤ 200/атр, ≤ 500
    ПОРЯДОК: обёртка его не держит — сортирует чарт; целостность — meta.rows = data.length.
    РУБИЛЬНИКИ: WITH_F = true — false, если ветка f тяжела на боевой кардинальности.
========================================================================== -#}
{% set VIEW = 'main' %}{% set BUILD = '' %}{% set T_ACC = 'prod_proteus.xx_access' %}
{% filter replace('\n    ', '\n')|replace('\n  ', '\n') %}
WITH
  {% if UNITS %}{{ qa(UNITS) }} AS dl_units,{% endif %}
  acc AS (                            {# агрегат без GROUP BY: одна строка и у логина без доступа #}
    SELECT groupArrayIf(ifNull(root_id, ''), ifNull(role, '') = 'hrbp') AS r_zone,
           toUInt8(countIf(ifNull(role, '') = 'super') > 0) AS a_all, count() AS a_n
    FROM {{ T_ACC }} WHERE ifNull(login, '') = {{ login_q() }}
  ),
  ctx0 AS (SELECT (arrayDistinct(arrayFilter(x -> x != '', r_zone)), a_all, toUInt8(a_n > 0)) AS ctxt FROM acc),
  ctx AS (SELECT c.1 AS c_roots, c.2 AS c_all, c.3 AS c_ok FROM (SELECT (SELECT ctxt FROM ctx0) AS c))
SELECT role, k, v, n, if(role = 'meta', replaceOne(jj, '"rows":0', concat('"rows":', toString(rows_n))), jj) AS j
FROM (
  SELECT ifNull(r0, '') AS role, ifNull(k0, '') AS k, ifNull(v0, '') AS v, toInt64(ifNull(n0, 0)) AS n,
         ifNull(j0, '') AS jj, count() OVER () AS rows_n
  FROM (
    SELECT 'meta' AS r0, … {# §7.4 #}
    UNION ALL SELECT 'r' AS r0, … {# §7.5 #}
    UNION ALL SELECT 'end' AS r0, '' AS k0, '' AS v0, toInt64(0) AS n0, '' AS j0
  )
)
{% endfilter %}
```
Окно — уровнем ниже внешнего SELECT (рядом с ORDER BY старый анализатор даёт Code 47); внутренние имена ≠ выходным (CH-11).

### 7.2 Экран литералов и логин
```jinja
{% macro qs(v) -%}
{%- set s = v|string -%}{%- set t = s.rstrip('\\') -%}
{%- if t|length < s|length -%}concat('{{ t|replace('\\', '\\\\')|replace("'", "''") }}', repeat(char(92), {{ s|length - t|length }}))
{%- else -%}'{{ s|replace('\\', '\\\\')|replace("'", "''") }}'{%- endif -%}
{%- endmacro %}
{% macro qa(values) -%}
{%- if values|length == 0 -%}CAST([], 'Array(String)')
{%- else -%}{%- set br = [] -%}{%- for v in values if ']' in v|string -%}{%- set _ = br.append(1) -%}{%- endfor -%}
{{ 'array(' if br else '[' }}{% for v in values %}{{ qs(v) }}{% if not loop.last %}, {% endif %}{% endfor %}{{ ')' if br else ']' }}
{%- endif -%}
{%- endmacro %}
{#- Логин — ТОЛЬКО здесь: тело — одна строка с вызовом в двойных фигурных скобках (AC-07). Вид shared: строку заменяет сборщик. -#}
{% macro login_q() -%}{{ qs((current_username() or '')|string|trim|lower) }}{%- endmacro %}
```
Штатный `|where_in` слэш не экранирует: перед ним выполни `replace('\\', '\\\\')`, как макрос `q()` в Adoption.

### 7.3 Фильтр-цикл
```jinja
{% set RQ_L = [] %}{% for v in (filter_values('rq_f') or []) %}{% set s = v|string %}{% if not RQ_L and s|length <= 40 and '\n' not in s and '\r' not in s %}{% set _ = RQ_L.append(s) %}{% endif %}{% endfor %}
{% set RQ = RQ_L|first if RQ_L else '' %}
{% set UNITS = [] %}{% for v in (filter_values('unit_f') or []) %}{% set s = v|string|trim %}{% if s and s|length <= 64 and s.isalnum() and UNITS|length < 50 and s not in UNITS %}{% set _ = UNITS.append(s) %}{% endif %}{% endfor %}
```
Одно значение — `|first|default(…, true)` и белый список. В SQL — `{% if UNITS %}AND arrayExists(x -> x IN dl_units, p){% endif %}`.

### 7.4 Строка meta
```sql
SELECT 'meta' AS r0, {{ qs(VIEW) }} AS k0, {{ qs(RQ) }} AS v0, toInt64(m.n_all) AS n0,
  concat('{"ver":"1","rows":0,"build":', toJSONString({{ qs(BUILD) }}), ',"ok":', toString(ctx.c_ok),
         ',"data_dt":', toJSONString(ifNull(toString((SELECT dt FROM <витрина> WHERE isNotNull(dt) LIMIT 1)), '')),
         ',"rq":', toJSONString({{ qs(RQ) }}),
         ',"units":', toJSONString({{ 'dl_units' if UNITS else "CAST([], 'Array(String)')" }}), '}') AS j0
FROM ctx CROSS JOIN (SELECT countIf(<условие>) AS n_all FROM <источник> WHERE <зона>) AS m
```
`meta` есть всегда; `"rows":0` подменяет внешний SELECT. Чарт ищет её по `role` и сам называет ошибку: нет `meta` —
старый датасет или мал лимит; `rows` ≠ `data.length` — ответ обрезан; `ok = 0` — нет доступа.

### 7.5 Много строк → пачки
```sql
SELECT 'r' AS r0, toString(ck) AS k0, '' AS v0, toInt64(count()) AS n0,
       arrayStringConcat(arrayMap(t -> t.2, arraySort(t -> t.1, groupArray((rn, line)))), char(10)) AS j0
FROM (
  SELECT rn, intDiv(rn - 1, {{ CHUNK }}) AS ck, line          {# номер пачки — колонкой, не алиасом в GROUP BY #}
  FROM (
    SELECT row_number() OVER (ORDER BY sk NULLS LAST, id) AS rn,
           arrayStringConcat(arrayMap(x -> replaceRegexpAll(x, '[[:cntrl:]]', ' '),
                                      [id, nm, unit, toString(v1)]), char(9)) AS line
    FROM (SELECT … FROM <источник> CROSS JOIN ctx WHERE <зона> AND <условие>
          ORDER BY sk NULLS LAST, id LIMIT {{ LIM }})       {# сначала отобрать, потом упаковать #}
  )
)
GROUP BY ck
```
Секции из одного скана собирай так (CH-07): `arrayJoin([('a', key_a), ('b', key_b)])` → один `GROUP BY role, key` →
`arrayStringConcat(arraySort(groupArray(line)), '\n')`.

## 8. SQL Lab

- **В файле один запрос, первое слово — SELECT или DESCRIBE.** Шапка из `--` допустима, CTE прячь внутрь `FROM (…)`
  (PL-04).
- **Ни слова `system` (даже в комментарии) и ни одного SHOW.** Вместо них — `version()`, `getSetting('…')`,
  `DESCRIBE TABLE`. `LIMIT N BY` на верхнем уровне не ставь: SQL Lab примет его за лимит строк.
- **Файл собирай скриптом из исходника** — отрендеренный типичный выбор, логин заглушкой `'ваш_логин'` один раз.
  Повтор замера — с меткой **в коде** (`SELECT …, 2 AS run`), а не в комментарии (PL-05).
- **Актуально 09–14.10.** «ЗАМЕР БОЯ» Adoption меняет цифру в комментарии — ненадёжно: 2.0.1 комментарии вырезает.
- **Разведку маскируй в самом запросе** (счётчики, промилле, `* EXCEPT` ПДн) (AC-15); данные боя не коммить (AC-16).
