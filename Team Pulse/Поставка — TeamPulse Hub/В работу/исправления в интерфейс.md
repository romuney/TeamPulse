# Новая итерация: уточнение логики вкладки «Ревью»

## Цель

Уточнить реализацию вкладки «Ревью» и правила её взаимодействия с остальным дашбордом:

1. Полностью убрать ссылки на словарь метрик из интерфейса и описаний реализации.
2. Применять фильтры к вкладке «Ревью» по общей глобальной логике дашборда.
3. Определять строки для ревью по значению поля `valit_dttm = 5999-10-10`, не используя статус.

# 2. Фильтры применяются глобально

## Требование

Фильтры должны работать по общей логике дашборда.

Вкладка «Ревью» не должна иметь отдельную или отличающуюся логику фильтрации.

Все глобальные фильтры должны одинаково применяться:

- к вкладке «Ревью»;
- к другим вкладкам;
- к графикам;
- к таблицам;
- к KPI;
- к расчётам;
- к сравнительным показателям;
- к итоговым значениям.

## Что нужно сделать

- Подключить вкладку «Ревью» к существующему глобальному состоянию фильтров.
- Использовать те же параметры фильтрации, что и остальные вкладки.
- Использовать те же значения по умолчанию.
- Использовать те же правила сброса фильтров.
- Использовать те же правила выбора одного или нескольких значений.
- Использовать те же правила обработки пустого фильтра.
- Использовать те же правила обработки даты.
- Использовать те же правила фильтрации по подразделениям, грейдам, стажу и специализациям, если эти фильтры уже есть в дашборде.

## Запрещено

Нельзя:

- создавать отдельный набор фильтров только для «Ревью»;
- создавать отдельное состояние фильтров для «Ревью»;
- применять фильтр только к части блоков вкладки;
- игнорировать глобальный фильтр в отдельных графиках;
- менять смысл фильтра на вкладке «Ревью»;
- использовать другие значения по умолчанию;
- автоматически сбрасывать глобальные фильтры при переходе на вкладку;
- применять фильтры к «Ревью» иначе, чем к остальным вкладкам;
- добавлять локальный фильтр, если он не предусмотрен общей логикой дашборда;
- показывать данные, не соответствующие выбранным глобальным фильтрам.

## Порядок применения фильтров

Фильтры должны применяться в общем порядке:

1. Получить данные из YAML-источника.
2. Применить глобальные фильтры дашборда.
3. Выбрать строки, относящиеся к ревью, по правилу `valit_dttm = 5999-10-10`.
4. Рассчитать eligible-популяцию.
5. Рассчитать показатели вкладки «Кого оцениваем».
6. Рассчитать показатели вкладки «Как оцениваем».
7. Передать отфильтрованные данные в графики и таблицы.

Если в общей логике дашборда установлен другой порядок обработки данных, необходимо использовать существующий порядок и не создавать отдельный порядок для «Ревью».

## Единообразие фильтрации

Для всех блоков вкладки «Ревью» должен использоваться один и тот же отфильтрованный набор данных.

Это относится к:

- общей численности;
- eligible-популяции;
- улучшившим оценку;
- ухудшившим оценку;
- впервые оценённым;
- переходам между оценками;
- первым оценкам;
- распределению по грейду;
- распределению по стажу;
- распределению по специализации;
- долям сотрудников с оценками `0–1`;
- долям сотрудников с оценками `3–4`.

Нельзя, чтобы разные блоки вкладки использовали разные правила фильтрации.

## Проверка фильтров

Проверить:

- [ ] Фильтры на «Ревью» используют глобальное состояние дашборда.
- [ ] При изменении глобального фильтра обновляются все блоки «Ревью».
- [ ] При переходе между вкладками фильтры сохраняются.
- [ ] Вкладка «Ревью» не сбрасывает фильтры.
- [ ] Один и тот же фильтр одинаково влияет на все вкладки.
- [ ] Нет локального фильтра, дублирующего глобальный.
- [ ] Нет блока, который игнорирует глобальную фильтрацию.
- [ ] Все показатели «Ревью» рассчитаны по одному отфильтрованному набору данных.

# 3. Выбор строк ревью по `valit_dttm`

## Требование

Для вкладки «Ревью» не использовать статус.

Строки, относящиеся к ревью, определять по условию:

```text
valit_dttm = 5999-10-10
```

## Основное правило

Строка считается строкой ревью, если значение поля `valit_dttm` соответствует дате:

```text
5999-10-10
```

В коде необходимо использовать точное имя поля:

```text
valit_dttm
```

Не заменять это поле на другое без подтверждения.

## Важное ограничение

Не использовать для выбора строк ревью:

- поле статуса;
- текстовый статус;
- флаг статуса;
- название ревью;
- наличие текущей оценки;
- наличие предыдущей оценки;
- другие косвенные признаки.

Единственным признаком отбора строк ревью в рамках этой итерации является:

```text
valit_dttm = 5999-10-10
```

## Порядок отбора

Применять следующий порядок:

1. Загрузить данные из YAML-файла.
2. Применить глобальные фильтры дашборда.
3. Отобрать строки, в которых:

```text
valit_dttm = 5999-10-10
```

4. Полученный набор использовать для всех расчётов вкладки «Ревью».
5. Не фильтровать этот набор по статусу.

## Тип значения

Проверить фактический тип поля `valit_dttm` в YAML.

Возможные варианты:

- строка;
- дата;
- дата и время;
- значение в другом сериализованном формате.

Сравнение должно корректно работать с фактическим типом поля.

Если значение хранится как дата и время, необходимо согласовать правило сравнения. Нельзя самостоятельно заменять точное условие на условие по году, месяцу или началу строки.

Пример допустимого условия только при подтверждении формата:

```text
date(valit_dttm) = date(5999-10-10)
```

Если поле хранится как строка с точным значением:

```text
valit_dttm == "5999-10-10"
```

Фактический вариант выбрать после проверки структуры YAML.

## Пустые и некорректные значения

- Строки с пустым `valit_dttm` не считать строками ревью.
- Строки с `null` не считать строками ревью.
- Строки с другой датой не считать строками ревью.
- Строки с некорректным форматом даты не считать строками ревью.
- Некорректные значения не заменять датой `5999-10-10`.
- Не использовать статус как запасной способ определения строк ревью.

## Примеры классификации

| `valit_dttm` | Относится к ревью |
|---|---|
| `5999-10-10` | Да |
| `5999-10-11` | Нет |
| `2024-01-01` | Нет |
| `null` | Нет |
| пустое значение | Нет |
| некорректная дата | Нет |

## Контрольная проверка

После реализации проверить:

- количество строк с `valit_dttm = 5999-10-10`;
- количество уникальных сотрудников в выбранных строках;
- наличие строк с другими датами;
- наличие строк с пустым `valit_dttm`;
- наличие строк с `null`;
- отсутствие влияния поля статуса на результат.

# 4. Влияние правила отбора на вкладку «Ревью»

## Подвкладка «Кого оцениваем»

Все блоки должны рассчитываться после применения условия:

```text
valit_dttm = 5999-10-10
```

Это относится к:

- общей численности;
- eligible-популяции;
- улучшившим оценку;
- ухудшившим оценку;
- впервые оценённым.

Общую численность также рассчитывать по данным, прошедшим глобальные фильтры.

Если для общей численности используется отдельный источник, условие его использования должно быть согласовано с общей логикой дашборда. Нельзя автоматически включать в общую численность строки, которые не относятся к выбранному периоду или области фильтрации.

## Подвкладка «Как оцениваем»

Все блоки должны рассчитываться на том же наборе данных:

```text
глобальные фильтры
+
valit_dttm = 5999-10-10
```

Это относится к:

- переходам между оценками;
- первым оценкам;
- распределению оценок по грейдам;
- распределению оценок по стажу;
- распределению оценок по специализациям;
- долям сотрудников с оценками `0–1`;
- долям сотрудников с оценками `3–4`.

## Единый набор данных

Не создавать отдельные версии набора для разных графиков.

Допускается выполнять дополнительные группировки и расчёты, но исходным набором для них должны быть одни и те же строки, прошедшие:

```text
глобальные фильтры
+
valit_dttm = 5999-10-10
```

Пример логики:

```text

    row.valit_dttm соответствует дате 5999-10-10
```

Фактическое имя функции выбрать в соответствии со стилем проекта.

## Пример последовательности обработки

```text
raw_data
→ apply_global_filters(raw_data)
→ select_review_rows_by_valit_dttm(filtered_data)
→ calculate_review_metrics(review_data)
→ render_review_tabs(review_metrics)
```

Не создавать отдельную фильтрацию статуса:

```text

```

для определения строк ревью.

## Обработка ошибок

Предусмотреть состояния:

- YAML-файл не найден;
- YAML-файл не читается;
- поле `valit_dttm` отсутствует;
- поле `valit_dttm` имеет неожиданный формат;
- после глобальной фильтрации нет данных;
- после условия `valit_dttm = 5999-10-10` нет строк;
- после удаления дублей нет уникальных сотрудников;

Сообщения об ошибках должны быть понятны пользователю и не раскрывать лишние технические детали.

## Если поле отсутствует

Если поле `valit_dttm` отсутствует в YAML:

- не использовать статус как замену;
- не считать все строки строками ревью;
- не применять условие по другому полю;
- показать ошибку или состояние отсутствия необходимого поля;
