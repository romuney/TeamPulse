# Новая итерация: подписи оценок и оформление таблиц «Ревью»

## Цель

Доработать вкладку «Ревью»:

1. Убрать числовые обозначения оценок из интерфейса.
2. Заменить названия двух процентных столбцов.
3. Визуально разделить распределения по грейду, стажу и специализации на три самостоятельные таблицы.
4. Сделать все столбцы этих таблиц одинаковой ширины.

## Общие ограничения

- Не менять шкалу оценок, расчёты и состав выборки.
- Не менять глобальную логику фильтрации.
- Не менять состав групп, используемых для расчёта процентных показателей.
- Числовые коды оценок могут оставаться во внутренних данных и расчётах, но не должны отображаться пользователю.
- Использовать существующие компоненты и стили дашборда.
- Не переносить в эту итерацию другие задачи.

---

## 1. Убрать числовые обозначения оценок

### Требование

На всей вкладке «Ревью» убрать числовое представление оценок: `0`, `1`, `2` и другие значения шкалы.

Для обозначения оценки использовать только:

- соответствующую картинку;
- текстовое название или описание оценки.

### Где проверить

На обеих подвкладках:

- в заголовках таблиц;
- в подписях строк;
- в легендах и подписях графиков;
- в переходах между оценками;
- в блоке первых оценок;
- в тултипах;
- в пояснениях;
- в доступных названиях элементов интерфейса.

### Что убрать

Не показывать пользователю конструкции вида:

- «Оценка 0»;
- «Оценка 1»;
- «Огонь (3)»;
- «0–1» как обозначение группы оценок;
- «3–4» как обозначение группы оценок.

### Что сохранить

- Картинки оценок.
- Их фактические текстовые названия.
- Порядок оценок.
- Количество сотрудников.
- Процентные значения.
- Числовые значения грейда, стажа и других показателей, если они не являются кодами оценок.

**Важно:** требование не означает удаление всех чисел с вкладки. Убираются только числовые обозначения самой шкалы оценок.

### Доступность

- В `alt` изображений использовать текстовое название оценки без числового кода.
- В подсказках и доступных описаниях не дублировать числовой код оценки.

## 2. Переименовать столбец «% 0–1»

### Требование

Во всех таблицах вкладки «Ревью» заменить заголовок:

**Было:** `% 0–1`

**Стало:** `% есть над чем поработать и ниже`

### Где применить

- В таблице по грейдам.
- В таблице по стажу.
- В таблице по специализациям.
- В связанных подсказках и пояснениях, если там используется прежнее обозначение.

### Правила

- Состав группы и расчёт доли не менять.
- В пояснениях использовать текстовые названия оценок без числовых кодов.
- Длинный заголовок переносить на несколько строк.
- Не сокращать заголовок обратно до числового диапазона.

## 3. Переименовать столбец «% 3–4»

### Требование

Во всех таблицах вкладки «Ревью» заменить заголовок:

**Было:** `% 3–4`

**Стало:** `% огней и выше`

### Где применить

- В таблице по грейдам.
- В таблице по стажу.
- В таблице по специализациям.
- В связанных подсказках и пояснениях, если там используется прежнее обозначение.

### Правила

- Состав группы и расчёт доли не менять.
- В пояснениях использовать текстовые названия оценок без числовых кодов.
- При необходимости переносить заголовок на несколько строк.

---

## 4. Разделить распределения на три отдельные таблицы

### Проблема

Таблицы по грейду, стажу и специализации визуально сливаются.

### Требование

Оформить их как три самостоятельных блока:

1. **Распределение оценок по грейду**
2. **Распределение оценок по стажу**
3. **Распределение оценок по специализации**

### Для каждого блока предусмотреть

- отдельный заголовок;
- отдельную таблицу;
- собственную строку заголовков столбцов;
- собственный контейнер в общем стиле дашборда;
- достаточный отступ до соседнего блока.

### Визуальные требования

- Между таблицами должна быть отчётливо видимая граница за счёт отступов и оформления контейнеров.
- Не объединять три распределения в одну таблицу с промежуточными подзаголовками.
- Не допускать прилегания последней строки одной таблицы к заголовку следующей.
- Сохранить единый стиль всех трёх блоков.
- Сохранить существующую механику раскрытия специализаций, если она реализована.

### Данные

Разделение является визуальным и не должно менять:

- строки распределений;
- значения ячеек;
- порядок оценок;
- расчёт долей;
- работу фильтров.

---

## 5. Сделать ячейки одинаковой ширины

### Требование

Во всех трёх таблицах распределения установить одинаковую ширину для всех столбцов, включая:

- первый столбец с грейдом, стажем или специализацией;
- столбцы отдельных оценок;
- два правых столбца с процентами.

Ячейки заголовка и тела одного столбца должны совпадать по ширине.

### Правила реализации

- Использовать единый принцип расчёта ширины столбцов.
- При одинаковом количестве столбцов и одинаковой доступной ширине все три таблицы должны иметь одинаковую сетку.
- Не расширять отдельный столбец из-за длинного текста.
- Не сжимать столбцы с картинками относительно остальных.
- Разрешить перенос длинных названий и заголовков на несколько строк.
- Не обрезать важный текст и не допускать наложения содержимого.
- Высота строк может увеличиваться для размещения текста: одинаковая ширина не означает одинаковую высоту.

### Адаптивность

- На узком экране сохранять равенство ширины столбцов.
- При недостатке места использовать горизонтальную прокрутку по правилам проекта.
- Не уменьшать текст и картинки до нечитаемого размера.
- Не допускать рассинхронизации заголовков и данных при прокрутке.

---

## 6. Ожидаемый результат

После доработки:

- пользователь видит оценки только через картинки и текстовые названия;
- числовые коды шкалы не отображаются;
- два процентных столбца называются:
  - `% есть над чем поработать и ниже`;
  - `% огней и выше`;
- распределения по грейду, стажу и специализации представлены тремя отдельными таблицами;
- все столбцы этих таблиц имеют одинаковую ширину;
- расчёты и фильтрация работают без изменений.
