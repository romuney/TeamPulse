# TeamPulse Hub — что куда вставлять

Отчёт в Proteus собирается так же, как HRBP HUB: **таблицы ClickHouse → один датасет →
один чарт**, и, если существующих таблиц не хватит, — ноут Helicopter со своими витринами.
Всё, что в макете было шапкой, вкладками, таблицей подразделений и графиками, будет жить
в одном чарте. Как отчёт должен выглядеть и работать — макет (`index.standalone.html`,
он же GitHub Pages) и правила в `AGENTS.md`; откуда берутся данные — `SOURCES.md`.

## Файлы

| Файл | Куда вставлять | Сейчас |
|---|---|---|
| `0а. SQL Lab — структура таблицы ClickHouse.sql` | SQL Lab в Proteus (или DBeaver, clickhouse-client): запросы по одному, ответы — мне | **готов — шаг 0** |
| `1. Helicopter — ноут TeamPulse Hub.yaml` | Helicopter → ноут «TeamPulse Hub» → импорт YAML | появится, если готовых таблиц не хватит |

| `3. Proteus — чарт TeamPulse Hub.js` | Proteus → чарт (тип ECHARTS) → JS | появится после датасета |

Номера закреплены заранее и между поставками не меняются: «замените файл 3» всегда значит
чарт. Файл с буквой (`0а`, `1а`) — дополнение к своему номеру.

## Шаг 0 — покажите структуру таблиц ClickHouse

SQL Lab в Proteus пропускает только `SELECT` и `DESCRIBE`, а служебные таблицы ClickHouse
в нём закрыты (запрос со словом `system` он не выполняет даже в комментарии). Поэтому
структура в файле `0а` — через `DESCRIBE TABLE`, остальное — обычные `SELECT` по самой
таблице. Таблица в файле уже вписана: `prod_proteus.hr_structure_overall`.

1. Откройте `0а. SQL Lab — структура таблицы ClickHouse.sql`.
2. Выделите **один** запрос — от `DESCRIBE` или `SELECT` до точки с запятой — и выполните
   (Ctrl+Enter).
3. Ответ — «Скопировать в буфер» или CSV — пришлите в чат с номером запроса.
4. Сейчас нужны запросы **1–4**: колонки, число строк, число разных значений в каждой
   колонке и заполненность. Если запрос 3 думает дольше минуты — вместо него 3б.
5. Запросы 5–9 — после ответа на 1: в них нужны имена ваших колонок (ключ сотрудника,
   дата, колонки с ФИО и почтой). Пока вместо имён стоят `<…>`, запросы нарочно не
   выполнятся. Пришлю их уже заполненными.

Другая таблица — замените `prod_proteus.hr_structure_overall` во всём файле (Ctrl+H).

**Персональные данные не присылайте.** Запросы 1–4 их не показывают — там имена колонок,
типы и счётчики. В запросах 5 и 6 колонки с ФИО, почтой, логином, табельным номером и
зарплатой исключены через `EXCEPT`, ключ сотрудника показан хешем. `EXCEPT` молча
пропускает имя, которого в таблице нет, поэтому имена сверяются с ответом на запрос 1.

**Что я сделаю с ответами:** сопоставлю колонки с метриками отчёта (`SOURCES.md` §7 —
паспорта метрик, §17 — что нужно новым метрикам), найду зерно таблицы и то, чего в ней не
хватает, и напишу датасет — файл 2.
