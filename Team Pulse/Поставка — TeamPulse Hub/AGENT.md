## Конвейер

```
usr_cross_data.hr_executive_proteus (люди по дням)        + перформанс, посещения, заявки T-роста, вакансии, AI
  → build_all_metrics → all_metrics: человек × месяц × юнит; разрезы — на конец месяца, события — max по дням
  → with_performance / with_office_traffic / with_TRost → all_metrics_with_performance_and_office_traffic_and_grt (SRC)
  → hub · 0…6 → teampulse_hub_* (узел × месяц × срез) → hub checks → to click (выгрузка в prod_proteus)
  → датасет 2: узлы ответа под фильтры → строки role/id/…/ms/mx → чарт
```

Параграфы ноутбука по порядку: описание (md) · `step1/step2` ожидание таблиц · `_PARAMS_` (FIXED_DIMS, параметры найма,
оттока, переводов) · `build_all_metrics` (функция) · `EXEC build_all_metrics` (список разрезов `fields`) ·
`unit_head_structure`, `org_structure` (юниты и руководители) · `with_performance` (категории мониторинга, часы, прогулы,
звонки) · `with_office_traffic`, `office_traffic` (посещения, брони, календарь) · `rost_info`, `with_TRost`,
`structure_x_rost` (заявки T-роста) · `hub · 0 колонки` (есть ли все колонки источников) · `structure_x_vacancy`
(снимок вакансий) · `hub · 1 структура` (`teampulse_hub_cal`, пути юнитов, `teampulse_hub_unit`) · `hub · 2 логины и AI` ·
`hub · 3 справочник и ряды` (`teampulse_hub_series`) · `hub · 4 разрезы` (`teampulse_hub_mix`, `_prof`, `_pfd`) ·
`hub · 5 переходы` (`teampulse_hub_trf`, `_trfe`) · `hub · 6 вакансии и meta` · `hub checks` · `to click`.

## Узлы, срезы, периоды

- **Узел** — юнит нынешней структуры (последний месяц). Ряды узла — по всему его поддереву; человек, переехавший в
  другой юнит, едет туда со своей историей. Путь юнита — `teampulse_hub_unit.path_rk` (ключи через `|`). Узел
  `<юнит>:d` в `teampulse_hub_trf` — «напрямую в юните» (люди в самом юните, без подразделений).
- **Срез** (колонки во всех таблицах людей): `paint_cd` покраска HQ / Line / Support · `it_cd` IT / Digital / NonIT ·
  `staff_cd` Штат / Не штат · `act_cd` тип численности целиком (по умолчанию в отчёте — «Активная», без подрядчиков).
  Датасет фильтрует их в `cond()`. Вакансии и AI — не люди: срезы на них не действуют.
- **Периоды** (`teampulse_hub_cal`): `lm` — последний месяц данных (может быть неполным), `dt` — дата данных,
  `cm` — последний закрытый месяц, сетка — с января прошлого года. «С начала года» = январь..`cm`.
  Численность — на конец месяца (у `lm` — на `dt`), события — за месяц по дням.

## Таблицы и контракт с датасетом

Датасет читает эти колонки. Переименовать или убрать колонку — значит менять датасет; новая колонка без датасета
просто не видна. Необязательные колонки датасет берёт «матчером» (`COLUMNS('^имя$')`): их нет — нули/пусто.

| Таблица | Зерно | Колонки |
|---|---|---|
| `teampulse_hub_meta` | 1 строка | last_month data_dt grid_start n_months ytd_idx root_rk def_rk built_at schema_ver |
| `teampulse_hub_unit` | узел | unit_rk parent_rk unit_lvl unit_nm kids_cnt path_rk head_login head_nm |
| `teampulse_hub_series` | узел × месяц × срез | hc_cnt act_cnt avg_cnt hire_cnt hco_cnt fire_cnt reg_cnt nreg_cnt tin_cnt tout_cnt pnor_cnt plow_cnt phig_cnt pgry_cnt wday_amt ovis_amt gapr_cnt gdec_cnt bk_amt bkv_amt vsv_amt hwd_amt hov_amt ab25_cnt ab5_cnt we25_cnt we5_cnt t23_cnt t35_cnt t5_cnt hrs_amt hrn_cnt tlk_amt |
| `teampulse_hub_mix` | узел × срез × разрез × значение | mx_key mx_val mx_n (ключи — ниже) |
| `teampulse_hub_prof` | нижний юнит × срез × сочетание разрезов | pf cnt |
| `teampulse_hub_pfd` | разрез × значение | k v i |
| `teampulse_hub_trf` | узел × месяц × вид × срез × флаги | trf_kind fu fa fp fi fs in_ok cv_k sp_cd fsp trf_cnt (+ x_* пустые) |
| `teampulse_hub_trfe` | событие × узел, 13 мес. | детализация переводов (в отчёте сейчас не показывается) |
| `teampulse_hub_vacancy` | узел × месяц × разрезы вакансии | channel search_reason cand_lvl position_lvl specialization status ttf_d vac_open_cnt vac_close_cnt vac_new_cnt vac_ttf_days vac_ttf_cnt |
| `teampulse_hub_ai` | узел × месяц | ai_wau ai_pen ai_pen_co |

Ключи `mx_key`: численность последнего месяца по разрезам `g a e t gr s c o w r sp tc rg ws mh`; увольнения с начала года
`xr xq xi xp xt xg xs xsp xtc`, по инициатору и месяцу `xim`, по специализации и месяцу `xsm`; найм с начала года
`hk hch hg hsp`; численность по специализации на начало/конец `sp0 sp1`; средний возраст по разрезам `es en`;
T-рост `rm rq rs`; посещения и брони по городам `oc ocp ocl ocpl ov ob`; календарь посещений `dw do`.
Профиль `pf` = «номер.номер.….номер:возраст» по разрезам `g a t gr s c tc o w r sp rg` (номера — из `teampulse_hub_pfd`).

## Метрики — как считаются

| Метрика | Формула (ноутбук → датасет → чарт) |
|---|---|
| Численность | люди на конец месяца: последняя строка человека в месяце (`rn = 1`) и не уволен в этот день (`hc_total_cnt`) |
| ССЧ | (численность на конец прошлого месяца + на конец этого) / 2 — `avg_cnt` |
| Найм | найм в компанию (`hire_flg`) + при выбранном типе «Активная»: из учебной группы в боевую и стажёр в штат (`in_ok = 0`, вид `cv_k` c / s) |
| Отток | `fire_flg` за месяц; нежелательные — `regrettable`, желательные — `non_regrettable` |
| Текучесть месячная | отток месяца ÷ ССЧ месяца × 100; в таблице подразделений — значение последнего закрытого месяца |
| Текучесть накопительная | сумма месячных с января |
| HQ-текучести («Как уходит HQ?») | те же формулы на активной численности HQ, без целей; сравнение — с прошлым годом |
| Переводы | как мастер-отчёт: строка дня с флагом. «В» — флаг юнита своего уровня `lvlN_mngt_unit_in_trsf_flg` или (при фильтре по этому срезу) флаг смены типа / покраски / IT / штата; кандидаты и стажёры в «в» не идут. «Из» — то же с `out`, без увольнений; последний день месяца — следующий месяц. Дневные строки сотрудник × день × путь юнита схлопнуты, флаги 0/1 |
| Водопад | на начало + найм + переводы в − отток − переводы из = на конец; «прочее» должно быть 0 |
| Движение по специализациям | переводы — только флаг юнита уровня узла (`fu`); смена специализации/среза без перевода — «Внутри юнита» (`tci` / `tco`) |
| Мониторинг | категория перформанса (норма / недоработка / переработка / не размечено) — только у численности на конец месяца; без записи — «не размечено». Сумма категорий = численность |
| Средняя рабочая активность | часы в день: сумма часов по плановым рабочим дням ÷ их число, среднее по людям с часами |
| Средняя доля звонков в Толк | часы звонков ÷ часы работы × 100 (взвешено по часам) |
| Посещаемость | посещения офиса ÷ рабочие дни × 100 |
| T-рост | заявки HQ без стажёров и черновиков, актуальная версия; решение — в месяц итога (`finish_month`); юнит — человека в месяце начала |
| Вакансии | открытые — в работе на конец месяца (группа «Согласованные»), по всем каналам; закрытые — `close_flg`, только каналы из списка; новые — согласованы в месяце |
| Срок закрытия | медиана: срок вакансии = дни от первого согласования до закрытия без дней в Hold (`ttf_d`); за месяц — по закрытым в месяце, за период — по всем вакансиям периода |
| Доля джунов | закрытые джунами ÷ закрытые с начала года |
| AI | проникновение = WAU ÷ численность того же месяца; только по месяцам |
| Средний возраст | по людям на последний день данных (профили), в срезе — по людям среза |
| Пересечения разрезов | по профилям: сумма `cnt` строк, где совпали выбранные значения; больше 40 000 строк в ответе — оценкой |
| Источник найма | `source_type_nm` со дня найма (поле `fields` с `at_hire: True`), пусто в день найма — «-» |

## Проверки

1. **`hub checks`** (последний gp-параграф перед выгрузкой) — каждая строка одно число. `FAIL` у обязательной —
   выгрузка не идёт. Главные: корень = источник по численности, увольнениям, перформансу; профили = численность;
   мониторинг = численность; источник найма со дня найма = 0; без повторов ключа «узел × месяц × срез».
2. **Файл 5** — запросы для сверки с мастер-источником на одном подразделении и месяце (параметры в блоке `p`):
   водопад, мониторинг по покраске, месячная текучесть, медиана срока, повторы строк источника, переводы по
   специализациям, профили и возраст, источник найма. Ожидаемое — в комментарии к каждому запросу.
3. Отчёт: сверять число на одной вкладке, одном подразделении, одном месяце, тех же фильтрах. Сначала численность,
   потом события, потом доли.

## Как отлаживать

- Меняй SQL параграфов ноутбука; имена и колонки выходных таблиц `teampulse_hub_*` сохраняй (контракт выше). Нужна
  новая колонка или ключ `mx_key` — запиши, что датасету нужно её читать.
- Диалект ноутбука — Greenplum 6 (PostgreSQL 9.4): нет `array_position`, `group by all`, `distinct on` есть. В
  датасете — ClickHouse 24.8 + Jinja Proteus.
- Логина, ФИО, табельного, ключей и имён юнитов в выводы для обсуждения не выноси — только счёт и суммы.
- Литералы конкретных юнитов (rk, имена) в ноутбук не вписывай — ключи берутся из структуры.
- После правки — ноутбук целиком (с первого параграфа, меняется `build_all_metrics`), `hub checks` без FAIL, затем
  запросы файла 5 на контрольном подразделении.
