# Объединение дашбордов Proteus в концепцию TeamPulse Hub

**Дата:** 07.10.2026
**Контекст:** сравнение двух документов
— `team-pulse_бизнес-анализ.md` (дашборды Proteus 34661 УС / 34136 HQ)
— `team-pulse-hub_бизнес-анализ.md` (интерактивный прототип TeamPulse Hub)
и ответ на вопрос, как дашборды объединяются в концепцию Hub.

---

## 1. Концептуальное сравнение

| Параметр | Дашборды Proteus (34661 УС / 34136 HQ) | TeamPulse Hub |
|---|---|---|
| Роль | Два отдельных отчёта под разные уровни | Один борт, уровни переключаются фильтром `paint` (HQ/Line/Support) |
| Модель данных | Реальные витрины (GP/ClickHouse): `ys_all_last_day_ottok_naym`, `atributy_nayma` и др. | Мок-данные (`data.js`), целевая архитектура в `SOURCES.md` |
| Структура | ~8 блоков на два дашборда | 7 блоков + OnePager + «Пульс команды» |
| Сравнение | база / YoY / план-факт | база из фильтров / KPI / MoM·YoY |
| Число графиков | 86 + 103 (перегруз) | лаконично, 167 проверок читаемости |

**Суть объединения:** Hub — не «третий отчёт», а **надстройка-агрегатор**, которая
заменяет оба дашборда. Блоки дашбордов перераспределяются в 7 блоков Hub, а
HQ/УС-специфика включается фильтрами и под-вкладками.

## 3. Пробелы — что из дашбордов ещё не в Hub (кандидаты на добавление)

1. **План-факт найма** (в работе/готово/backlog/холд/просрочка, доля закрытых) — сильная
   УС-функция, в Hub только вакансии + воронка.
2. **Каналы привлечения** (`mapping_channel_name`) — где берём людей.
3. **Доля джунов в найме, вакансии джунов** — качество и риск воронки.
4. **Найм по грейдам** (HQ) — разрез найма.
5. **Отток по инициатору** (сотрудник/работодатель/другое, `fire_initiative`) — Hub
   разбирает только причины + regret.
6. **Полный ревью-разбор** (динамика оценок «сигарета/пончик», улучшение/ухудшение) —
   в Hub лишь low_perf/underwork.
7. **T@T карьерного роста** (время до повышения).
8. **Качество бронирования офисов** (брони без посещений и т.д.).
9. **Регионы** — география численности/найма.
10. **AI-метрики** (проникновение AI, WAU) — самый заметный разрыв: у Hub есть «Пульс»
    и AI-плашки, но нет метрик проникновения.

---

## 4. Как объединить (дорожная карта переноса)

1. **Блоки дашбордов ложатся в 7 блоков Hub по матрице выше.** УС/HQ-специфика не
   создаёт новые отчёты, а становится:
   - фильтром `paint` (HQ-блоки «Рост», «Посещаемость», «AI»; УС-блоки «Ревью»,
     «План-факт найма»);
   - под-вкладками внутри блока (план-факт найма → блок 4; ревью → блок 6;
     качество бронирования → блок 7).
2. **Закрыть пробелы метриками из `REVIEW_2.0.md`:** план-факт, каналы, доля джунов,
   инициатор оттока, T@T, регионы, AI-проникновение — производные не требуют новых
   данных и добавляются через `derived`/новые витрины.
3. **Мост данных:** реальные витрины дашбордов (`ys_all_last_day_ottok_naym`,
   `atributy_nayma`, `vacancy_daily_for_digest*`, `junior_ratio_hr_digest*`,
   `plan_fact_tf_rabota`, `review_*`, `ys_all_fire_initiative`) — это ровно те
   источники, которые в `SOURCES.md` лягут вместо моков `data.js`. То есть
   **дашборды = реальные данные для Hub**, а не конкурирующий продукт.
4. **Единая «шапка»-дайджест:** OnePager + «Пульс команды» в Hub уже реализуют
   рекомендацию из анализа дашбордов («свести ключевые метрики в единый сводный
   KPI-блок»).
5. **Дальнейшая судьба дашбордов:** после того как Hub станет источником правды,
   дашборды 34661/34136 либо остаются «детальным» слоем (переход с блока по ссылке
   «Детальный дашборд»), либо вытесняются. Это продуктовая развилка — решать
   с заказчиком.

---

## 5. Резюме

- **Концепция уже задана:** Hub спроектирован как единый борт вместо УС + HQ,
  разделение — фильтрами, а не отчётами.
- **~70% контента дашбордов** покрыто блоками 1–7; OnePager/«Пульс» переосмысливают
  HR-дайджест.
- **~10 пробелов** (план-факт, каналы, джуны, грейды найма, инициатор оттока, ревью,
  T@T, бронирование, регионы, AI-метрики) — кандидаты на перенос в под-вкладки/разрезы.
- **Реальные витрины дашбордов** становятся источником данных для Hub (мост к
  `SOURCES.md`).
- **Развилка:** дашборды остаются «детальным» слоем или вытесняются Hub — решает
  заказчик.
