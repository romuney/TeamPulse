# Тестовая поставка TeamPulse

Эта папка предназначена для экспериментов с раздельными чартами. Владелец разрешил
публиковать её в main, сохраняя боевую `../Поставка — TeamPulse Hub` и общие исходники
без изменений. Для задач в этой области не запускай общий `proteus/build.js`:
он пишет и боевой чарт. Запускай локальный `build.cjs`, затем проверяй git diff.

Исходники эксперимента — `src/`. `patches.cjs` накладывает точечные изменения в памяти
на общие исходники; при несовпадении единственной точки вставки сборка должна падать.
Не редактируй сжатые файлы 3 и 3а вручную. Зависимости берутся из `../proteus/node_modules`.

Инварианты:

- Обычная поставка — golden source: не менять расчёты, доступ, фильтры, правила
  `has`/`isStub` и SQL ради скорости или исчезновения меток. Полная раздельная
  модель и итоговые экраны сверяются с обычным собранным чартом.
- «В разработке» — устаревший статус для этой поставки. Ожидание ответа и отсутствие
  данных обозначаются отдельно; отсутствие не заменяется нулём или условной цифрой.
- До aux доступны факты core, но не окончательные сравнения и выводы: база сравнения
  может изменить вердикт. Полные детали ждут и собственные части, и aux.
- После первого показа core явно запросить недостающие части: их HELLO мог прийти
  до появления главного чарта. Не ждать очередного фонового опроса.
- Краткая сводка не заменяется при фокусе клавиатуры внутри неё или после прокрутки:
  переход к полному отчёту — через кнопку готовых подробностей.
- Упаковывать разрешено только текст CSS/HTML с точным восстановлением. Исполняемый
  код остаётся обычным ES5; декодирование не должно исполнять строки.

- Первый core нельзя задерживать фоновым таймером. При фильтрации ждём части активной вкладки.
- Последнее намерение фильтра сохраняется после pending; поздний чужой core не применяется.
- Переход на другую вкладку пересматривает готовность. Возврат к уже показанному выбору
  отменяет ожидание другого выбора и не зависает на дедупликации core.
- Эхо фильтров и отметка сборки данных должны совпадать у объединяемых частей.
- Догрузка сохраняет оболочку, фокус, выделение, настройки и место чтения.
- После прокрутки предварительные графики не заменяются другим экраном без явного клика;
  кнопка готовых подробностей остаётся в видимой области.
- Нельзя выдавать отсутствующие разбивки за нули или показывать демонстрационные данные.

Проверки: `node tests/scheduler.cjs`; `python tests/fixture_server.py` и в другом
терминале `python tests/browser.py`. Браузерные проверки используют реальные сборки,
синтетические ответы и изолированные iframe. Для оценки SQL/боевого объёма нужен
отдельный стенд, эти проверки его не заменяют.

Дополнительно: `node tests/text-codec.cjs` проверяет точное восстановление текста;
`python tests/parity.py` на fixture_server сверяет модель, готовность и все вкладки
с обычной поставкой на расширенных данных и явных нулях. Для браузерных тестов
используется Chromium из Playwright; `CHROMIUM_PATH` — необязательный путь для browser.py.
