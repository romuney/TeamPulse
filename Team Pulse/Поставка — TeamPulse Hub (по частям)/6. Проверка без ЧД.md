# Повторная проверка скорости без передачи ЧД

Необязательная справка для будущей точечной диагностики. Текущая поставка уже
исправлена по собранным данным и проверена локально; новый корпоративный прогон
не является условием её установки и сейчас не требуется.

Скриншоты, видео, DOM-тексты, значения показателей, названия и идентификаторы
подразделений остаются внутри корпоративной среды. Они не нужны в передаваемом пакете.
Сравнение значений выполняется локально; наружу — только результат сравнения,
число проверенных элементов и обезличенные времена.

Старый отчёт остаётся эталоном. Ссылки, конкретные подразделения и учётная запись
используются только внутри корпоративной среды. В результатах — OLD/NEW и A/B.
Сохранённую конфигурацию, SQL и доступ не менять.

## Повторяемые сценарии

По три парных запуска OLD/NEW с чередованием порядка: открытие, повторное открытие,
смена подразделения, применение фильтра. У обоих отчётов одинаковые данные и настройки.
Первый вход в браузере не называть холодным серверным кэшем без подтверждения.

Отдельно проверить локально:

- Огоньки сменяются обычным One-pager; нет четырёх квадратов, упрощённой таблицы,
  неоформленной разметки и дополнительного полноэкранного спиннера.
- Готовые строки доступны до остальных частей; раскрытие строки и настройки отвечают.
- Подвкладка «Стримы» появляется после people, когда у эталона есть стримы.
  Её таблица и текст главы совпадают. Повторить для A → B без стримов → A со стримами.
- Для каждой вкладки пройти все доступные подвкладки; сравнить значения, MoM/YoY,
  оценки, базу, подписи и выводы локально. Экспортировать только количества
  проверок и расхождений, тип расхождения и обезличенный сценарий.
- Фокус, раскрытая строка и положение чтения сохраняются при догрузке.
- При A → B → A ни один промежуточный экран не смешивает новый заголовок со старыми
  данными. Сигнатуры и версии сравнить локально, экспортировать только boolean.
- Непришедшая часть не превращается в нули; сообщение об ошибке не зависает навсегда.

Для визуальной проверки достаточно наблюдений корпоративного агента с результатом
pass/fail/not_checked и методом проверки. Отсутствие записанных ошибок не доказывает
отсутствие визуального дефекта. Если инструмент не умеет проверять кадры локально,
пометить visual check как not_checked, не запрашивать выгрузку изображения.

## Исправление методики времени

1. На каждом сценарии t0 — фактический переход по ссылке либо клик «Применить»/
   «Открыть», а не открытие окна настроек. Одинаковый критерий для OLD и NEW.
2. Для каждого HTTP-запроса связывать начало, ответ и завершение по CDP requestId
   в пределах одного запуска. Повторяющийся URL не является ключом.
   В экспорт requestId заменить локальным operation_id, без URL, query string и тела.
3. Для async 202 сохранить отдельные HTTP-этапы и объединяющий operation_id.
   Роль результата выводить из локального подтверждённого соответствия, иначе unknown.
4. Проверить start ≤ response ≤ end и совместимость длительностей до расчёта медиан.
   Не присоединять Resource Timing предыдущего открытия к запросу смены подразделения.
5. Различать начало вычислений, завершение применения данных и возможность отрисовки.
   Событие run — начало; ran/applyEnd — завершение JS, а не доказанный показ кадра.
   frameOpportunity — rAF с последующей задачей; это тоже прокси, не пиксельное измерение.
6. Если paint в OLD недоступен, показать его прокси отдельной колонкой. Не выдавать
   сравнение разных прокси за точный процент ускорения видимого интерфейса.
7. Измерить задержку реакции на реальный клик по готовой строке во время фоновой
   загрузки. Первый экран, сразу заблокированный долгим JS, не равен готовности к работе.
8. TTFB не равен SQL; отсутствие browser cache-hit не доказывает повторный расчёт на сервере.

## Обезличенные клиентские фазы новой сборки

Выполнить в iframe главного чарта сразу после сценария. Скрипт только читает
фиксированный белый список; не экспортировать весь window, __pvtState или TP_REAL.

~~~js
(() => {
  const s = window.__pvtState && window.__pvtState.tp;
  const p = s && s.perf;
  const parts = window.TP_PARTS;
  const number = v => typeof v === 'number' && Number.isFinite(v) ? v : null;
  const phases = ['merge', 'model', 'data', 'render', 'nav'];
  return JSON.stringify({
    version: p ? number(p.version) : null,
    originEpochMs: p ? number(p.originEpochMs) : null,
    frames: p && Array.isArray(p.frames) ? p.frames.slice(-40).map(f => ({
      id: number(f.id),
      intent: number(f.intent),
      intentAtMs: number(f.intentAtMs),
      startMs: number(f.startMs),
      applyEndMs: number(f.applyEndMs),
      frameOpportunityMs: number(f.frameOpportunityMs),
      partsReady: number(f.partsReady),
      superseded: f.superseded === true,
      phasesMs: Object.fromEntries(phases.map(k => [k, number(f.phasesMs && f.phasesMs[k])]))
    })) : [],
    pending: Boolean(s && s.pending),
    mixed: parts ? Boolean(parts.mixed) : null,
    missingPartsCount: parts && parts.have
      ? ['people', 'flow', 'aux'].filter(k => !parts.have[k]).length : null,
    latePartsCount: parts && Array.isArray(parts.late) ? parts.late.length : null,
    temporaryLayoutPresent: Boolean(document.querySelector('.tp-quick-table,.tp-boot'))
  }, null, 2);
})()
~~~

Все времена кадров — миллисекунды от originEpochMs. intentAtMs — момент отправки
намерения из отчёта, не замена внешнего t0 клика. Кадр superseded не считать
видимым актуальным результатом. Пустые значения означают отсутствие измерения.

merge — сбор строк; model — разбор модели; data — сборка API данных;
render — интерфейс с навигацией и layout; nav — часть render, их нельзя складывать.
До startMs могут оставаться передача ответа, запуск песочницы и подготовка кода.
Эти фазы не измеряют SQL или всю задержку платформы. Хранится только 40 последних кадров.

## Передаваемый пакет

- report.md: наблюдения, методы проверки, ограничения и таблицы сопоставимых времён.
- timings.csv: run_id, вариант, сценарий, повтор, метод и времена отдельных вех.
- network.csv: локальные operation_id, роль, HTTP-метод, статус, времена и размеры.
- diagnostics.json: только вывод белого списка выше, с локальным run_id.
- checks.csv: run_id, имя проверки, pass/fail/not_checked, число сравнённых элементов,
  число несовпадений, обезличенное описание.

Не включать сырые HAR/trace, консоль целиком, ответы датасетов, строки таблиц,
тексты подсказок, параметры фильтров, пути к корпоративным отчётам и изображения.
Performance-профиль можно изучить внутри среды и передать агрегированные длительности
фиксированных фаз; исходный профиль может содержать ЧД и наружу не требуется.
