# TeamPulse Hub

Интерактивный HTML-макет верхнеуровневого HR-борда для руководителей.

## Запуск

Из папки проекта:

```bash
python3 -m http.server 8765
```

Открыть: http://localhost:8765

Прямое открытие `index.html` тоже возможно, но локальный HTTP-сервер надёжнее.

## Сдача одним файлом

```bash
node build.js        # → index.standalone.html, ~282 КБ
```

Собирает всё в один self-contained HTML: стили и скрипты встроены, внешних ссылок нет.
Та же сборка кладёт копию в корень репозитория как `index.html` — это точка входа
GitHub Pages, чтобы короткий адрес сайта открывал отчёт сразу.
**Библиотек в проекте нет вообще** — вся графика рисуется на голом SVG. Интернет нужен
только для шрифта Inter в режиме разработки; в автономном файле эта ссылка вырезается,
и шрифт деградирует до Helvetica/Arial.

## Возможности

- OnePager: 7 блоков, 19 метрик, KPI, MoM/YoY, спарклайны, раскрываемая динамика
- Изменение подписано месяцем сравнения («+3 к маю»), карточки KPI полосы
  выровнены по строкам даже при переносе заголовка
- Детальные вкладки с таблицей −1/−2, временным drillRoot и выбором подразделения
- У каждой таблицы с каретками есть общая: раскрывает и сворачивает всё одним
  кликом — дерево подразделений, стримы со специализациями, графики метрик блока
- Состав численности десятью разрезами на четырёх вкладках плюс конструктор
  «Свой срез»: матрица «строки × колонки» из любых двух атрибутов
- Стримы двухуровневые: каретка раскрывает стрим до специализаций внутри него
- Клик по строке разбивки берёт срез: карточки, таблица подразделений и соседние
  разбивки пересчитываются по этой категории
- Разбивки по атрибутам и причинам увольнений — таблицами с полосами в ячейках
- Отток и текучесть тремя панелями: факт в людях, месячная, накопительная с января
- Ось значений всегда от нуля; при подписанных значениях ось Y не рисуется
- С базой сравниваются только относительные метрики; у абсолютных стоит пометка
  «не сравнивается»
- Где утверждён KPI, метрика сравнивается с целью, а не с базой — базы там нет
  ни в карточке, ни в таблице, ни на графике
- Все фильтры пересчитывают и команду, и базу сравнения
- Персональная ссылка сохраняет фильтры, активный раздел, срез состава и оси конструктора
- Первый вход показывает справку «Как читать отчёт»
- Адаптив для планшета и телефона, клавиатурная навигация, печатная версия

## Файлы

Разбивка по слоям, потом по экранам — чтобы правка одного экрана не требовала читать всё.

- `data.js` — оргструктура, метрики, моковые данные, агрегации, формулы текучести
- `draw.js` — рисование на голом SVG: линии, бары, дивергент, панели, водопад, воронка
- `ui.js` — общие элементы: KPI-карточки, чипы, `barTable` (таблица с полосами в ячейках)
- `insights.js` — отбор фактов по порогам
- `screens/_block.js` — каркас детальной вкладки и реестр экранов
- `screens/<блок>.js` — по файлу на экран: `structure`, `movement`, `turnover`, `hiring`,
  `tgrowth`, `monitor`, `office`, `onepager`
- `app.js` — состояние, URL, роутер, события
- `styles.css` — дизайн-система и адаптив
- `smoke.js` — прогон всех экранов и 167 проверок правил без браузера: `node smoke.js`
- `build.js` — сборка в один файл: `node build.js`
- `SPEC.md`, `PROGRESS.md`, `AGENTS.md` — спецификация, журнал итераций, правила работы
- `DESIGN_SYSTEM.md` — дизайн-система одним файлом: токены, компоненты, правила
  визуализации, подсказки, доступность, тон. Пишется не для этого макета, а для
  любого следующего отчёта: файл рассчитан на подачу нейросети как промпт, чтобы
  сгенерированный HTML с другой раскладкой выглядел частью того же продукта.

Файл экрана не пишет разметку сам: только сбор данных и вызовы `draw.js` / `ui.js`.
Так общие элементы не расходятся между экранами.
