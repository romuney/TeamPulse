## ЧТО УДАЛИТЬ из дашборда 2.0

Блоки и графики, которых **нет в каталоге** HQ/УС — они либо выдуманы для макета,
либо дублируют реальные данные вымышленными. Реального источника под ними нет
(в коде помечены как мок).

### 1. Воронка найма (блок `hiring`, под-вкладка «Воронка»)
- Коэффициенты этапов `0,63 / 0,49 / 0,41` **выдуманы** (комментарий в `hiring.js`).
- В каталоге HQ/УС **воронки найма нет** — есть только открытые/закрытые вакансии
  и каналы привлечения.
- **Решение: удалить** (или заменить на реальный источник, если появится).

### 2. Календарь посещаемости (блок `office`, под-вкладка «Календарь»)
- **Решение: ОСТАВИТЬ** — календарь хочется добавить/сохранить.
- ⚠️ Подневные отметки и привязка людей к офисам сейчас **сгенерированы**
  (сноска `MOCK_NOTE`) — до показа заказчику подключить **реальный источник**
  подневных данных, иначе календарь будет показывать вымышленные цифры.
- В каталоге посещаемость — по месяцам, по грейду, по юнитам, по городам;
  календарь — **дополнение**, которого в исходных дашбордах нет, но оно полезно.

### 3. Рейтинг офисов (блок `office`, под-вкладка «Рейтинг офисов»)
- Привязка сотрудников к офисам **сгенерирована** (`MOCK_NOTE`).
- В каталоге есть «офисы по городам и нарушения бронирования» — но это про города,
  а не вымышленный рейтинг.
- **Решение: удалить** до появления реальных данных по офисам.

### 4. «Лоу-перформеры» (блок `monitor`, метрика `low_perf`)
- **Понятия «лоу-перформеры» в компании НЕТ** (по словам владельца дашборда).
- Метрика `low_perf` выдумана для макета.
- **Решение: удалить** метрику и её график. Реальный мониторинг работы — из каталога
  (раздел 9): **недоработка, переработка, % звонков в толк, прогулы, работа в выходные**.
  На их основе пересобрать блок `monitor` (см. «Что добавить»).

### 5. Масштаб мок-данных (найм ~100 человек и другие порядки чисел)
- Все ряды борта генерируются seed'ом, поэтому «найм 100 человек», численность
  и отток — **нереальные порядки чисел**.
- Пока борта на моках, значения нельзя использовать ни для вывода, ни для KPI.
- **Решение: не опираться на числа мока**; подключить реальные данные
  (хранилище/источник из каталога), прежде чем показывать заказчику.
