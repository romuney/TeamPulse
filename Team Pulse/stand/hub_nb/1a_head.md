# 1а. Helicopter — изменённые параграфы (22.10, поставка 58)

Для ноутбука, который уже стоит: вариант Адель «TeamPulse Hub_20.10_final» с правками поставок 54 и 56.
Новая установка — целиком файл 1, в нём то же самое.

## Что меняется

Таблицы `teampulse_hub_*` собирают параграфы gp, а не Python-параграф `build_hub_detect`.

**Почему падало.** Python здесь данных не гонял. Каждый шаг — SQL, он выполняется внутри GP, а Python только
отправлял текст запроса и ждал ответа. Но в одном параграфе он ждал больше ста запросов подряд: ряды и разрезы —
по запросу на каждый месяц, переходы — 22 прохода по дневному источнику. Параграф упирался в таймаут.

**Что стало.**
- Восемь параграфов gp и один короткий Python. Каждый шаг виден отдельно: если что-то упадёт, видно где.
- Тяжёлые шаги — за один проход. Ряды и разрезы — 4 запроса по нужным колонкам вместо ~55 запросов, которые
  тащили все ~80 колонок источника. Дневной источник читается один раз вместо 22.
- Даты в SQL — не литералами. Последний месяц и дата данных лежат в `teampulse_hub_cal`. Дневной источник
  отсекается по `current_date`: по ней GP режет партиции.
- Таблицы для отчёта — те же. На стенде они сверены построчно с прежней версией, вместе с типами колонок; на
  них датасет 2а сходится с правдой по людям.
- Python остался в параграфе «hub · 2 логины и AI». Там сначала нужно проверить, есть ли источник логинов и AI, —
  SQL так не умеет. Это два коротких запроса.

На стенде (источник ×25, 6 млн строк по дням): было {{T_PY}} с и {{Q_PY}} запросов к GP, стало {{T_SQL}} с и
{{Q_SQL}} запросов.

## Как поставить

1. **Выключить** — не удалять, это откат: `structure_x_vacancy`, `EXEC structure_x_vacancy`, `build_hub_detect`,
   `EXEC build_hub`, `hub checks`. Если включён `build_hub` — его тоже.
2. **Добавить** перед `to click` девять параграфов по порядку. Код — ниже, каждый параграф целиком.

   | № | Параграф | Тип | Что делает |
   |---|---|---|---|
   | 1 | hub · 0 колонки | gp | проверяет колонки источников; нет колонки — ошибка со списком |
   | 2 | structure_x_vacancy | gp | снимок «структура × вакансии», как делал Python |
   | 3 | hub · 1 структура | gp | последний месяц, дата данных, пути юнитов, узлы |
   | 4 | hub · 2 логины и AI | python | логины руководителей и AI, если источник есть |
   | 5 | hub · 3 справочник и ряды | gp | `teampulse_hub_unit`, `teampulse_hub_series` |
   | 6 | hub · 4 разрезы | gp | `teampulse_hub_mix` |
   | 7 | hub · 5 переходы | gp | `teampulse_hub_trf` |
   | 8 | hub · 6 вакансии и meta | gp | `teampulse_hub_vacancy`, `teampulse_hub_meta`, число строк таблиц |
   | 9 | hub checks | gp | проверки; не сошлось — ошибка, и выгрузки нет |

3. `to click` не меняется — он остаётся последним.
4. Запустить ноутбук с параграфа «hub · 0 колонки».

**Что должно получиться:**
- «hub · 0 колонки» — строка «колонки на месте»;
- «hub · 6 вакансии и meta» — число строк семи таблиц;
- «hub checks» — таблица проверок и строка «таблицы TeamPulse Hub сходятся».

Если параграф упал, пришлите в чат его название и текст ошибки. Если всё прошло — время каждого параграфа hub.

**Откат:** выключить новые параграфы и включить прежние пять.
