# TeamPulse Hub — ноутбук сборки (копия TP 2.0 под отчёт)

Тот же конвейер, что TP 2.0: источник по дням → человек × месяц × юнит → перформанс, посещаемость,
T-рост → `hr_structure_overall` для других отчётов. Плюс таблицы **`teampulse_hub_*`**: в них
посчитано всё, что нужно отчёту TeamPulse Hub. Виртуальный датасет отчёта не кешируется, поэтому
на каждый запрос он только выбирает узлы ответа (выбранный юнит, базу и три уровня под ним) и
склеивает строки — без дерева, без склейки копий, без истории в нынешней структуре.

**Что изменено против TP 2.0** (подробно — «Предложения — физическая таблица под датасет.md»):

1. `build_all_metrics` — численность на последний календарный день месяца: ушедшие в месяце в
   численность его конца больше не входят. Признак `last_row_flg` — одна строка человека в месяце.
   Ключи уровней `lvl1_rk … lvl11_rk` выводятся рядом с именами.
2. `with_TRost` — заявки сначала суммируются по человеку и месяцу: строки больше не двоятся.
3. Перформанс, посещаемость, T-рост — к одной строке человека в месяце (`last_row_flg = 1`).
4. `EXEC build_all_metrics` — сырые коды покраски и IT (`paint_cd`, `it_cd`) для срезов отчёта.
   В `hr_structure_overall` они не идут: его колонки не меняются.
5. Новые параграфы: `build_hub`, `EXEC build_hub`, `hub checks` и выгрузка четырёх таблиц.
6. Убраны выключенные и отладочные параграфы (`get_hr_structure`, `join_structure_combos`,
   `Untitled …`, `select …`, `tst`).

**Таблицы для отчёта** (выгрузка — параграф `to click`, база `prod_proteus`):

| Таблица | Строка | Что в ней |
|---|---|---|
| `teampulse_hub_meta` | одна | последний закрытый месяц, начало сетки, корень, юнит по умолчанию |
| `teampulse_hub_unit` | узел нынешней структуры | родитель, уровень, имя, число подразделений, путь ключами |
| `teampulse_hub_series` | узел × месяц × срез | численность, активная, ССЧ, найм, увольнения, regret, переводы через границу узла, мониторинг, посещаемость, T-рост — по всему поддереву |
| `teampulse_hub_mix` | узел × срез × разрез × значение | численность по атрибутам, увольнения с начала года по причинам, инициативе, стажу, грейду, стриму |

Срез — покраска × IT × штат: фильтры отчёта. История — в нынешней структуре: юнит переехал — его
прошлое едет с ним. ССЧ = (активная месяца + прошлого) / 2 по узлу и срезу.

**Порядок:** параграфы сверху вниз. `hub checks` до выгрузки: не сошлось — исключение, выгрузки нет.
