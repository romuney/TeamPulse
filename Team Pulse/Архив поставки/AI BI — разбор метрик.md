# AI BI — разбор метрик для вкладки «AI-инструменты»

26.10, правки (п. 9). Источник описания — `AI BI.md` (виджет AI-метрик: 5 вкладок, таблица `ai_digest_weekly`).
Сверено с тем, что отчёт получает сейчас: таблица ноутбука `teampulse_hub_ai` — подразделение × месяц: WAU,
проникновение подразделения и компании из месячного дайджеста `usr_mlpa.ai_bi_all_copilots_usage_digest_monthly`
(`avg_wau`, `avg_penetration_unit_pct`, `avg_penetration_company_pct`). Строк по людям и неделям в отчёте нет.

## Итог

| Категория | Что сюда попало |
|---|---|
| 1. Можно реализовать | тренд проникновения «команда против компании»; WAU и численность команды — **по месяцам** (в отчёте) |
| 2. Непонятна логика | воронка сообщений при классификации по выборке; неделя против месяца; разрезы конструктора по неделе |
| 3. Не хватает данных | частота использования, инструментов на человека, топ инструментов, топ задач, воронка сообщений, по покраске, стажёры, конструктор, всё по неделям |
| 4. Данные есть, нужна интерпретация | «покраска» AI-отчёта = IT-код отчёта; юнит в AI-выгрузке — имя, а не ключ; стажёр — флаг AI-выгрузки или тип численности |

## 1. Можно реализовать — сделано на вкладке

| Метрика AI BI | Поле | Что в отчёте |
|---|---|---|
| Тренд проникновения: команда против компании | `avg_penetration_unit_pct`, `avg_penetration_company_pct` | «Проникновение AI, %» — год к году, пунктиром — компания (было) |
| WAU · активные за неделю, пунктиром — численность команды | `avg_wau` | «Активные пользователи AI (WAU)» по месяцам; **26.10 добавлен пунктир «Численность команды»** — знаменатель проникновения источника (WAU × 100 ÷ проникновение), от него и считается доля |

Обе — по месяцам (в AI BI: «по месяцам — среднее WAU»). По неделям — после недельной выгрузки (п. 3).

## 2. Непонятна логика — вопросы

1. **Воронка сообщений.** «Не классифицировано = все сообщения Copilot/Nestor − классифицированные», но
   классифицируется только выборка (размер — в графике «Классификация сообщений»). Остаток тогда смешивает
   «не попало в выборку» и «не определён класс». Как считать: доля классифицированных в выборке или в сумме всех?
2. **Неделя или месяц.** Виджет показывает закрытую (предпоследнюю) неделю, отчёт — месяцы с текущим незакрытым.
   Для AI оставляем месяцы (как сейчас) или показываем последнюю закрытую неделю, как в виджете?
3. **Конструктор.** Частота и число инструментов — свойства человека за неделю. Разрез «частота × юнит» — по закрытой
   неделе или по среднему за месяц?
4. **`never_used_copilot_flg`** есть в строке данных, но ни в одном графике AI BI не используется. Нужен ли он отчёту?

## 3. Не хватает данных

Всё ниже считается из строк `ai_digest_weekly` (человек × неделя); в таблицах отчёта их нет.

| Метрика AI BI | Поля | Что нужно |
|---|---|---|
| Частота использования в неделю (0–7 дней) | `usage_days_in_week` | распределение людей по дням за закрытую неделю — по подразделению |
| Количество инструментов на человека (0 / 1 / 2 / 3 / 4+) | `tools` | число инструментов у человека → корзины — по подразделению |
| Топ инструментов | `tools` | активные пользователи по каждому инструменту — по подразделению |
| Воронка сообщений | `total_copilot_nestor_messages`, `total_tasks_messages` | суммы по подразделению за неделю + ответ на вопрос 2.1 |
| Топ задач в Copilot, Nestor IDE, Nessy CLI | `tasks`, `task_messages` | сообщения по классам задач — по подразделению |
| Проникновение по покраске с инструментами | `paint`, `tools` | численность, активные, проникновение по IT / Non-IT / Digital и инструменты в каждой |
| Стажёры: используют / нет, инструменты, частота | `is_intern_flg` | то же, что выше, по стажёрам |
| Конструктор (два разреза × численность / активных / проникновение) | всё выше | агрегат по подразделению × разрез × разрез |
| WAU и проникновение по неделям | `week`, `ai_usage_flg` | недельный ряд по подразделению |

Предложение: один параграф ноутбука «hub · 7 AI по неделям» — из `ai_digest_weekly` таблица «подразделение × неделя ×
разрез × значение: людей, активных» (разрезы: частота, число инструментов, инструмент, покраска, стажёр) и «× класс
задачи: сообщений». Подразделение — по ключу нынешней структуры (см. п. 4.2). Отчёт возьмёт закрытую неделю.

## 4. Данные есть, нужна интерпретация

1. **«Покраска» в AI BI — IT / Non-IT / Digital.** В отчёте это фильтр «IT-код», а «покраска» — HQ / Line / Support.
   Подпишем в отчёте «IT-код», чтобы не путать с покраской шапки. Подходит?
2. **Юнит в AI-выгрузке — `next_lvl_new_management_unit_nm`, имя, а не ключ.** Сшивка с деревом отчёта по имени
   ломается на одинаковых именах в разных ветках. Есть ли в `ai_digest_weekly` ключ юнита или ключ сотрудника
   (`person_id` = `mdm_employee_rk`?) — тогда юнит берём из структуры отчёта.
3. **Стажёр.** В AI BI — `is_intern_flg`, в отчёте — тип численности «Стажеры» (они не входят в «Активную»). Это одни
   и те же люди? Проникновение AI считается по HQ-численности — стажёры в неё входят?
4. **Расхождения с источником на несколько человек** (характеристики внутри недели присваиваются по-разному) —
   принимаем, как в AI BI; при сверке не считаем ошибкой.
