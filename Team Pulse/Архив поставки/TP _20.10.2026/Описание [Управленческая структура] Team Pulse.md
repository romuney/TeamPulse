# Описание ноутбука — Team Pulse

## Назначение
Dev-ноутбук **«NEW - [УС - отчет] Team Pulse»** — ETL-конвейер для HR-отчёта **Team Pulse** (УС = управленческая структура). Он строит витрины в **Greenplum** и выгружает их в **ClickHouse** (`prod_proteus.*`) для внешнего BI-дашборда. Расписание включено: ежедневно в 06:00.

## Источники данных
- **`usr_cross_data.hr_executive_proteus`** (Greenplum, ~15,1 млн строк) — основной источник: численность, найм, увольнения, переводы, атрибуты сотрудников, уровни УС (lvl1–lvl12).
- **`usr_cross_pub.cross_management_unit`** (DLH) — справочник подразделений (management_unit_rk → новое название).

## Структура и логика
Ноутбук разбит на 8 тематических блоков. Внутри каждого — повторяющийся паттерн: детальные SQL-таблицы → агрегаты → финальная витрина → выгрузка в ClickHouse.

### 1. Структура численности
- Ожидание готовности источника (`tables_wait`, DAL-проверка).
- Численность на конец месяца по уровням УС с атрибутами (специализация, тип занятости, стаж, возрастная группа).
- Разрез «Все / Штатные / ГПД» → выгрузка в ClickHouse.

### 2. Динамика численности
- Численность по месяцам, найм (в т.ч. переводы в БГ, стажёр→штат), отток (увольнения).
- Полный каркас месяц × тип × юнит.
- Входящие/исходящие переводы (`perevody_plus`/`perevody_minus`).
- Динамика активной численности и **водопад численности** (старт/конец, fire, hire, transfer_in/out) → выгрузка.

### 3. Водопад переводов
- Детализация переводов по типам (штатные / ГПД / все сотрудники) с приоритизацией флагов.
- Водопад переводов по transfer_type (Тип численности / УС / Тип трудоустройства) → выгрузка.

### 4. Отток накопительно, инициатива, причины
- Детальная таблица оттока (fire_reason, fire_initiative, стаж).
- Отток по инициативе (работник / работодатель / прочее).
- **Текучесть** (`tekuchest` = отток / среднесписочная численность), накопительно по годам.
- Причины оттока за текущий/предыдущий год, текучесть по причинам и юнитам → выгрузка.

### 5. Стаж + причины
- Отток и численность по стажу (`experience_group_nm`).
- Текучесть по стажу с ранжированием (до 1 года / 1–3 / 3–5 / 5–10 / свыше 10 лет).
- Финальная витрина (топ-3 причины по стажу) → выгрузка.

### 6. Атрибуты оттока
- Уволенные с атрибутами: стаж, пол, грейд, возраст, тип работы, тип компании, специализация, stream.
- Агрегаты по атрибутам за 12 мес / за год → выгрузка.

### 7. Изменения по подразделениям
- Численность, найм, отток, переводы по подразделениям.
- Расчёт «неприкреплённых» сотрудников (метрики родителя минус сумма детей).
- Прирост / прирост%, отток/найм/переводы/текучесть → выгрузка.

### 8. По специализации
- Численность, отток, найм по `employee_specialization_desc`.
- Отток/текучесть по специализации за год → выгрузка.
- Назначение владельцев витрин `prod_proteus.*`.

## Метрики
Численность (на конец месяца, по типам сотрудников), найм, отток, переводы входящие/исходящие, текучесть (накопительно по годам), причины оттока, инициатива оттока, стаж, атрибуты оттока (пол, возраст, грейд, специализация, тип работы), изменения по подразделениям, отток по специализации.

## Выходные витрины ClickHouse (`prod_proteus.*`)
`ys_all_last_day_ottok_naym`, `ys_all_dinamika_aktivnoy_chislennosti`, `ys_all_waterfall_chislennosti`, `ys_all_waterfall_perevody`, `ys_all_fire_initiative`, `initiative_reason_unit_tekuchest`, `experience_initiative_reason_unit_tekuchest`, `type_atributy_ottoka`, `type_atributy_ottoka_year`, `type_flg_izmeneniye_po_podrazdeleniyam`, `type_flg_stream_ottoka_year`.

## Визуализации
В самом ноутбуке графиков нет — он готовит витрины для внешнего BI-дашборда (водопады численности и переводов, динамика, накопленная текучесть).
