# TeamPulse Hub — SPEC (контракт макета)

## Цель
Один верхнеуровневый борт вместо нескольких TeamPulse (HQ-версия и версия по всей управленческой структуре).
Разделение обеспечивается не отдельными отчётами, а 4 управляющими фильтрами и персональными ссылками.

## Архитектура
index.html / styles.css / data.js / charts.js / app.js
Порядок: data -> charts -> app. ECharts из CDN. Без фреймворков.

## 4 управляющих фильтра
| Фильтр | Значения | Популяция | База сравнения |
|---|---|---|---|
| unit — подразделение | узел оргдерева | да | нет |
| paint — покраска | HQ / Line / Support / all | да | да |
| itSeg — IT-разрез | IT / nonIT / all | да | да |
| staffType — занятость | штат / не штат / all | да | да |

## ГЛАВНОЕ ПРАВИЛО — база сравнения
benchmarkPopulation(state) = все листья компании, прошедшие paint + itSeg + staffType,
БЕЗ ограничения по unit.
Подпись собирается автоматически: «вся компания» / «всё HQ» / «всё HQ IT» / «всё HQ IT штат».
Таргет OnePager = значение метрики на этой популяции.
Исключение: метрики с KPI (regrettable по HQ) сравниваются с KPI и помечаются тегом.

## Блоки и метрики
1. structure — Структура численности: hc_active, hc_total (int, flat)
2. movement — Движение: hire, attrition, transfer_in, transfer_out (int, flat)
3. turnover — Отток и текучесть: turnover_m, turnover_y, regret (pct, lower, KPI по HQ), exit_reasons (разрез)
4. hiring — Найм и вакансии: vac_open, vac_closed (int), time_to_fill (days, lower)
5. tgrowth — T-рост: tgrowth_pass, tgrowth_deny (int), tgrowth_conv (pct, higher)
6. monitor — Мониторинг работы: low_perf, underwork (pct, lower)
7. office — Посещаемость офисов: office_att (pct, higher)

Поля конфига метрики:
key, block, name, short, fmt(int|pct|days), better(lower|higher|flat), unit,
threshold, kpi, hint, drillUrl, aiTemplate

## ВТОРОЕ ПРАВИЛО — сравнимость метрик
С базой сравниваются только относительные метрики (проценты и сроки): turnover_m,
turnover_y, regret, time_to_fill, tgrowth_conv, low_perf, underwork, office_att.
Абсолютные счётные (COUNT_METRICS) не сравниваются никогда: численность, найм, отток
в людях, переводы, вакансии, T-рост в штуках. 212 человек против 2 968 по компании —
это масштаб, а не оценка.
Реализация: D.comparable(key), compareState отдаёт neutral. В UI вместо базы — пометка
«не сравнивается»; линия базы на графике не рисуется; колонка «К базе» в таблице
появляется, только если основная метрика блока сравнима; AI-инсайты по разрыву с базой
и концентрации отклонения строятся только по сравнимым.

## Контракт state (не менять)
{ unit, paint, itSeg, staffType, period, tab, subTab, mainMetric,
  drillRoot, selNode, openMetric, aiOpen }
Поля level и viz из ранних итераций больше не используются: уровень −2 раскрывается
каретками в таблице, отдельного переключателя визуализации нет.

## Скелет детальной вкладки (одинаковый всюду)
Заголовок блока со ссылкой на детальный дашборд справа в той же строке -> AI-инсайт ->
KPI блока -> две колонки: слева сводная таблица (ИТОГО первой строкой, каретка
раскрывает уровень -2), справа визуализация с под-вкладками, фильтруемая кликом
по строке таблицы.

## Правила визуализации
1. Два бара рядом за один период не рисуем: динамика не читается и сравнивать тяжело.
   Вместо этого — дивергентный бар (вверх/вниз) для пар «пришли/ушли» или отдельные
   панели друг под другом с общей осью X.
2. Подпись значения над каждой точкой и каждым баром: борт бизнесовый, значение должно
   читаться без наведения.
3. Единая гамма потоков во всех блоках: прибыло — зелёный --green, убыло — красный --red.
   Приглушённых вариантов той же семантики быть не должно.
4. Заголовок графика слева, легенда справа — они не накладываются друг на друга.
