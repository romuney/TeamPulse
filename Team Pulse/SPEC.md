# TeamPulse Hub — SPEC (контракт макета)

Актуально на 02.08.2026. Журнал изменений — в `PROGRESS.md`, правила работы
и обоснования решений — в `AGENTS.md`.

## Цель
Один верхнеуровневый борт вместо нескольких TeamPulse (HQ-версия и версия по всей
управленческой структуре). Разделение обеспечивается не отдельными отчётами,
а 4 управляющими фильтрами и персональными ссылками.

## Архитектура
**Библиотек нет вообще.** Конечный инструмент заказчика их не поддерживает, поэтому
вся графика рисуется на голом SVG в `draw.js`. Внешняя ссылка одна — шрифт Inter
из CDN в режиме разработки; в автономной сборке она вырезается, шрифт деградирует
до Helvetica/Arial.

Разбивка по слоям, потом по экранам. Порядок загрузки жёсткий, каждый следующий
файл читает неймспейс предыдущего:

`data.js` → `draw.js` → `ui.js` → `mascot.js` → `insights.js` →
`screens/_block.js` → `screens/<блоки>.js` → `screens/onepager.js` → `app.js`

| Файл | Неймспейс | Ответственность |
|---|---|---|
| `data.js` | `TPDATA` | Оргдерево, метрики, генератор моков, агрегация, текучесть, формат, светофор |
| `draw.js` | `TPDRAW` | SVG: line, bars, diverge, panels, waterfall, funnel, calendar, 2 спарклайна |
| `ui.js` | `TPUI` | KPI-карточка, чипы, ячейка сравнения, плашка инсайта, `barTable`, тултип |
| `mascot.js` | `TPMASCOT` | Пульс: картинки WebP в base64, эмоция вкладки, словарь метрик |
| `insights.js` | `TPINSIGHTS` | Отбор фактов по порогам `INS_GAP` / `INS_TREND` / `INS_CONC` |
| `screens/_block.js` | `TPSCREENS` | Каркас детальной вкладки, реестр экранов, общие помощники |
| `screens/<блок>.js` | — | Только специфика блока: под-вкладки, заголовки, правая панель |
| `app.js` | — | State, URL, шапка, навигация, модалки, роутер, события |

**Файл экрана не пишет разметку сам** — ни строк SVG, ни `<table>`. Только сбор
данных и вызовы `TPDRAW` / `TPUI`. Новый визуальный элемент сначала появляется
в `draw.js` или `ui.js` и только потом используется экраном.

Сдача — одним файлом: `node build.js` собирает `index.standalone.html` со
встроенными стилями и скриптами, без единой внешней ссылки.

## 4 управляющих фильтра
| Фильтр | Значения | Популяция | База сравнения |
|---|---|---|---|
| unit — подразделение | узел оргдерева | да | нет |
| paint — покраска | HQ / Line / Support / all | да | да |
| itSeg — IT-разрез | IT / nonIT / all | да | да |
| staffType — занятость | штат / не штат / all | да | да |

## ПЕРВОЕ ПРАВИЛО — база сравнения
```
reportLeaves(st)    = листья под st.drillRoot||st.unit, прошедшие paint+itSeg+staffType
benchmarkLeaves(st) = ВСЕ листья компании, прошедшие paint+itSeg+staffType
```
База выводится из фильтров, а не из подразделения. Подпись собирается автоматически
(`benchmarkLabel`): «вся компания» / «всё HQ» / «всё HQ IT» / «всё HQ IT штат».
Drill по кнопке `↓` меняет `drillRoot`, но базу не трогает.

Исключение: `regret` сравнивается с KPI `{green:4, red:7}`, но только при `paint==='HQ'`
(`kpiFor`); иначе — со средней по базе.

Светофор `compareState`: мёртвая зона ±5%, `better:'flat'` всегда `neutral`.

## ВТОРОЕ ПРАВИЛО — сравнимость метрик
`D.comparable(key)` — с базой сравниваются только относительные метрики, 8 из 19:
`turnover_m`, `turnover_y`, `regret`, `time_to_fill`, `tgrowth_conv`, `low_perf`,
`underwork`, `office_att`. Счётные из `COUNT_METRICS` — никогда: 212 человек против
2 968 по компании это масштаб, а не оценка.

В UI вместо базы — пометка «не сравнивается»; линия базы на графике не рисуется;
колонка «К базе» появляется, только если сравнима основная метрика блока; инсайты
про разрыв с базой и концентрацию считаются только по сравнимым.

## ТРЕТЬЕ ПРАВИЛО — состав метрик выбирает пользователь
В state лежат **скрытые** метрики (`hiddenMetrics`), а не показанные: пустой список
означает «показать всё», и новая метрика в `METRICS` появляется у всех сама. Набор
едет в ссылке параметром `hide=` и нормализуется `sanitizeHidden`.

`LOCKED_METRICS` = `hc_active` + `hc_total` — выключить нельзя. Четыре пресета
(`METRIC_PRESETS`): Всё · Текучесть · Найм · Минимум.

Скрытие доходит до строк OnePager, столбцов сводной таблицы, KPI-карточек, инсайтов
и пунктов навигации. **До графиков в правой панели не доходит** — они рисуют смысл
блока, а не список метрик.

## Блоки и метрики
19 метрик в 7 блоках:

1. `structure` — Структура численности: `hc_active`, `hc_total`, `hc_avg` (int, flat)
2. `movement` — Движение: `hire`, `attrition`, `transfer_in`, `transfer_out` (int)
3. `turnover` — Отток и текучесть: `turnover_m`, `turnover_y` (pct, lower),
   `regret` (pct, lower, KPI по HQ), `exit_reasons` (разрез)
4. `hiring` — Найм и вакансии: `vac_open`, `vac_closed` (int), `time_to_fill` (days, lower)
5. `tgrowth` — T-рост: `tgrowth_pass`, `tgrowth_deny` (int), `tgrowth_conv` (pct, higher)
6. `monitor` — Мониторинг работы: `low_perf`, `underwork` (pct, lower)
7. `office` — Посещаемость офисов: `office_att` (pct, higher)

Поля конфига метрики: `key`, `block`, `name`, `short`, `fmt` (int|pct|days),
`better` (lower|higher|flat), `unit`, `anchor`, `hint`, плюс необязательные
`kpi`, `derived` (числитель/знаменатель), `ytd` (накопительная), `cmp`
(перекрывает правило сравнимости). `drillUrl` — поле **блока**, не метрики.

Текучесть: `turnover_m` производная (`attrition / hc_avg × 100`), `turnover_y`
накопительная с января (обнуляется каждый январь). Для этого генератор считает
18 месяцев — 6 до окна.

## Контракт state
```
{ unit, paint, itSeg, staffType, period, tab, subTab, mainMetric,
  drillRoot, selNode, aiOpen, hiddenMetrics }
```
`mainMetric` в `DEFAULT_STATE` не объявлен — выставляется в рантайме, UI для смены
нет: `blockMain()` отдаёт первую сравнимую метрику среди выбранных в блоке.
`period` хранит `PERIOD_LABEL` и сейчас не читается — задел под выбор периода.

Поля `level`, `viz` и `openMetric` удалены 02.08.2026: механизмов, которым они
принадлежали, больше нет. Уровень −2 раскрывается каретками в таблице,
переключателя визуализации нет, раскрытые строки OnePager живут в `openRows`
(Set в `app.js`).

## Скелет детальной вкладки (одинаковый всюду)
Заголовок блока со ссылкой на детальный дашборд справа → AI-инсайт → тулбар
(только при временном корне) → KPI блока → `.split`: слева сводная таблица
(ИТОГО первой строкой, sticky-шапка, каретка раскрывает уровень −2), справа
содержимое блока с под-вкладками. Клик по строке таблицы фильтрует правую панель.

Высота `.split` — экран под шапкой (`calc(100vh - var(--head-h) - 28px)`, минимум
520px, только от ширины 901px). От неё зависит и число видимых строк таблицы,
и возможность прокруткой убрать всё выше рабочей зоны.

Под-вкладки объявляются в файле экрана (`subTabs`); `smoke.js` берёт список оттуда
же, поэтому тест не может отстать от кода. Неизвестная под-вкладка откатывается
на `defaultSub`.

## Правила визуализации
0. **Ось значений ВСЕГДА от нуля.** `niceMax()` считает только верх, урезанную ось
   в `draw.js` нельзя получить даже случайно.
1. **Ось Y не рисуем вообще**, если значения подписаны у точек и баров. Остаётся
   только базовая линия нуля.
2. **Два бара рядом за один период не рисуем.** Пары «пришли / ушли» — `diverge`
   (одна шкала на оба плеча), разные метрики — `panels` (у каждой своя шкала от нуля).
3. **Подпись значения над каждой точкой и баром**, с halo: белая обводка
   `stroke-width="3.2"`, потом заливка. `paint-order` не используем — в Safari даёт
   двойной текст.
4. **Разбивка по атрибутам — таблица, а не бар-чарт** (`TPUI.barTable`): полоса
   внутри ячейки, растёт от левого края.
5. **Граница календарного года** — вертикальный пунктир ровно на высоту области
   построения.
6. **Единая гамма потоков:** прибыло — `C_IN`, убыло — `C_OUT`. Одинаково везде.
7. **Заголовок графика слева, легенда справа** — не накладываются.
8. **Подсказка собирается конструктором `TPDRAW.tipHtml`**, а не склейкой тегов.
   Он экранирует входы сам — `esc()` снаружи вызывать нельзя.
9. **Единая геометрия:** все виды берут `AXIS_H`, `HEAD_GAP`, `PAD_X`, `LBL_ROOM`,
   `VAL_SZ/VAL_W/VAL_DY/VAL_ASC`, `DRAW_MS`, `STACK_GAP` из `draw.js`.
12. **Расстояние между графиками в стопке — одно.** Его задают два механизма:
    `STACK_GAP` внутри `chart('panels')` и CSS-зазор `--chart-gap` между двумя
    отдельными `chart()`. Величины обязаны совпадать, иначе одинаковый по смыслу
    зазор выглядит разным на соседних вкладках. Сверяет `smoke.js`.
13. **Календарь не растягивается.** У клетки есть потолок `CELL_MAX`, сетка
    центрируется, шкала интенсивности стоит **над** сеткой: снизу она упиралась
    в таблицу дней недели и читалась как подпись к ней.
14. **Календарь показывает окно последних `CAL_DAYS` = 30 дней по `CAL_TODAY`, а не календарный
    месяц.** Окно пересекает границу месяцев — `D.attLast()` отдаёт массив блоков,
    `drawCalendar` рисует их сетками рядом с общей шкалой интенсивности. Тесная
    клетка теряет подписи, но не заливку: значение остаётся в подсказке.
10. **Серии и легенда:** состав серий в `SERIES`, каждая марка несёт `data-s`.
    Легенда подсвечивает и выключает серии; последнюю выключить нельзя,
    `waterfall` заблокирован через `LOCKED`.
11. **Цвета живут только в `draw.js` и `:root`.** В `screens/*.js` литеральных
    `#rrggbb` быть не должно — на это есть проверка в `smoke.js`.

## Дизайн-система
`--bg #f4f5f7`, `--card #fff`, `--line #e7e9ee`, `--ink #1f1f1f`, `--muted #8a909c`,
`--green #12b048` / `--green-bg #bff2cd`, `--red #f51f1f` / `--red-bg #ffcccc`,
`--blue #3b6fe0` / `--blue-bg #eef3fe`, акцент `--act #2b6cff`, AI `--ai #6f4ed8`.

Шкалы: расстояния `--s1…--s10`, семь ролей кеглей `--fs-micro…--fs-hero`,
радиусы `--r1…--r5` плюс `--r-pill`. Новые значения берём из шкал, а не на глаз.

**В светофоре два цвета: зелёный и красный, жёлтого нет.** Состояние `warn`
в логике осталось (от него зависят подписи «на уровне» и «зона риска»), но красится
серым. Жёлтый остался только там, где он не про отклонение метрики: severity
плашек инсайтов и настроение Пульса.

**Изменение показывается знаком, а не стрелкой** (`TPUI.deltaChip`): `+7`, `−4`,
при нуле просто `0`. Знак отвечает за направление, класс `up`/`down`/`neu` — за оценку.

## Форматирование
Тонкий пробел в тысячах, запятая в дробной части, компакт на барах, `п.п.` у дельт
процентов. Всё через `fmtVal` / `fmtDelta` / `fmtInt` / `fmtCompact`.
